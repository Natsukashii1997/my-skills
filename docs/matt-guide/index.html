Matt Pocock 技能库 · 给不写代码的人

像装修一样，让 Claude 先问清再动手

Matt 技能库是一套给 Claude 用的做事规程：写代码之前先把你的想法问透、写成文档、拆成小任务，再一小步一小步地做、审、复盘。你不用懂技术，只在几个关键处拍板。

靠谱的装修队不会一进门就砸墙。先上门问清你要什么，出图纸，拆成工单，按单施工，最后验收、复盘下次怎么更顺。Claude 也一样：想法越模糊、活越大，越要按这个顺序来。

这套技能解决的问题：AI 写得快，但常常没听懂就开工，改到一半才发现方向错了。

02
四档怎么判断

先看活多大，再决定走几站

判档的是 Claude，你只需要认一句。下面是它的判断依据，方便你看懂它为什么这么建议。

0顺手改

信号改一两处，改完看一眼就知道对不对，功能怎么用不变。

不走技能，直接改
例子（示意）驿窗设置页「已配置」写成了「以配置」，改掉。

Claude 怎么做不问，直接改，改完告诉你改了哪一处。

1轻量

信号要改功能的行为，但范围清楚，一次对话做得完。

grilling→tdd→code-review
例子（示意）牛马之家的折线图，鼠标停在点上时显示当天的具体数值。

Claude 怎么做说一句这是 1 档，按 追问 → 测试先行 → 审查 来就开始，不等你回。追问只问一轮，最多 3 题。

2标准

信号一个新功能，牵涉好几个界面或文件，需求得先定下来，可能要分几次做。

grill-with-docs→prototype→to-spec→to-tickets→implement→code-review→pr→retro
例子（示意）给驿窗加一个「会话接力」面板：看到哪些会话在等你，一键接着做。

Claude 先问你我判断这是 2 档（新功能，牵涉侧栏和会话列表），建议走 追问 → 需求文档 → 任务卡 → 实现 → 审查，开始吗？你回「好」才开始。

3大雾

信号连终点长什么样都说不清，先要做很多决定，一次对话装不下。新项目但一句话说得清的小工具，不算这档。

wayfinder→并入 2 档，从to-spec开始
例子（示意）从零做一个新应用，比如「个人 AI 工作台」：用户是谁、放哪些模块都还没想好。

Claude 先问你我判断这是 3 档（新应用，方向还没定），建议先用 wayfinder 画地图，路清楚了再写需求文档，开始吗？

拿不准时

Claude 按高一档问你，并说明「也可以按 X 档轻量做」。你回按 1 档来就降档。

中途变了

升档要问：1 档做着发现要改多处、要取舍，Claude 停下来问要不要升 2 档。比想的小，它说一句就直接降档。

只想聊不想改

回先只聊，不改代码。追问照常进行，聊完再决定做不做。

03
最常卡住的地方

grill-me 问完了，下一步做什么

grill-me 只负责「想清楚」，不会自己往下走。问完以后看你要的是什么，选一条路接上。

先分清grill-me 和 grill-with-docs 问的一样，差在留不留记录

grill-me什么都不存

适合不在项目文件夹里想事情：一个计划、一篇文章、一个要不要做的决定。聊完就结束，没有文件留下。

04

平时不用记，Claude 会判档、带路

你直接说想做什么不用说技能名。比如「牛马之家的折线图想加悬停数值」。

05
半路入口

不是每次都从头开始

先找你现在的情况，从对应那站上车。半路上车不判档，也不问「开始吗」，Claude 说一句「从 X 这站接上」就开始；要对外发布的那一步照样先问你。

06
技能卡片

每个技能做什么、怎么叫

常用的在前面，冷门的收在最后。标着「Claude 会自动用」的，你说出意思它自己会调；标着「只能手动叫」的，要么你点名，要么由 matt-flow 带路时替你调。

主线技能

按流程顺序排

半路工具与设施

出状况、缺资料、第一次铺设施时用
冷门技能写文章、特定技术栈、作者自用，平时用不到

没找到匹配的技能，换个词试试，比如「测试」「文档」「bug」。

07
术语表

听到这些词，知道在说什么

每个词三件事：一句白话、一个比喻、在这套流程里什么时候会碰到。可以搜，也可以按类别看。

没找到这个词。可以直接问 Claude：「XX 是什么意思，用大白话讲」。

下次有想法，直接跟 Claude 说。它判好档、问你一句，你回「好」就行；听不懂随时说「用大白话重讲」。
