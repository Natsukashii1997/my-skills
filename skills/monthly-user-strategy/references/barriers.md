# 购买障碍（阶段 04 用）

摘自 niuma-home `docs/策略规则/02-障碍体系v2.md` **barrier-v2.1**（第 1–2.3 节）。促销目标与打法卡的映射（第 3–5 节）在批 2 用，这里不摘。规则以原文为准。

障碍回答「学生为什么可能不采取购买行动」，是购买行为判断；学业痛点是完成学业任务的阻力。两者分开写，不混。

## 1. 障碍清单

| 编码 | 障碍 | 判定要点 | 适用人群 |
|---|---|---|---|
| `BR-M1` | 没意识到需要 | 学生没把当前学业任务和外部辅导联系起来 | 新签 |
| `BR-M2` | 觉得还来得及 | 节点在行动窗口之外或刚进入，倾向推迟决定 | 新签 / 续费 |
| `BR-M3` | 不信任辅导效果 | 一般性怀疑效果或老师水平，不以本人既往服务体验为依据 | 新签 / 续费 |
| `BR-M4` | 有替代方案 | 用学校资源、同学、AI 工具替代 | 新签 / 续费 |
| `BR-M5` | 学术诚信顾虑 | 担心外部帮助被认定为学术不端 | 新签 / 续费 |
| `BR-C1` | 嫌贵 | 价格超预期，或在等折扣节点 | 新签 / 续费 |
| `BR-C2` | 怕选错 | 不知道选哪个方案、班型或老师 | 新签 / 续费 |
| `BR-C3` | 没时间 | 多任务叠加，担心辅导占用复习时间 | 新签 / 续费 |
| `BR-C4` | 需要家长同意 | 付款或决策需要家长参与 | 新签 / 续费 |
| `BR-O1` | 没被触达 | 不知道我们能帮，或需要时没看到我们 | 新签 |
| `BR-F1` | 方案不匹配任务 | 现有产品覆盖不了当下的具体任务（科目、时段、形式、交付周期） | 新签 / 续费 |
| `BR-R1` | 上阶段体验或效果一般 | 已购学员基于既往真实服务体验不满意 | 续费 |
| `BR-R2` | 下阶段没有明确任务 | 已购学员看不到下一阶段还需要什么帮助 | 续费 |
| `BR-R3` | 导师或课程衔接不上 | 原导师不可约、课程内容不接续 | 续费 |
| `BR-R4` | 已有余量 | 课时、权益没用完，暂不需要追加 | 续费 |
| `BR-R5` | 续费价格无优势 | 老学员价不比新客价有优势 | 续费 |

- 只适用续费的（R1–R5）不能出现在 `targetRelation=新签`；只适用新签的（M1、O1）不能出现在续费；`targetRelation=通用` 只能用两类人群都适用的障碍（I-11）。
- 正文、论证里写障碍的**名称**，不写编码（I-15）。编码只放在 `barrierCode` 字段。

## 2. 主障碍（02 §2.1）

- 同一情境、同一 `targetRelation` 下可以多个障碍并存，但**恰好一个** `barrierRole=primary`，其余 `secondary`。
- 主障碍是对这群学生当下不购买影响最大、方案要优先解决的那个；选定理由写进该 Claim 的 `rule`。
- 只有一个障碍时它就是主障碍。证据不足以分主次时，按证据较强的一条定，limitations 写「主次依据不足」。
- 没有障碍 Claim 时不强造主障碍。全部障碍都是 `unknown` 时，primary 只表示待验证的研究重点。

## 3. 相近障碍判定（02 §2.2）

先查清「需要区分的事实」；事实不清就写 `unknown`，不凭印象二选一。

| 相近障碍 | 需要区分的事实 |
|---|---|
| 没意识到需要 ↔ 下阶段没有明确任务 | 新签还是已购。已购学员看不到下一阶段要做什么 → R2；新签没把任务和辅导联系起来 → M1 |
| 觉得还来得及 ↔ 嫌贵 | 推迟是因为时间判断（节点还远）还是价格（等折扣、嫌贵）；有等折扣行为归 C1 |
| 不信任辅导效果 ↔ 上阶段体验一般 | 不信任是否来自本人既往真实服务体验：有 → R1；没有 → M3 |
| 没时间 ↔ 方案不匹配任务 | 没有可用时间（任务叠加）→ C3；有时间但时段、形式、周期对不上 → F1 |
| 方案不匹配任务 ↔ 导师或课程衔接不上 | 产品覆盖不了新任务 → F1；产品有但原导师不可约或课程不接续 → R3（只用于续费） |
| 嫌贵 ↔ 续费价格无优势 | 绝对价格超预期 → C1；老学员价与新客价比较后觉得没优势 → R5（只用于续费） |

## 4. 证据要求（02 §2.3，服务端会拦截）

1. **客观事实只作情境依据**：节点在日历上的位置、学校政策、学期安排，能说明学生处在什么情境，不能单独证明学生已经有某种购买顾虑。
2. **`BR-M2`、`BR-M5` 仅凭客观事实时写 `unknown`**：gap 写缺少的用户行为证据，route 指向可补的已登记来源（`SRC-bizcard` 可用 → `available`；`SRC-voice`、`SRC-crm` 未接入 → `unavailable`）。
3. **其他障碍只有常识依据时最高 `inferred + weak`**，limitations 写「缺少用户决策行为证据」。
4. 证据要**直接说到这个障碍的判定要点**（第 1 节）：例如「觉得还来得及」要有推迟、观望的行为，「嫌贵」要有比价、问折扣的行为；只是间接相关（学生在咨询复习规划，不等于学生在推迟决定）的，按第 2、3 条处理，并在 limitations 写明差在哪里。`evidenceRefs` 只放真正支撑的证据，不为凑强度多挂。
5. 能提到 `inferred + partial` 或 `known` 的只有用户决策行为证据：背景卡里的事实记录或业务观察（咨询、成交、流失、续费情况）、Voice 原话。管理判断（weak）只能当待检验的假设，不能单独认定障碍。

## 5. 新签、续费独立研判

- 续费不复制新签的障碍；不默认老学员没有信任障碍。
- 背景卡没有「存量用户情况」时：续费的障碍和购买准备度一律 `unknown`，gap「缺少存量学员下一阶段任务与续报信息」，route `{ status: available, source: SRC-bizcard }`（07 §3）。这时续费障碍仍要指定一个 primary（作为待验证的研究重点）。
