# 报告结构与逐章规格（第 4 轮写作用）

摘自 niuma-home `docs/策略规则/10-报告内容规格.md` **report-v2.1**（2026-11-09 冻结，同日修订为 v2.1）第 1–4、6、8.4 节。规则以原文为准；原文版本号变了，先核对本文再用。

## 1. 报告是什么

《YYYY-MM 月度用户策略报告》是以真实学业时间线和业务数据为基础，研究主要留学目的地在目标月份的用户状态、关键任务、深层需求和购买决策，识别最有商业价值的机会，并形成地区优先级、产品策略、价值主张、营销促销与执行方针的**完整经营决策文档**。既是这个月的说明文档，也是行动方针。

四个价值标准：**可读性**（读第一章 1–2 分钟就有月度整体认知）、**洞察力**（解释学生在争取什么、害怕什么、怎么选、什么决定他买不买）、**推导力**（地区、用户、SKU、优惠的选择都能顺因果链说出来）、**指导性**（各部门知道本月先做什么，有取舍、有下一步）。**详细是对重要问题充分展开，琐碎是对低价值信息同等罗列**：可以详细，不能琐碎。

信息分三层：核心策略判断写正文与小结；关键论证事实写成正文里的必要表格和段落；完整研究依据（全部学校日期、Claim、来源、规则版本、自检）只放附录。正文**不从 Claim 拼接**，不出现 Claim / Evidence / 情境编号、状态码、障碍编码（`report-check.mjs` 会拦）。

## 2. 八章与比重

正文参考 8,000–12,000 字（试写校准），附录不计入。

| 章（二级标题一字不差） | 回答 | 比重 |
|---|---|---|
| `## 第一章 月度策略总览` | 这个月到底要怎么打？ | 8% |
| `## 第二章 月度时间线与需求节奏` | 本月不同时间会发生什么？ | 12% |
| `## 第三章 六地区用户需求深度分析` | 为什么这些用户在这个月值得关注？ | 32% |
| `## 第四章 地区优先级与机会判断` | 资源应该优先投入哪里？ | 10% |
| `## 第五章 SKU 与产品价值策略` | 卖什么？用户为什么买？ | 14% |
| `## 第六章 营销主张与促销策略` | 怎么吸引、说服和促成购买？ | 12% |
| `## 第七章 月度执行方针` | 各部门接下来具体做什么？ | 9% |
| `## 第八章 关键假设与验证事项` | 哪些判断还需要验证？ | 3% |
| `## 附录 研究依据` | 判断凭什么？ | 不计入 |

比重分三块：第 1–4 章约 62%（洞察与需求判断，报告主体）、第 5–6 章约 26%、第 7–8 章约 12%；阅读层次另按 1–3 看清局势 / 4–6 形成选择 / 7–8 指导行动。

阅读顺序 = 决策顺序；**第一章最后写**。同类信息只完整论证一次：第二章说时间线，第三章解释需求，第四章比较机会，第五章判断产品，第六章设计营销促销，后文只引用前文结论并推进新判断。**共有机制只论证一次**：同一处境出现在多个地区时，只在最主要的地区完整论证，其他地区写「同 X 地区，差异在于……」。

## 3. 逐章写什么

### 第一章 · 月度策略总览（8%）

所有研究完成后浓缩出的月度经营判断。三个三级标题：

- `### 1.1 月度整体定性`：**一段 150–250 字**的连贯文字（脚本按不计空白的字数查），讲清四件事：本月在全年学业周期中的位置；各主要目的地的总体学业节奏（有错峰讲错峰）；本月需求的主要特征及变化；应采取的总体经营方向。写阶段、变化和经营含义，不只写事实。「本月多地进入考试窗口，需求活跃度高」不合格。
- `### 1.2 本月核心策略判断`：3–5 条，一屏内。用表格：需求主线｜地区选择（主攻、提前布局）｜核心用户（学业阶段、新老学员）｜产品方向（服务价值，不罗列 SKU）｜**关键取舍**（本月哪些方向暂不重点投入、为什么；必填）。
- `### 1.3 本月经营目标`：业务目标已知写目标；不知道就定**策略性质**：新增获客驱动 / 老学员续费驱动 / 紧急需求转化驱动 / 多地区不同阶段的组合策略。不编收入目标。

### 第二章 · 月度时间线与需求节奏（12%）

1. **全年学业周期定位**：本月对各地区分别是学期初、学期中、期末、出分及补考，还是新学期前衔接；错峰的写明不在同一周期；不归成统一「期末季」。
2. **跨地区关键时间线**：一张表：时间段｜主要学业事件｜用户需求变化｜经营意义。**按真实转折点分段**，上中下旬只是阅读辅助（旬按 1–10 / 11–20 / 21 起）；每段都回答需求和商业机会怎样变化。范围：目标月整月 + 下月前 14 天。
3. **月度需求波次**：判断各地区处在提前规划期 / 集中准备期 / 考前高紧迫期 / 考后衔接期中的哪一段；不要求四段都出现。生命周期窗口只是研究线索，不是行动概率；阶段转换没有咨询、购买证据时标〔待验证假设〕。

读完本章应能说清：需求为什么不均匀分布，哪些节点推动需求变化，为什么各地区要不同节奏。

### 第三章 · 六地区用户需求深度分析（32%，研究主体）

以地区为阅读单元，以院校时间线为事实依据，以用户场景为研究核心，以商业机会判断为出口。**每个地区一个三级标题，标题里要有地区名**（英国、美国、香港、澳洲、加拿大、其他），按本月重要程度排序。

每个地区的分析逻辑七层（用小标题和连贯段落写，不是七张卡）：01 地区总体判断（一句话）→ 02 关键院校节点与地区时间规律 → 03 用户状态与关键任务 → 04 核心需求与深层痛点 → 05 购买决策与行为机制 → 06 需求强度与机会成熟度（四维）→ 07 地区策略结论（本月核心用户是谁？核心需求是什么？优先承接哪种机会？）。04–06 层怎么挖见 `insight.md`。

写法用「结论 → 论证 → 行动含义」三段式：先说该地区处于什么关键阶段、最重要的需求；再用学校节点、真实反馈、用户任务论证，说清为什么形成这种需求、有哪些例外；最后写优先关注哪些用户、满足什么需求、什么服务价值方向。

院校时间线归纳：具体事实 → 院校群体聚合 → 时间分布 → 阶段差异 → 地区规律。不罗列学校，也不过度概括。用「多数 / 例外」，例外写校名；逐校日期放附录。

篇幅差异化：2–3 个核心地区完整七层；其他有明确机会的地区中等篇幅、突出差异；数据不足或暂不投入的地区简明说明（含覆盖情况），不强编故事。核心地区由当月研究决定，不固定为英美。某地区有两个显著不同群体可以写两条路径，不列十几个情境。

### 第四章 · 地区优先级与机会判断（10%）

地区优先级是第三章的结论，不由预设权重和覆盖率直接决定。见 `design.md` 第 1 节。输出：

- `### 4.1 地区决策表`：表头 `| 地区 | 本月主要机会 | 关键窗口 | 推荐优先级 | 机会阶段 | 经营动作 |`，**六个地区各一行**（第一格写英国、美国、香港、澳洲、加拿大、其他），「推荐优先级」只写主攻 / 培育 / 观察（后面可跟可信程度标注）。脚本逐行查。
- `### 4.2 本月核心机会主题`：建议 2–4 个（证据不足可以少于 2 个，写明原因）；跨哪些地区、哪类用户、窗口、为什么值得做。地区是资源管理维度，机会主题是营销和产品组织维度，第五、六章按机会主题组织。

### 第五章 · SKU 与产品价值策略（14%）

见 `design.md` 第 2 节。输出：卖点对照表（用户关切｜产品需要的实际能力｜可提炼的卖点）；产品策略表（策略机会｜对应地区与用户｜主推 SKU｜选择理由｜核心卖点｜必要交付条件）；**七个 SKU 都表态**（灵活学Lite、安心学Max、学考无忧Pass、补考护航Pass、选课指导、论文稳Pass、先修班课）：主推 / 辅推 / 条件性承接 / 本月不推，不推写一句原因。

七个 SKU 的角色用一张固定表写在 5.3 末尾（脚本逐行查：七行都在、角色只能是这四种、理由不能空；角色是「主推」的 SKU 会和 `design.md` 的决策追溯表核对）：

```markdown
| SKU | 本月角色 | 理由 |
|---|---|---|
| 安心学Max | 主推 | 一句话：对应哪个机会主题、解决哪个关切 |
```

### 第六章 · 营销主张与促销策略（12%）

见 `design.md` 第 3–4 节。每个促销方案一个四级标题 `#### 方案 N：<方案名>`，下面逐项写六行，每行都要有内容（脚本逐项查）：

```markdown
#### 方案 1：<方案名>
- 促销目标：……
- 适用人群：……
- 核心机制：……
- 选择依据：……（为什么这个机制解决已识别的障碍、为什么不用其他候选；对应哪张打法卡写在 design.md，正文不写卡号）
- 商业约束：……
- 验证指标：……
- 前提条件：……（条件性策略版必写）
```

方案名要和 `design.md` 决策追溯表的「促销方案」一格对得上。研究假设版不出正式方案：方案名后标「（候选待确认）」，或不写方案。没有方案时，在 6.2 正文（不是标题）写明「本月不额外促销」及理由，这是合法结论。

### 第七章 · 月度执行方针（9%）

见 `design.md` 第 5 节。时间 × 部门；可执行事项表；不再解释学生为什么需要辅导。

### 第八章 · 关键假设与验证事项（3%）

一张表，**3–5 行**：关键待验证问题｜为什么重要（影响哪个决策）｜验证方式。只列会实质影响商业决策的；其余未知放附录。

### 附录 · 研究依据

院校时间表（逐校节点、核验状态、时间线疑点）；关键判断的证据链（这里可以写 Evidence ID）；结构化研判摘要；输入清单（底稿指纹、产品与活动来源、规则版本）；第 5 轮审核记录摘要；被否方案。

## 4. 报告等级（规格 8.4）

报告头写「报告等级：研究假设版 / 条件性策略版 / 可执行策略版」之一，按输入判定，**只能低报、不能高报**（`report-check.mjs --digest --products` 会核对）：

| 等级 | 输入条件 | 写法 |
|---|---|---|
| 研究假设版 | `digest.md` 业务背景卡「用户观察」「存量用户情况」都空；或没有能力卡；或能力卡 4 个及以上 SKU 一项都没填 | 第三章 04–06 层以〔待验证假设〕为主；卖点写「需确认产品能力：……」；主推按线索暂定或不设（`design.md` 第 2 节）；促销只出「候选待确认」或本月不额外促销；第一章 1.1 说明等级和缺什么 |
| 条件性策略版 | 介于两者之间 | 主推、促销写前提条件（方案加「- 前提条件：」）；第八章写补齐哪项输入后可以升级 |
| 可执行策略版 | 两栏都填了；每个主推 SKU 能力卡五项都填了；`products.md` 活动基线就是目标月 | 正常写 |

低报可以，第一章写理由。等级不替代内容验收：研究假设版也要深入解释、敢下判断。

## 5. 写法

1. 结论先行；地区和重要段落用「结论 → 论证 → 行动含义」。
2. 写段落和必要表格，不写卡片；表格单元格可以短，正文不受「单条 40 字」限制。
3. 具体：有日期写日期，有学校写学校；地区归纳用「多数 / 例外」并写例外校名；旬按日期算。
4. **敢下判断**：证据不足时给出当前最有解释力的判断，在关键判断旁标可信程度 `〔已验证〕` `〔有依据的判断〕` `〔待验证假设〕`（三档定义见 `insight.md` 第 7 节）；边界集中写在节末、第八章或附录，**不在每句话里重复「可能」「尚待验证」**（脚本按每千字次数提示）。
5. 同类信息只完整论证一次。
6. 禁用空话：赋能、抓手、闭环、全方位、打造、助力、持续发力。
7. 不编：Evidence、学校、日期、经营数据、收入目标、价格金额、产品能力、负责人。缺了写缺什么、影响哪条判断。
8. 主张和结论对它覆盖的每个子群体都要成立：一个机会主题里处境不同的子群体（时间、地区、新老用户）分开说，不把最紧迫那群人的说法推给整个主题（`design.md` 第 3 节）。
9. 篇幅跟比重走：`report-check.mjs` 提示某章偏离规格比重 ±30% 以上时，压缩或调整；确实需要（例如本月促销约束多），在交付答复里写一句理由。
