# 商业策略设计：机会、产品、营销促销、执行（第 3 轮用）

摘自 niuma-home `docs/策略规则/10-报告内容规格.md` **report-v2.1** 第 4 节第四至八章、第 8.2 节，以及 `02-障碍体系v2.md` **barrier-v2.1** 第 4 节（促销目标与候选打法卡）、`06-SCOUT-8运行规范.md` **scout-v1.1** 阶段 06（六个匹配条件、时间适用性、分级）。规则以原文为准。

第 3 轮只用第 2 轮的 `synthesis.md` 和产品与活动输入（`products.md`），产出 `design.md`；不回头重做研究。**需求驱动产品，不是产品驱动需求**：不先定卖某个 SKU 再编理由。

## 1. 地区优先级与机会主题（报告第四章）

地区优先级是第三章需求分析的结论。六维定性判断（没有可靠商业数据时不用任意权重造精确分数；覆盖率默认矩阵只作初始提示）：

| 维度 | 要回答 |
|---|---|
| 时间机会 | 本月是否有明确且正在形成的需求窗口 |
| 需求规模与质量 | 目标用户规模及需求证据是否充分 |
| 购买条件 | 需求是否已接近咨询或购买决策 |
| 产品适配 | 是否有能有效解决问题的服务 |
| 商业价值 | 预计收益、获客成本、服务成本是否合理 |
| 执行可行性 | 师资、销售、营销能否及时承接 |

- **和研究层优先级的关系**：第 1 轮 `draft.json` 里的 `priority`（主战场 / 次要 / 平稳）是研究阶段的判断（默认矩阵 + 样本与日期质量修正），给 Schema 用；这里的主攻 / 培育 / 观察是第 3 轮的经营决定，以第 2 轮洞察为准。默认对应：主战场 ↔ 主攻、次要 ↔ 培育、平稳 ↔ 观察；可以不同（例如校历齐全、覆盖率高，但考前需求在月初已过），不同时在地区决策表的经营动作或表后写一句理由，不回头改研究层。
- **投入优先级**写「主攻 / 培育 / 观察」；**机会发展阶段**另写（提前规划 / 集中准备 / 高紧迫 / 考后衔接）。「低即时成交机会」不等于「低地区重要性」：业务重要的地区在提前规划期，应经营潜在用户、积累线索，在更合适的窗口强化转化。
- 输出地区决策表（地区｜本月主要机会｜关键窗口｜推荐优先级｜机会阶段｜经营动作）和**核心机会主题，建议 2–4 个**（证据不足可以少于 2 个，写明原因；不为凑数拆分或合并。如「Final 考前冲刺」「假期备考」「考后衔接与续费」：跨哪些地区、哪类用户、窗口、为什么值得做）。机会主题是第五、六章的组织单位。

## 2. SKU 与产品价值（报告第五章）

链条：目标用户的核心任务 → 深层痛点、决策标准与理想结果 → 服务能力与需求匹配 → 确定主推 SKU 或组合 → 从匹配理由提炼价值主张。

卖点逐一回应用户关切：

| 用户关切（第 2 轮 L3、L4） | 产品需要的实际能力（产品能力卡） | 可提炼的卖点 |
|---|---|---|
| 怕找不到合适老师 | 课程匹配与师资资源 | 熟悉目标课程、快速对接合适师资 |
| 怕抓不住重点 | 课程诊断、考点梳理 | 针对重点难点制定复习方案 |
| 时间太少 | 灵活排课、高效课程规划 | 更好利用剩余复习时间 |
| 怕买了没效果 | 明确学习目标、过程反馈、可信案例 | 辅导过程和阶段性进展更透明 |
| 不知道买几节课 | 基于学情的课时建议 | 按剩余时间和任务配置课程 |

（上表是示例格式，每月按真实关切和能力卡填。）

**营销主张必须同时满足：用户确实在意 + 产品确实能提供。** 主张和机会主题的说法还要对主题里**每个子群体**都成立：同一主题下处境不同的子群体（例如补考 12 月批出分到补考只有几天，1 月批有三到六周），主张分开写，不能把最紧迫子群体的说法推给整个主题，否则对其他子群体就是不实的紧迫感。 产品能力卡没填的能力，卖点写「需确认产品能力：……」，不写承诺（不能因为学生在意速度就写「两小时配到老师」）；第八章把它列为验证事项。

产品策略表：策略机会｜对应地区与用户｜主推 SKU｜选择理由｜核心卖点｜必要交付条件。**七个 SKU 都表态**：主推 / 辅推 / 条件性承接 / 本月不推（附原因）。名称照用：灵活学Lite、安心学Max、学考无忧Pass、补考护航Pass、选课指导、论文稳Pass、先修班课。产品名称不能替代服务说明：不推断 Lite / Max 的服务差别，不把 Pass 写成包过、退款或结果保证，不编课时、师资、有效期。

**能力卡没填时怎么选主推（研究假设版、条件性策略版里没填的 SKU）**：只能用「机会主题需要的服务类型 + SKU 名称所指的用途 + 价格档案的档位」三条线索暂定，名称只作线索，不推断服务内容；角色表理由里写明「暂定：能力卡确认前」，第五章 5.1 写出用了哪几条线索、能力确认后按什么改。三条线索都对不上某个机会主题时，这个主题**可以不设主推**（5.3 产品策略表的主推 SKU 一格写「不设主推」及原因），不硬凑。第八章把「主推 SKU 的能力能否承接」列为验证事项。

## 3. 营销与促销（报告第六章）

**促销从用户购买决策中的阻力出发设计，不从月份出发。** 营销回答「为什么现在需要关注这项服务、为什么我们值得选」；促销回答「已认可服务价值的前提下，什么合理的商业机制能推动购买」。顺序：明确目标用户与需求 → 提炼核心价值主张 → 分析当前购买阻力 → 选择机制 → 验证毛利、交付及规则限制 → 确定推广与转化方案。

阻力 → 干预（思考工具，不是规则库）：

| 主要阻力 | 优先考虑的干预 | 促销是否必要 |
|---|---|---|
| 不确定老师是否合适 | 诊断、试听、师资信息、匹配说明 | 不一定需要降价 |
| 时间紧，怕赶不上 | 明确服务启动流程、可用排课能力 | 折扣可能不是主要因素 |
| 不清楚需要多少课时 | 分阶段购买、课时组合、规划建议 | 可考虑降低初始决策门槛 |
| 价格敏感且已验证 | 满足利润约束的优惠、组合权益 | 可以考虑价格机制 |
| 老学员缺少续费动力 | 下阶段学情规划、课程衔接、合理续费权益 | 先分析续费原因 |
| 替代方案很强 | 差异化服务、教学效果证据 | 不能单纯靠价格竞争 |

例：离考试只剩十几天、最关心能否找到合适老师，大额折扣解决不了师资匹配；准备期长、课程选择多的阶段，合理的组合或增值权益更符合决策方式。同样是考前辅导，Final 冲刺、期中、毕业季的机制可以不同，依据要写出来。

**每个促销方案六项**（报告里逐项写这六个词）：

| 项 | 要求 |
|---|---|
| 促销目标 | 提高首次转化、客单价、续费，还是提前锁定需求 |
| 适用人群 | 哪些地区、新老用户、需求阶段 |
| 核心机制 | 降价、权益、组合、抵扣、赠课或非价格方案 |
| 选择依据 | 为什么这个机制能解决已识别的障碍，为什么不用其他候选 |
| 商业约束 | 毛利、退款、师资成本、与现行活动冲突 |
| 验证指标 | 如何判断带来了增量，而不是原有购买的价格让渡 |

**「本月不额外促销，集中提升服务价值表达和转化效率」是合法结论**；不要求每个地区都有促销，不为填满报告生成优惠。不编具体金额（价格归价格模块），可以写机制和条件。

## 4. 候选机制池：促销目标与打法卡（02 §4、06 阶段 06）

七个促销目标：需求唤醒（不知道是否需要）、信任建立（担心质量与匹配）、降低行动门槛（对购买步骤或方案选择有顾虑）、时间促进（有需求没及时行动）、价值增强（认为价值不足）、续费承接（衔接下一阶段）、扩科发展（新学科需求）。

障碍 → 候选目标：没意识到需要 → 需求唤醒；觉得还来得及 → 时间促进、需求唤醒；不信任辅导效果 → 信任建立、降低行动门槛；有替代方案 → 价值增强、信任建立；学术诚信顾虑 → 信任建立（主要靠服务边界说明）；嫌贵 → 价值增强、降低行动门槛；怕选错 → 降低行动门槛、信任建立；没时间 → 降低行动门槛、价值增强；需要家长同意 → 信任建立；没被触达 → 需求唤醒（主要靠渠道触达，不靠让利）；方案不匹配任务 → 价值增强、扩科发展；上阶段体验一般 → 信任建立、续费承接；下阶段没有明确任务 → 续费承接、需求唤醒；导师或课程衔接不上 → 续费承接；已有余量 → 续费承接、扩科发展，或「暂不推动续费」；续费价格无优势 → 续费承接、价值增强。

目标 → 候选卡（`docs/打法库/P*.md`，`products.md` 列了索引）。卡片元信息用旧障碍编号，`products.md` 已在括号里标出对应的 v2 编码（规则 02 第 3 节：v2 障碍的候选卡 = 旧编号对得上、且阶段与人群相容的卡；BR-M5、BR-F1、BR-R3、BR-R4 没有自动候选卡）：

| 目标 | 候选卡 |

| 需求唤醒 | P0603 免费学业诊断 · P0602 免费试听 / 公开课 · P0601 低价引流课 · P1104 集卡 / 闯关 · P1005 渠道专属权益 · P1103 红包雨 |
| 信任建立 | P0602 免费试听 · P0701 7 天无理由退 · P0703 学习保障条款 · P0502 赠 1v1 答疑 · P0504 赠伴学督学 · P0802 预约排队 · P1101 签到打卡 |
| 降低行动门槛 | P0601 低价引流课 · P0603 免费学业诊断 · P0401 班型梯度 · P0305 自选课包 · P0803 分期免息 · P0804 合规学费分期 · P1001 新客无门槛券 · P1004 弃购挽回 |
| 时间促进 | P0201 早鸟价 · P0204 涨价预告 · P0205 封班截止报名 · P0202 阶梯降价 · P0203 前 N 名加赠 · P0801 定金预售 · P0702 价保 · P0101 限时折扣 |

| 续费承接 | P0901 老学员续报价 · P0303 连报优惠 · P0902 学习会员 · P0903 学员等级 · P0904 积分体系 · P1002 老客续报券 · P1003 沉睡召回券 · P0805 储值 · P0905 节日关怀 |
| 扩科发展 | P0304 多科联报 · P0404 全程班 · P0305 自选课包 · P0402 加价升级 |

`products.md` 的打法库表只是索引（卡号、阶段、针对的障碍、机制、定位句），**只看索引不能定方案**：一项机制可能只适用于老学员、不能和现行活动叠加、有容量或期限前提，这些只在卡片原文里。每个目标提 2–3 个候选，**进入候选的卡逐张读原文**（`<niuma-home>/docs/打法库/<文件>`），过**六个匹配条件**（目标、用户、时间、产品、组合、业务边界），结果填进「候选卡核对表」（模板见第 8 节）：

| 卡号 | 适用人群 / 阶段 | 期限与时间条件 | 产品条件 | 叠加限制 | 业务边界 | 生效 / 失效条件 | 是否采用及理由 |
|---|---|---|---|---|---|---|---|

- 每格从卡片原文取；原文没写的写「卡片未写」，不自己补。「是否采用及理由」以「采用」「附条件采用」「待确认」「不采用」开头，后面写理由。
- 第六章每个正式促销方案都要对应核对表里一张「采用」或「附条件采用」的卡；不用打法卡的方案（服务价值表达、流程改进等非价格方案）写明「非打法库机制」和理由。对应关系写在「决策追溯」表的「促销方案」一格（见第 7 节），`report-check.mjs --design` 会核对。时间适用性：考试只剩几天不推早鸟类；「限时」要有真实期限、容量或学习节点依据。续费卡不能用于新签。依据分级：充分 → 推荐；部分 → 附条件推荐（写适用信号）；关键判断缺失 → 候选待确认；明显不适用 → 不采用（写实质理由）。

**现行活动的时间口径**：`products.md` 的活动基线不是目标月时，它不是本月活动。每项权益区分「当月即时可用 / 跨月预告 / 满足条件后适用」，核对购买时间、上课或完成时间、领取和使用时间（例：10 月录入的成长金有效期到 12 月 31 日，在 12 月仍可抵扣续费订单，但只抵后续续费订单）。

## 5. 执行方针（报告第七章）

时间维度：何时准备、上线、转化、切换（对齐第二章的转折点）。部门维度：

| 工作方向 | 营销投放 | 销售转化 | 用户运营 | 师资交付 |
|---|---|---|---|---|
| 核心需求识别 | 需求型内容与受众测试 | 验证咨询需求和障碍 | 盘点老学员下阶段任务 | 提供常见学习问题与课程支持信息 |
| SKU 推广 | 明确卖点与传播素材 | 匹配产品方案和话术 | 老用户触达与课程衔接 | 确认可交付的课程能力 |
| 活动转化 | 活动推广与渠道投放 | 促销规则解释及成交 | 存量用户权益与续费 | 排课和老师匹配保障 |
| 效果复盘 | 线索质量及投放成本 | 成交与购买阻力 | 续费与用户反馈 | 交付体验与投诉风险 |

最后列可执行事项：事项｜建议负责部门｜时间点｜依赖条件｜验收标准。具体负责人、预算未确认的写「待指派」，不编。本章不再解释学生为什么需要辅导。

## 6. 关键假设（报告第八章）

从 `synthesis.md` 和本轮设计里挑 **3–5 项**会实质影响商业决策的：关键待验证问题｜为什么重要（影响哪个决策：卖点、主推、促销、资源）｜验证方式（查咨询记录、教师匹配数据、盘点存量学员、检查师资排课和投诉风险……）。其余未知放附录。

## 7. 决策追溯（内部，必填）

每个主推 SKU、核心卖点和正式促销方案，都要能沿着「用户情境 → 需求洞察 → 商业机会 → 产品选择 → 价值主张 → 促销方案 → 执行行动 → 验证指标」往回追到第 2 轮的洞察。这张表只留在 `design.md`，不进报告正文；它防止每份文件单看都合理、合起来却证明不了方案来自用户需求。

| 编号 | 用户情境 | 需求洞察 | 可信程度 | 商业机会 | 产品选择 | 价值主张 | 促销方案 | 执行行动 | 验证指标 |
|---|---|---|---|---|---|---|---|---|---|

- 一行是一条决策链，编号 T-01 起；表头一字不差。每格都要填。
- 用户情境：哪些地区、哪类学生（新签 / 续费、学业阶段）、哪个时间窗口。
- 需求洞察：引用 `synthesis.md` 关键洞察编号（如「I-01、I-03」），可加一句话。
- 可信程度：〔已验证〕〔有依据的判断〕〔待验证假设〕之一，取这条链里最弱的一环。
- 产品选择：SKU 名照用，写清角色（如「安心学Max（主推）」）。报告第五章角色表里每个「主推」SKU 都要在某一行出现。
- 价值主张：解决哪个用户关切；能力卡没填的写「需确认产品能力：……」。
- 促销方案：写报告第六章的方案标题和对应卡号，如「考后衔接续报（P0901）」；不用打法卡写「……（非打法库机制）」；这条链不配促销写「本月不额外促销」。报告第六章每个 `#### 方案 N：标题` 的标题都要在这一格出现。
- 执行行动：哪个部门、什么时间点做什么。验证指标：怎样判断有效（增量，不是原有购买的价格让渡）。

检查：`node scripts/report-check.mjs report.md --design design.md --synthesis synthesis.md` 核对每格非空、洞察编号存在、主推 SKU 和方案标题都能追到、方案对应的卡在核对表里是「采用」或「附条件采用」。

## 8. design.md 模板

```markdown
# 商业策略设计 · YYYY-MM

## 1. 地区决策表与机会主题
## 2. 产品匹配（每个机会主题：关切 → 能力 → 卖点；主推 / 辅推；七个 SKU 角色）
## 3. 营销主张
```
