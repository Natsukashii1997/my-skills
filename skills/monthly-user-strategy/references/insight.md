# 深挖机制与洞察综合（第 2 轮用）

摘自 niuma-home `docs/策略规则/10-报告内容规格.md` **report-v2.1** 第 3.2、5、6.1 节。规则以原文为准。

章节结构对了，AI 仍可能只在各章填浅显信息。本文约束第 2 轮「洞察综合」：把第 1 轮的事实、情境、Claim 变成相互关联的商业结论。**负责生成大量 Claim 的第 1 轮不承担这一步**，第 2 轮单独完成、单独产出 `synthesis.md`。

## 1. 院校时间线 → 地区规律

具体事实 → 院校群体聚合 → 时间分布 → 阶段差异 → 地区规律。每个地区看六个维度：

| 维度 | 观察什么 |
|---|---|
| 时间集中度 | 关键考试、作业截止是否集中在某段时间 |
| 院校覆盖 | 数据代表了哪些学校，有多少重要学校缺失 |
| 阶段差异 | 本科与研究生是否节奏不同 |
| 事件连续性 | Final 后是否衔接出分、补考或下学期 |
| 地区内差异 | 有没有明显早考、晚考或特殊院校群 |
| 数据可靠性 | 哪些日期已核实，哪些仍是推测 |

结论形如：「在已覆盖院校中，主要节点集中在某时间段，形成一波以某任务为中心的需求窗口；但部分学校明显错峰（写校名），需要分别设计触达节奏。」

## 2. 六层分析

每个核心用户场景至少回答六层：

| 层 | 必须回答 | 价值 |
|---|---|---|
| 1 事实层 | 用户真实处在什么时间、任务和情境下 | 定位问题 |
| 2 约束层 | 什么现实条件让任务变难 | 发现压力来源 |
| 3 动机层 | 用户真正想达成什么结果、避免什么风险 | 发现深层需求 |
| 4 决策层 | 用户用什么标准评价和选择服务 | 发现购买关键因素 |
| 5 价值层 | 现有产品如何比替代方式更好地满足需求 | 形成产品价值 |
| 6 策略层 | 应在何时、通过什么商业方式满足需求 | 形成实际行动 |

示例（考前约 20 天）——浅层：任务＝期末复习，痛点＝时间有限，需求＝高效复习辅导，强度＝高（任何顾问都写得出，价值有限）。深层：L1 距 Final 约 20 天，要完成期末复习 → L2 时间有限、考试内容广、课程难度不同、能投入辅导的时间也有限 → L3 需要的不只是更多学习时间，而是在剩余时间里找到最值得投入的复习内容与方式 → L4 选外部帮助时更在意：老师能否及时匹配、是否熟悉课程、能否快速诊断问题、是否针对考点 → L5 产品应提供可及时启动、重点明确、适合有限时间的针对性支持，而不只是卖若干课时。

L1 是事实，L2–L5 是研究推导，标可信程度（第 7 节）。**缺少真实反馈时，不停在「可能需要辅导」，继续提出合理、可检验的机制假设，再区分哪些已被证实。** 严谨不等于没有洞察。

## 3. 需求三问

用户表面上要什么？真正想解决什么？最终想得到什么？例（考前辅导）：找老师复习课程 → 剩余时间有限，不知道怎样提高复习效率 → 在有限时间内更有把握地完成重点复习和考试准备。第三问决定卖点打「专业导师 / 大牌师资」还是「快速诊断 / 针对性复习 / 高效利用剩余时间」。**用户买的不是 SKU 名称，而是希望通过服务获得的进展**（Jobs to Be Done）。

## 4. 不同学业节点（研究框架，按当月证据筛选，不机械全列）

| 用户阶段 | 核心任务 | 潜在深层矛盾 | 服务价值重点 |
|---|---|---|---|
| 开学初 | 建立学习基础 | 尚不清楚课程难度与自身准备程度 | 学习诊断、课程适应、提前规划 |
| 学期中 | 跟上进度、完成作业与阶段考试 | 多门课程持续占用精力 | 跟课支持、薄弱点补强、进度管理 |
| Final 前约 20 天 | 集中应对考试 | 时间与考试任务之间出现明显约束 | 快速匹配、重点定位、针对性复习 |
| 补考阶段 | 准备再次参加考试 | 原有学习方式可能未解决关键问题 | 原因诊断、针对性强化、重新规划 |
| 出分后 | 评价学习结果及下一步 | 尚未明确后续课程与支持需求 | 学情复盘、下一阶段规划 |

## 5. 需求洞察与购买障碍分开，中间加「决策标准」

「担心考前没有合适老师」含两种信息：服务需求（希望快速匹配熟悉课程的老师）→ 决定产品能力；购买障碍（不确定我们能否及时提供）→ 决定销售与营销怎样建立信任。两者不能混为一个 barrier。顺序：

用户任务与现实约束 → 深层需求与理想结果 → **用户评价服务的决策标准** → 购买障碍、信任问题与行动时机 → 产品匹配、价值表达、商业干预

障碍编码（`barriers.md`）照用，但研究的是购买行为，不是机械套编码。新签、续费仍分开研判。

## 6. 机会判断四维与竞争性解释

不把 `need_strength` 当核心商业优先级。分开判断：

| 维度 | 研究什么 |
|---|---|
| 需求紧迫性 | 距关键任务还有多久，延误的后果 |
| 需求真实性 | 用户是否真的在寻求帮助，有哪些反馈或行为证据 |
| 购买成熟度 | 是否有意愿、预算、信任及明确购买计划 |
| 服务可行性 | 我们能否及时匹配老师、交付有效课程支持 |

四者可能完全不同：只剩三天、极紧迫，但来不及诊断、排课和交付，就不能因紧迫性高判为最值得销售的机会，甚至应减少承诺。机会价值是四者的定性综合，不是公式。

**竞争性解释**：凡会影响主推 SKU、促销方式或重大资源投入的核心判断，至少比较一个有意义的替代解释，写明用什么证据排除或保留。例：考前咨询量上升，可能是压力上升、临考才意识到准备不足、早有需求但因价格或信任迟迟未买、某内容或渠道改变了咨询行为、考试时间集中使分散咨询聚集——对应完全不同的营销策略。比较过程留在 `synthesis.md`，报告正文只留结论、关键依据和必要的不确定性。

## 7. 证据来源与可信程度

四类来源：学校官方与外部信息；内部历史经营数据（尤其**历史同阶段数据**：去年同一窗口咨询何时增长、哪些地区先增长、购买集中在哪、咨询为何未成交；比较时控制口径，渠道、产品、校历、样本变了不照搬）；用户声音与一线反馈；产品及交付数据。

正文关键判断标三档（只标关键判断，不逐句标）：

| 标注 | 含义 | 典型依据 |
|---|---|---|
| 〔已验证〕 | 有直接事实或数据 | 官网核实的日期；背景卡事实记录（适用范围对得上）；经营数据 |
| 〔有依据的判断〕 | 多条间接依据一致指向 | 原表日期；业务观察（适用范围对得上）；同阶段历史规律 |
| 〔待验证假设〕 | 机制推演，合理且可检验 | 第 2 节 L2–L5 中没有证据的部分；管理判断 |

研究层的 status / 证据强度规则（`schema.md`、`barriers.md`、`lifecycle-bizcard.md`）照旧约束 `draft.json`；报告的三档是面向读者的表达，二者要对得上：研究层 `unknown` 或 `inferred + weak` 的购买判断，报告里只能是〔待验证假设〕。

## 8. 写作单位：Insight

Insight = 事实模式 + 解释机制 + 经营含义。完整的一条包含：核心结论｜事实支撑｜解释机制｜适用范围｜经营含义｜可信程度。只有事实没有解释，不是完整洞察；只有解释没有事实，是假设；有事实有解释却不影响任何决策，不进正文。

**适用范围写到国家和人群**：写清哪些国家或地区、哪类用户（新签 / 续费 / 通用，必要时加学业阶段）、证据是什么时间的。业务证据的范围看 `digest.md`「业务背景卡条目」的「适用国家」「适用人群」「来源」三列，结论不能比证据的范围更宽：英国新签的咨询记录不能证明美国学生或英国老学员的购买障碍；要推到别的地区或人群，那部分写成〔待验证假设〕并说明推的理由。范围写「未填（范围不明）」的业务证据，不能支撑〔已验证〕。

**编号**：关键洞察从 I-01 起编号。第 3 轮 `design.md` 的「决策追溯」表按编号引用，`report-check.mjs --synthesis` 会核对编号是否存在。编号只在内部文件用，报告正文不出现。
