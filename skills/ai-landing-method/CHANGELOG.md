- 新增：「不值得新建 / 先修规则 / 只做局部 / 保留人工」都是合格结论；承重判断写成可以被推翻的因果链，深度框架第 5 步加竞争解释对照表。

- 改动：step2、step3 检查项同步加上以上几条。
- 修复（第二轮盲测后）：step1「要问用户的」第 5 题补上要过程数据样本（聊天记录、工单、表格导出）；SKILL.md 写明并成一轮时材料题以第一轮第 3 题的范围为准；建议回上一步时先确认上一步的材料在不在。
- 修复（第三轮盲测后，改后未重跑）：给用户的填写示例改用括号占位、不加引号，reference 表格里的引号示例只作参考答案；能判断进入哪一步时，第一轮回复第一句写明判断。
- 没迁的：诊断工作底稿（已有跨会话续接）、一图一文交付（第二步已有）、只能点名调用（本 skill 要能自动触发）、路觅公司案例笔记。

## 0.5.0 - 2026-11-05（8ff2d17，#35）

第五次执行层修订：常浩确认三步的对象。第一步是业务团队（一线和业务负责人）；第二步、第三步都是产品和技术。两步读者相同、看的不同：第二步看系统整体怎么建（本体、链路、界面），第三步看每类人怎么用（分角色流程、动作留痕、检查口径）。SKILL.md、深度框架、data-ontology 和三步 reference 里写到对象的地方同步改；第三步的论证逻辑改为写给产品和技术看。

## 0.4.0 - 2026-11-05（c2176de，#33）

## 0.3.0 - 2026-11-05（5857abb，#27）

一个 PR 里合了第一到第三次执行层修订。

**第一次**：在路觅企微侧边栏案例上做第二步时，产出深度明显不如范例，重做时又险些照搬范例的 13 章。原因在执行层：没有分析环节，范本写成了章节清单，检查只问有没有，材料没有盘点。

- 新增 `references/depth-framework.md`：「从证据到决定」八步、浅深对照的质量特征、自检题、反模式。
- 三步的「产出范本」改为「质量特征与范例」，写明案例章节只作参照；各步新增「深度动作库」，检查项加入深度类和材料类。
- 执行改为按八步走，结构从本案推导；检查改为对照质量特征，并加独立审查。

**第二次**：第二步重写两版都被否。首页把一个数据发现当成立意，没有交代这是销售工作台和侧边栏的整体设计；章节按零散发现命名，打碎了论证顺序；推进部分写「先给谁用」，对开发没有价值。根因是旧版深度框架把「主线发现」当成立意和结构的来源，也没写清每一步给谁看。

- 新增 `references/data-ontology.md`：对象、关系、状态、事件；待办 = 本体事件 × 规则；六步推演，分工和失败标准，三步各怎么用。
- 深度框架新增第 0 节「每一步给谁看」：受众 × 步骤矩阵，定位立意和发现分开；第 5 步改为「找关键发现」，第 6 步改为「按读者的论证逻辑排结构」。
- 三步各新增「论证逻辑」。章节名可以按场景改，顺序和每部分的作用不能丢。

**第三次**：用新 agent 按上一版 skill、以同一输入模拟第二步。结构和技术深度达标，但暴露了这些问题：只比了用户提到的业务线差异，没验证三位新人的新老差异；用代理指标得出和兑现数据相反的结论；直接推翻了用户「两条线分开做」的要求；用户的第一项功能需求没画出来；自检全部打勾，独立审查却查出 15 处前后不一致；页面干巴巴。

- 新增 `references/deep-dig.md`：按 grill-me 的追问树问到底；七个差异维度逐个过；每个业务单元追六层；量结果不量代理。
- 新增 `references/presentation.md`：网页质感的底线和截图自检（当时默认引用 `hairline-page`，0.7.0 改为自带）。
- SKILL.md：提问加深挖要求；用户的结构要求和证据相反时必须停下来问；槽位先从材料找；大附件给路径；检查加机械核对、截图和审后复核。
