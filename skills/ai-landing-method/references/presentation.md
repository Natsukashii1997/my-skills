# 呈现：做到网页的质感

三步的产出都是单页 HTML。读者愿不愿意读完、能不能一眼看懂，取决于页面本身。所以呈现和深度一样是验收项：先把深度做够，交付前呈现也必须过线。干巴巴的文字和表格堆在一起，就算内容对，也不算完成。

## 1. 用什么风格

- 用户或项目指定了风格，按指定的来。
- 没有指定时，从下面三套里选，默认用**细线**；用户说“用柔光”“用精密暗色”就换。
- 选定一套后，颜色只用这一套里的色值，不即兴调色；字体、圆角、阴影也照这一套。
- 三套都要过第 2 节的底线。下面的色值和尺寸是起点，换了业务或团队有自己的品牌色，直接改这里的值。

### 三套风格一览

| | 细线 | 柔光 | 精密暗色 |
|---|---|---|---|
| 气质 | 专题讲解页：冷静、像设计稿，信息密度高 | 产品功能页：亲和、轻盈，像一个产品官网 | 深色产品官网：精密、克制，像在看真软件 |
| 适合 | 默认；内容多、要一块块讲清楚的报告 | 想让读者先看到产品长什么样、语气偏轻松的场合 | 界面原型分量重、读者习惯深色软件界面的场合 |
| 底色 | 冷灰 `#F3F4F6`，白卡片 `#FFFFFF` | 浅蓝灰 `#EEF1F6`，白卡片，浅底 `#F5F7FA` | 近黑 `#08090B`，表面分四级 `#0F1013` / `#141519` / `#1A1B20` / `#22232A` |
| 文字 | 主 `#101318`，次 `#434A55`，弱 `#5F6672` | 主 `#1B2333`，次 `#4A5568`，弱 `#667085` | 主 `#F4F5F6`，次 `#D0D4DB`，弱 `#8A8F98`，最弱 `#5E636B` |
| 线 | 1px `#D7DAE0`，浅一级 `#E6E8EC` | 1px `#E2E7EF`，少用，靠阴影分层 | 1px 半透明白：`rgba(255,255,255,.07)`，强调处 `.12` |
| 强调色 | 每条主线一种：橙 `#DD5129`、蓝 `#2D53D2`、绿 `#0A8470`；各配浅底 `#FBE8E1` / `#E6ECFB` / `#DBF0EA` | 每条主线一种：橙 `#EE7340`、青 `#2A8C83`、紫 `#6A5AE0`；各配浅底 `#FDECE3` / `#DDF1EE` / `#ECE9FD` | 只有一种淡紫蓝 `#8790F5`（浅底 `rgba(135,144,245,.14)`），只用在焦点、当前项和主按钮；状态色 完成 `#4CB782`、提醒 `#E5A44B`、紧急 `#EB5D5D` |
| 字体 | 标题和正文 Noto Sans SC；数字、编号 Archivo；标签和代码 JetBrains Mono | 标题 Manrope + Noto Sans SC；正文 Noto Sans SC | Geist + Noto Sans SC；代码 Geist Mono |
| 标题 | 900 超粗，`letter-spacing:-.015em`；首屏 `clamp(42px,6.4vw,86px)`；章节大编号 Archivo `clamp(110px,15vw,200px)` | 800，`letter-spacing:-.02em`；首屏 `clamp(40px,4.8vw,66px)` | 600，字距收紧 `-.035em`；首屏 76px，章节 44px；标题分两段，第二段用次级文字色 |
| 形状 | 方角；只有应用窗口 8px 圆角，按钮 2–3px；**不用阴影** | 大圆角：卡片 22px，窗口 18px，标签和按钮全圆（胶囊）；柔和阴影 `0 1px 2px rgba(27,35,51,.05), 0 12px 32px -8px rgba(27,35,51,.12)` | 窗口 12px，控件 6–10px；窗口带深阴影 `0 30px 80px -40px rgba(0,0,0,.9)`，其余靠表面明暗分层 |
| 版式 | 左标签右内容，逐块往下；章节头用超大色编号，左右交替；演示放进深色全宽带里的浅色应用窗口 | 首屏放一个可播放的产品演示当主视觉；讲解（判断、决策、提示词、产出）收进一组标签页；主线画在应用窗口顶部的步骤条里 | 1200px 居中，左对齐大标题；内容放进一块块“产品界面截图”窗口；主线做成左侧项目列表，提示词做成带批注的编辑器 |

### 各套的关键组件

**细线**
- 顶栏：56px，半透明冷灰加毛玻璃，左边品牌字，右边带编号的锚点导航。
- 首屏：40px 细网格底往下渐隐；左边超大标题（同一标题里用一段 400 细体灰字做对比），右边 2px 黑顶线的引用块。
- 主线骨架：N 列白卡，顶上 4px 主线色线，列间黑色箭头。
- 数字条：顶上 2px 黑线，Archivo 大数字配小字口径，重点数字用主线色。
- 批注视图：左边带行号的等宽正文，`{{槽位}}` 浅底高亮；右边灰底批注栏。用于提示词、规则、配置。
- 演示带：深色区（`#15181D`）横跨全宽，里面放浅色应用窗口；收尾是一条深色“下一步”条。
- 标签和元信息：等宽字 11–12px，大写，`letter-spacing:.08em`。

**柔光**
- 胶囊标签：白底、全圆角、柔和阴影，放在标题上方说明这是哪一部分。
- 舞台：主线色浅底的大圆角区域（28px），里面放白色应用窗口（18px 圆角、较深的下沉阴影）。
- 步骤条：一排胶囊，当前步用主线色实底。
- 待办卡：白底 16px 圆角，1px 线加阴影；优先级用浅底色字的胶囊（如 `P0` 橙底橙字）。
- 聊天气泡：白底，左上角 4px、其余 16px 圆角。
- 数字卡：一张张白色圆角卡，大数字加小字口径。
- 主按钮：深色实底、白字、全圆角。

**精密暗色**
- 窗口：表面 1 级底、1px 半透明白边、12px 圆角、深阴影；窗口顶部是细的标题栏。
- 列表项：当前项背景升一级表面，左侧 2px 淡紫蓝内边线。
- 状态点：14px 圆圈；完成为绿色实心点，进行中为淡紫蓝半圆，未开始为空心。
- 编辑器：等宽字、行号用最弱文字色；批注挂在右侧，像代码评审。
- 事件时间线：当前节点淡紫蓝实心，外加一圈 4px 淡紫蓝光环。
- 强调色克制：同一屏里淡紫蓝只出现在一两处。

## 2. 底线

| 项 | 要做到 | 不合格的样子 |
|---|---|---|
| 首屏 | 超大标题、一句设计思想，再加一张把全貌画出来的图（主线骨架、系统全貌或业务流 × 数据流）；读者不往下翻就知道这是什么 | 一段说明文字加四张数字卡 |
| 空间和节奏 | 章节之间大留白（96–120px），区块之间 64px；段落最多 3 行；白底和灰底整带交替；各章构图要变：演示的位置、尺度、标题方向至少换两样 | 连续两屏只有表格或文字；每章长得一样 |
| 原型图 | 照用户给的截图或真实界面还原，比例、控件、配色像真的：比如企微聊天窗口加右侧栏、电脑工作台；放像真的示例内容，标“示意”，不用真实客户姓名 | 几个方框加几行字的线框图 |
| 需求对照 | 用户给了功能需求（截图、需求文档）的，做一张“需求 → 视图”对照表，每一项都有对应的原型图 | 需求只在图注里带一句 |
| 生图 | 环境有图像生成工具时，用它画全貌插画、场景图（比如一位销售的一天），再用 HTML 在图上标注；没有时，用 SVG 或 HTML 画到同样具体。生成的图压缩后内联，不放没有信息的装饰图 | 全页没有一张能让人进入场景的图 |
| 过程演示 | 每条核心链路至少一个可以播放、逐步查看的演示，演示的是真实过程：一条消息变成事件，事件生成待办，完成后写回 | 静态文字描述流程 |
| 数据图 | 能用图说清的数据（时段分布、漏斗、对比）画成图，按 dataviz 规范；表格留给字段表、规则表、对照表 | 数字全部放在表格里 |
| 技术图 | ER 图、状态机、流程图用同一套视觉语言：同一类东西同一种颜色（规则、AI、外部系统、人工），连线、箭头、基数标注清楚 | 每张图各用各的颜色，线挤在一起 |
| 主题 | 细线、柔光在浅色和深色下都清楚可读；精密暗色本身是深色，只做深色；默认只做电脑版 | 深色下文字看不见 |

动效只允许三类：业务过程演示（对话逐条出现、步骤逐个点亮、待办生成后写回、清单逐条打勾）；交互反馈（标签切换、悬停、复制成功，0.15–0.3 秒）；演示里新内容进场（约 0.4 秒，上移 8px 并淡入）。不加背景动画、流动虚线、脉冲光圈、漂浮小点、滚动视差、数字滚动这类装饰。演示要有“播放 / 暂停、重播、逐步”控件，第 0 步也要有可读内容；开启“减少动态效果”时直接显示最终画面。

## 3. 自检

1. 用无头 Chrome 截整页长图，逐段看：有没有溢出、错位、文字墙、空白演示、看不清的图。macOS 上的命令（`$TMP` 换成任意临时目录；截图前在预览副本里关掉 CSS 过渡，否则可能截到半途的画面）：

   ```bash
   "/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" --headless=new --disable-gpu --hide-scrollbars --user-data-dir=$TMP/chr --window-size=1440,14000 --virtual-time-budget=8000 --screenshot=$TMP/full.png "file://$TMP/preview.html"
   ```
2. 逐条对照第 2 节的底线，每条写“做到了”或“没做到，原因”。
3. 回答三个问题：
   - 只看首屏，能说出这是什么吗？
   - 随便翻到哪一章，有没有一个视觉锚点（图、原型、演示）？
   - 用户给的每一项功能需求，能在页面上找到它的样子吗？
4. 改完再截一次图确认。

## 4. 反例

路觅案例的模拟测试（2026-11-05）：内容按论证逻辑排得很完整，ER 图、状态机、事件表、接口都有，但页面是默认灰底加一张接一张的表格；原型只有两张线框；用户的第一项功能需求“试听课表日历”没有画出来。用户的评价是“干巴巴的，没有任何设计感、美感、空间感”。深度和呈现都要过线，缺一样都不能交付。
