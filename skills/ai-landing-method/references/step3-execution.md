# 第三步 · 执行规范：从用户视角落到每个人的具体动作

翻译方向是方案 → 每个人的具体动作。技术框架大家已经有感觉了，新问题是：每个人具体要处理哪些业务单元、什么时候、怎么做。这一步不再另做访谈，用已定方案和过程数据来回答。

- **对象**：一线和主管。
- **输入**：上一版方案 + 过程数据材料 + 新情况材料（有的话）。
- **产出**：一份执行规范，按人群（有差异时）和组织维度排好的具体动作，能照着做、能被检查。
- **交给下一步**：上线后的新反馈，回到第二步或第三步。

## 先行判断

1. **技术框架已经定了，新问题是“每个人具体做什么”。** 不能推翻上一步定下的东西。
2. **这次为什么要出规范。** 可能是出现了新反馈（路觅案例里是业务负责人反馈新人和老手的需求不一样），也可能只是方案刚定、要第一次落到一线。照实写，不要假设有新反馈。
3. **不需要再访谈。** 上一版方案加过程数据（路觅案例里是真实聊天记录）已经足够回答，再访谈只会重复采集。前提是材料够用；不够时先补材料，或在报告里写明结论的可信度。

用户的局面和这三条不一样时，按 SKILL.md 第 3 节 ① 处理。常见的差异：没有成文的上一版方案（请用户提供，或者先回到第二步）；过程数据只有一部分（写明局限后继续，或请用户补充，见 SKILL.md 第 1 节）。

## 设计决策

| 判断 | 所以提示词要 | 对应段落 |
|---|---|---|
| 不能推翻已经定下的东西 | 开头交代上一版方案定下的核心内容，并附上原文 | 已定方案、附件 |
| 结论要来自行为，不能来自印象 | 写明这次不再访谈，直接基于过程数据分析；材料不够的地方指出缺什么，不补编 | 新情况 |
| 视角要从“系统能做什么”换到“用户最想看什么” | 站在业务人员视角，回答问题是什么、怎么分析、最想看到什么、每类人要处理的业务单元清单 | 需要回答 |
| 不同的人缺的可能不一样，但分组要有依据 | 数据显示需求明显不同才分组，否则合成一套 | 组织方式 |
| 规范要能照着做、能被检查 | 按组织维度排序（路觅案例里是一天中待办发生的时间顺序），可以画成时间轴或流程图 | 组织方式 |

## 骨架公式

**已定方案 × 新情况 × 用户视角 × 分组与顺序 → 可执行的规范**

缺了“已定方案”，会推翻上一步；缺了“用户视角”，结论又回到系统能做什么；缺了“分组与顺序”，规范没法照做。

## 标准提示词（v8.1）

本步专属槽位：

- `方案核心`：一句话概括上一版方案定下了什么。
- `新情况`：这次为什么要出规范。没有新反馈时，写“方案刚定下，要第一次落到一线”。
- `人群划分`：怀疑存在差异的人群；没有依据怀疑有差异时删掉。是否真的分组，由 AI 按数据判断。
- `上一版方案`、`过程数据材料`：附原文。
- `新情况材料`：业务方的反馈原文、看板等；没有时连标签一起删掉。

```
上一版方案已经定下{{方案核心，例：待办事项怎么流转、数据怎么回流、业务流怎么打通}}（附在后面）。大家对技术框架已经有感觉了，接下来要解决的是：每个人具体要处理哪些{{业务单元，例：待办}}，该怎么做。

最近有了新情况：{{新情况，例：业务负责人反馈，新人和老手的需求已经不一样了，并准备了看板。}}这次不再另做访谈，请直接基于上一版方案和{{一线角色，例：销售}}的{{过程数据，例：真实聊天记录}}来分析；材料不够支撑结论的地方，直接指出还缺什么，不要补编。

请站在业务人员的视角回答：
1. 他们日常工作中遇到的具体问题是什么，我们做出来的软件要帮他们解决哪些；
2. 这些问题该怎么分析，需要看哪些数据；
3. 他们最想看到的是什么；
4. 每类人要处理的{{业务单元}}清单是什么，每一项写清楚什么时候出现、要做什么、怎么做。

如果数据显示不同的人需求明显不一样{{人群划分，没有可删，例：（比如新人和老手）}}，请分开梳理，否则合成一套。每一套都按{{组织维度，例：一天中待办发生的时间顺序}}来组织，可以画成时间轴或流程图。输出一个单页 HTML。

<上一版方案>
{{上一版方案}}
</上一版方案>
<过程数据>
{{过程数据材料，例：新老销售近两周的企微聊天记录}}
</过程数据>
<新情况材料>
{{新情况材料，没有可删，例：业务负责人的反馈原文和看板}}
</新情况材料>
```

## 产出范本

一份能照做的执行规范分四组内容，每组都能追溯到提示词的某一段：

| 组 | 作用 | 来自提示词 | 路觅案例里的章节 |
|---|---|---|---|
| 先定口径 | 哪些数字能用，先说清楚：样本、对照组、剔除项、时间窗口 | 需要回答 | 00 先讲清楚口径 |
| 比出差异 | 用真实行为比较不同人群（有分组时）：行为指标、做法上的差异、能力画像；没有分组时，改为找出共性的问题和薄弱环节 | 新情况 | 01 行为差异（七项指标）；能力画像（六维） |
| 按组织维度排动作 | 每一套按组织维度排出具体动作：什么时候出现、要做什么、怎么做 | 组织方式 | 03 新人每日行动逻辑；04 熟练销售每日节奏 |
| 落到动作和检查 | 每天（或每个阶段）具体做什么、系统留下什么、怎么查：分层跟进规则；动作 → 回流数据；可执行的检查清单和执行指标 | 需要回答 | 05 分层客户跟进规范；06 动作 → 回流数据；07 可执行的检查清单 |

路觅原页：《新老销售 · 能力模型与执行规范》（2026-11-04 晚，8 节，依据 1,361 个客户会话；新人承诺 72 小时兑现率当前 56.8%，目标 ≥ 75%）<https://s3.fmode.cn/user/K0xKEZANOG/lumi/sales-standard/index.html>。原页打不开不影响检查，以上表为准。

## 检查项

结构：

- [ ] 四个问题都答了：遇到的具体问题、怎么分析与看哪些数据、最想看到什么、业务单元清单。
- [ ] 清单里每一项都写了什么时候出现、要做什么、怎么做。
- [ ] 分组有数据依据；没有依据时合成一套，没有硬分。
- [ ] 按组织维度排序，有时间轴或流程图。
- [ ] 每个动作写了会留下什么数据，主管能据此检查。
- [ ] 和上一版方案一致；有调整的地方写明了理由。

事实：

- [ ] 开头讲清了口径：样本多大、时间窗口、剔除了什么。
- [ ] 行为差异和指标来自过程数据材料，样本小的地方写明了。
- [ ] 材料不够支撑的结论，指出了缺什么，没有补编。
