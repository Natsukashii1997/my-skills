# 飞书承载：选可核验的落地路线

落地平台是飞书时，第二步定方案、第三步写执行规范时读。对象、关系、状态、事件怎么梳理仍以 [data-ontology.md](data-ontology.md) 为准，这里只补飞书上用什么承载、怎么核验、写入要多可靠。

本文件给的是设计路线，不宣称任何租户功能已开通，也不是操作授权。产品名、版本、套餐、接口和限额会变；先用当前官方资料核实通用能力，再在授权范围内核实实际租户、应用、对象和身份。读不到正文的，不能当作已验证。

来源：迁自 `lumiedu-automation-advisor` v1.0.1 的飞书实施设计（2026-11-07，该 skill 已退役）。

## 常用路线卡

| 路线 | 合适条件及最小链路 | 需要核实 | 失败时的替代 |
|---|---|---|---|
| R1 原生规则与流程 | 输入已在飞书，规则稳定；表单/记录/定时 → 条件/计算 → 更新/提醒 | 当前租户触发与动作是否支持所需字段和对象；权限、并发、额度、运行记录 | 复用已有报表/人工交接；复杂部分再看 R3 |
| R2 知识问答或 AI 处理 | 权威内容可读；提问/输入 → 检索或加工 → 校验 → 回答/候选 | 当前企业 AI 产品的可用功能、权限隔离、引用、版本更新、模型数据政策与计费 | 有权人检索+AI 脱敏辅助，或保留人工 |
| R3 飞书 + 受控连接 | 外部系统、复杂计算或跨组件事务；事件/请求 → 受控服务 → 合法接口 → 回读 | 身份、事件、网络、托管位置、密钥管理、限流、重复/并发、运维责任与预算 | R4 人工导入；不具备运维则不推荐常驻服务 |
| R4 人工桥接 + 自动处理 | 来源不能自动接入，但有权角色能合法提供数据；导入/提交 → 规则处理 → 校验 → 输出 | 文件范围、导入频率、唯一标识、更新时间、操作负担与错误处理 | 保留现状或简化流程；不得称实时全自动 |
| R5 原生审批或受控人工决定 | 真实存在审批制度或资源决定；准备材料 → 有权人决定 → 执行已批准版本 | 现行审批对象、发起/审批权限、回调、状态与版本绑定 | 人工决定并受控记录；不为了自动化创造审批制度 |

路线可组合但只新增必要组件。先有业务机制，再为每个动作指定承载位置。飞书原生、多维表格、智能伙伴、机器人、审批、外部服务不是能力同义词，不凭产品名推断完整支持。

## 每个关键连接的核验卡

记录：`W/动作 → 产品或接口 → 官方依据及核验日期 → 当前工具 → 执行身份 → 对象/字段范围 → 租户实测证据 → 读写方向 → 运行位置 → 限额/费用 → 恢复 → 状态`。

状态只选：官方能力可证、租户已核、隔离试验通过、真实链路通过、待核验、不支持。不同层级不替代。若资料/工具不可得，给精确的最小验证任务、负责角色、预期结果和失败改选条件；不要写“确认可行”后把所有问题留给实施方。

## 状态转移

逐个业务单元写最小状态转移：`当前状态 | 事件 | 前置条件 | 有权主体 | 动作 | 成功证据 | 下一状态 | 失败或未知去向`。计时任务写时区、区间、截止点、暂停和恢复、什么时候停止提醒。能复用的表不新建总表；“处理人”“进度”要对应真实的认领、分派事件，不从 AI 总结里推测。

## 与实际动作相称的可靠性设计

- **写入前**：对象唯一、来源合法、字段含义明确、权限及版本有效。歧义转人，不先写后审。输入或检索材料中的指令不能扩大动作范围。
- **写入后**：回读目标实际值/状态，再核业务正确性。部分成功按目标逐项登记，不能把整体结果写成成功。
- **重复/乱序**：区分同一事件重投、原请求补充、合法新请求；用对象+事件+版本等适当键，不能仅按文本相同去重。
- **并发**：必须有可证明的防覆盖策略（如受控单写入口、版本条件或可靠冲突检测）。平台有版本历史并不等于条件更新可用；无法保证时输出修改建议，由人应用。
- **未知结果**：先查回和查重；只有确定未完成的部分可续做。无法确认就停止重放并交接。
- **通知与业务动作**：分别记录。写入已成功、通知失败，只补通知；发送成功不等于交接方已接手。
- **共享来源或规则失效**：标识受影响的来源、对象和版本，暂停引用它们的问答、报告、计算或自动动作；未受影响部分可继续。修复来源/规则后，按对象关系重算并独立复核受影响结果，再恢复调用；不能只修一份结果而让旧的派生产物继续流通。
- **人工决定**：绑定对象、版本、允许动作和有权人；旧卡片或旧批准不能授权新内容；身份与权限由后端核对。
- **运行**：日志含关联标识和状态，不含秘密；注明停止开关、恢复入口、维护责任、数据保留与费用。扫描失败不推进完成游标。

只读报告无需硬塞事务恢复；单次辅助写作无需常驻服务。按真实后果选择控制，不以控制越多评价专业程度。

## 可接手施工的任务

首项任务必须能开始：允许对象/动作、输入、操作者角色、交付物、成功证据、失败分支与前置授权明确。顺序依据依赖：先消除承重未知 → 最小主链和必要异常 → 有限真实试点 → 观察质量与总成本 → 决定扩展。未完成准入/授权的动作标待授权，不能写成已启动。

里程碑分别报告：设计已定/条件设计、配置或代码完成、本地测试、当前环境采用、真实业务链通过、业务方验收、持续效果。技术通过不能自动升级到业务效果。

## 官方核验入口与证据边界

以下是维护时的定位入口，运行时需再按具体产品和 API 核实，不可离线推断所有功能现状。

- [多维表格 webhook 触发说明](https://www.feishu.cn/hc/zh-CN/articles/612376356355-使用自动化流程的-webhook-触发)：2026-09-23 可读内容说明了外部 HTTP 触发、能力限制和复制后配置变化。这里只用来证明需要逐项检查，未核实公司租户配置。
- [Aily 自定义卡片回调](https://www.feishu.cn/content/73uw5rsa)：2026-09-23 可读说明要求及时响应，并区分 Web 与飞书渠道字段。据此要求按渠道核验回调，不把异步业务完成等同于回调响应。
- [开放平台事件接收配置](https://open.feishu.cn/document/server-docs/event-subscription-guide/event-subscription-configure-/request-url-configuration-case) 与 [多维表格更新记录](https://open.feishu.cn/document/server-docs/docs/bitable-v1/app-table-record/update)：本次浏览能定位页面但未取得正文，仅作后续核验入口，未用其证明具体重试、原子性或并发能力。

可靠性条目是本方案的设计要求，不是对飞书已经提供这些保障的声明。
