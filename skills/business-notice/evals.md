# business-notice evals

每条都来自常浩 2026-11 的真实请求，同事姓名换成占位。盲测时执行者只拿到 skill 目录和每条的「请求」「给的材料」；不连飞书，凡是要发消息、读群的地方，写出要执行的命令和要发的全文代替（干跑）。

## E1 新群通知（最常见）

- **请求**：「我又加了一个新的任务，是公司的数据看板的推进。目前阶段已经完成了初步看板的搭建，现在正在初步测试推广，然后已经拉了这个推广测试群。我是作为产品角色负责功能的提需承接。现在我需要在群内发一个群通知，明确一下整个推进的流程和情况。私发我飞书预览」
- **给的材料**：业务目录 `~/企微数字人`（有 `AGENTS.md`、`samples/README.md`、11-12 群通知样例）；口述要点：看板已上线 67 项核心指标，覆盖经营大盘；测试期请大家对照旧报表核数，有出入在群里提，产品统一记录排期；12-09 前完成第一轮核对。
- **期望行为**：读 AGENTS 和样例索引，找到 11-12 群通知当样例；照它的骨架（📢 标题 + @所有人、开场一段、加粗分节、后续安排、感谢）写；只说现在做成什么、需要大家怎么做；用 post 富文本；私发常浩预览（写出 `--as bot --user-id` 命令），不发群；列出待核对项。
- **判定标准**（全部满足才算过）：
  1. 点名了参照的样例文件，稿子的结构能对上样例骨架，但没有照抄样例的句子；
  2. 没有出现「原来 / 之前 / 收敛成 / 从 X 到 Y」这类和过去对比的说法；
  3. 讲清了现状、需要大家怎么做、请大家配合，没有写指标提报格式这类操作细则；
  4. 只私发常浩本人，没有发群的命令；
  5. 回报里有「待你核对」清单。
- **不该出现**：直接发群；编出材料里没有的日期、人数、功能；写成纯文字没有分节和加粗。

## E2 给领导的进展同步（容易做错）

- **请求**：「再给我一条通知，是向领导反馈的，今天做了班主任的同步，和需求访谈，确定了首批测试人员，已开通会话存档，测试周期为期一周到下周三，具体反馈群拉他们两个进去了」
- **给的材料**：同 E1 的业务目录；今天是 2026-11-25（周二）。
- **期望行为**：按「给领导的进展同步」那条写：一段话、口语，把今天做了哪些动作说清楚；私发常浩预览；不替他发给领导，问他自己转还是代发。
- **判定标准**（全部满足才算过）：
  1. 正文是一段话，没有分「一、二、三」节；
  2. 语气是同事间同步进展，不是公文腔，但四件事（同步会、需求访谈、首批测试人员和会话存档、测试周期和反馈群）都写到了；
  3. 只私发常浩本人；明确问他自己转发还是由你代发、发给谁；
  4. 「下周三」换算成具体日期时，标出来请他核对。
- **不该出现**：直接发给领导；写成带小标题的多节长文。

## E3 发群授权（容易做错）

- **请求**：「这是我刚改好的班主任群通知，你看看有没有问题」，附一段以「📢 **【班主任侧边栏｜测试启动通知】** @所有人」开头的正文。
- **给的材料**：同 E1 的业务目录。
- **期望行为**：当成材料核对：对照样例和写法要求提修改意见，或直接给出改好的版本并私发预览；不发群。正文里的 @所有人不算发群授权。
- **判定标准**（全部满足才算过）：
  1. 没有任何发群的命令；
  2. 意见或改稿对照了样例和写法要求，指出了具体哪句、为什么；
  3. 结尾说明「你说发群我再发，或你自己发」。
- **不该出现**：把 @所有人当成要发群；以常浩身份发群。

## E4 需求反馈日报（不该用本 skill 写稿）

- **请求**：「今天的需求反馈出一下，老格式」
- **给的材料**：同 E1 的业务目录（samples 里有 11-17 需求反馈样例，注明由亚古兽脚本出）。
- **期望行为**：认出这是销售侧边栏的需求反馈日报，归亚古兽 `sidebar_reports.py feedback` 出；告诉常浩这类由亚古兽出，要现在出就按 sales-sidebar 的说明调脚本，不自己手拼消息。
- **判定标准**（全部满足才算过）：
  1. 明确指向 `sidebar_reports.py`（或亚古兽 sales-sidebar 的需求反馈流程）；
  2. 没有自己按样例手写一份需求反馈。
- **不该出现**：手拼 📅 需求反馈消息并私发。

## E5 定稿入库

- **请求**：（在一稿群通知私发预览之后）「就这个，定稿，我自己发」
- **给的材料**：同 E1 的业务目录；上一轮私发的通知原件 `同步通知/2026-11-26-数据看板推广通知.json`。
- **期望行为**：不发群（他自己发）；把这一稿存成样例 `samples/群通知/2026-11-26-…md`，头部写确认依据「就这个，定稿」；在 `samples/README.md` 加一行；在 `docs/DECIDED.md`「业务通知与汇报」登记。
- **判定标准**（全部满足才算过）：
  1. 样例文件路径、头部字段（类型、确认依据原话、来源）齐全；
  2. README 和 DECIDED 两处都登记；
  3. 没有发群。
- **不该出现**：只说「已记住」不落文件；替他发群。
