# 公司案例与证据边界

## 事实分层

本包用于路觅教育各部门的飞书自动化诊断。用户在 2026-09-23 本次请求中明确陈述：已经跑通管培带教和营销战役，希望向其他部门迁移。本包接受这一项目背景；没有本次可定位的逐环运行记录，不进一步声称具体版本、全量覆盖或净收益。

以下机制提取自用户提供的 `路觅AI自动化诊断-v2.6.2.zip` 内 `references/case-patterns.md` 与 `references/meta-scenarios.md`，本次审查输入 SHA-256：`1105b244eda93d68e1606cfa4a4f867c4921bbb48d108b059a33550aa829f6b0`。原包说明材料含历史局部实现、候选和回溯示例。这里只把它们作为可迁移机制线索，不推断公司当前业务系统状态。

不随包分发私人知识库、内部原始记录、员工/学员资料或目标系统标识。需要核实某条经验的运行成熟度时，向获准材料取证；未核实就标机制候选。

## P1 带教的知识复用与责任保留

来源定位：原包 `case-patterns.md`“一、管培带教”。

- 问题机制：重复问题分散，导师纠错难复用；学员有学习目标，不能把答案生成等同于培养完成。
- 可复用链：适用知识检索 → 提示/反馈 → 导师纠正实际交付内容 → 候选知识审定 → 在后续答疑调用。
- 适用前提：有权审定者、可追溯的问题/回答/版本、知识使用边界；学习目标明确。
- 必须适配：何时先答后审、何时先审后答；哪些任务只能启发不能代做；何种资料仅归位不重写。
- 失效信号：AI 替学员完成要训练的判断、审核对象与实际送达内容不一致、候选变成正式规则。
- 最小验证：给一条需导师纠正的问题，检查纠正绑定原回答、引用侧采用正确版本、学习边界仍成立。仅检查这些机制，不据此证明整个带教系统。

## P2 营销的模板启动与分项交付

来源定位：原包 `case-patterns.md`“二、营销战役”。

- 问题机制：跨角色输入、重复建项和物料交接；流程完整不自动带来营销判断质量。
- 可复用链：明确角色输入 → 模板初始化 → 单项条件齐全可推进 → 整场对独立应交清单查漏 → 版本化复核与交接。
- 适用前提：应交清单独立于已建记录，有权角色作策略/终审决定，来源和业务对象可唯一绑定。
- 必须适配：输入岗位、成果类型、对象关联方式、现行审批与真实交接条件；不复制旧表数、任务数和卡片外观。
- 失效信号：建了记录就记成果完成；只查已建任务所以漏掉应交物；旧批准批准新内容；事实已写入却因通知失败整链重放。
- 最小验证：故意缺一项应交物、修改已批版本、制造通知失败，检查能否识别及只恢复未完成部分。业务收益需另外观察。

## P3 将两类实践迁移到新部门

抽掉部门名之后检验“同一损耗原因、前提是否成立、责任是否一致、错误是否可发现、恢复代价是否相近”。只有这些相近才复用相应机制，其余重新设计。管培的学习约束不能套在行政统计上，营销的整场交付清单也不强加给只读查询。

没有匹配案例时按机制库和业务事实推导。新经验先形成当前方案中的假设或观察；未经明确维护授权，不修改共享 Skill 或个人长期知识。
