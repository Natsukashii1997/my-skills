# U 型诊断、元认知与选路

## 问：锁定结果与边界

一句问题定义应含工作对象、现状差距、合格结果和有效范围。目标是业务结果，例如“在规定时点形成可复算的结算草稿”，不是“建一个 Agent”。时间、预算、维护人、资料边界和不可改变的责任可能决定路线，应在相关判断前核实。

全面以有效范围为边界。扫描原始目标、业务生命周期、角色交接和异常，登记发现的 W；不把“全面”解释成扩展到全公司，也不把所有环节都改造。

## 挖：事实与机制

把来源事实和解释分开。正常样本说明主路径，失败/例外样本说明机制边界；没有样本时保留假设，不伪造统计。关键材料标来源、时间或版本、适用范围、冲突及可信限制。

常见竞争解释：

| 表象 | 需要区分的机制 | 有区分力的证据 |
|---|---|---|
| 反复问同一问题 | 找不到 / 看不懂 / 无权看 / 来源冲突 / 需要例外裁决 | 最近问题、可用资料、人工回答实际在做什么 |
| 交付慢、总催人 | 输入不齐 / 无人认领 / 处理产能 / 有权决定未作 / 反复返工 | 关键时点、等待原因、责任及退回记录 |
| 数字不一致 | 粒度/口径不同 / 传输漏项 / 计算错误 / 展示过期 | 同一对象从来源到结果的可追溯样本 |
| 内容产出慢 | 找素材 / 重复加工 / 判断要求不清 / 目标变化 | 一次制作及修改过程、修改原因 |
| 想让 AI 自动决策 | 可规则化筛选 / 不确定判断 / 需要承担责任的取舍 | 硬标准、实际裁决理由、判错后果 |

不要停在“沟通不足”“数字化不足”。每个主要判断至少解释：某条件如何造成某损耗，已有证据支持哪一段，还有什么解释未排除。

## 破：干预与反证

判断突破口时同时看对结果的影响、可干预性、前后依赖、错误后果和采用成本。某个大问题可能暂不可干预，需给现实替代动作。几个 W 的瓶颈不同，可以分别选路。

记录最小因果论证：

`现象与证据 → 候选原因及反例 → 当前主判断（含把握边界）→ 干预动作 → 预期中间变化 → 业务结果 → 推翻/调整信号`

避免把结果目标当手段：多提醒不能增加实际产能；建知识库不能替代口径裁决；生成更多初稿不能解决目标不断改变。若瓶颈主要是这些，自动化只做信息或辅助部分，明确需要谁作非技术决定。

## 立：选出适配路径

对会改变投入或风险的方案比较以下维度，不做无数据的综合评分：

| 路线 | 解决哪个原因 | 成立条件与已有证据 | 效果及限制 | 建设/复核/维护/采用代价 | 风险与恢复 | 什么条件改选 |
|---|---|---|---|---|---|---|
| 现状或流程简化基线 | 具体机制 | 有据或待核 | 保留何种损耗 | 基线未知就给采样计划 | 现有兜底 | 可观察信号 |
| 推荐路线 | 同上 | 同上 | 同上 | 区间及假设，不编造报价 | 同上 | 同上 |
| 最有力的替代 | 只列有现实竞争力的方案 | 同上 | 同上 | 同上 | 同上 | 同上 |

先检验可行性及责任硬边界，再比较净收益。不得因为 AI 更先进就优先，也不因为现状不完美就一定新建。

首期挑一个能验证主机制、形成合格结果、可恢复且资源可承受的闭环；不是随机选最小功能。如果一个只读检验就能推翻昂贵方案，先建议该检验。用户已明确首期时，沿该边界补齐依赖与失败路径，不强迫重新选择。

基准情景写输入正常时如何产生收益；不利情景写输入差、采用低、连接失败或需求变化时怎样降级。高影响方案明确停止/缩小条件及责任人；普通低影响诊断不写冗长情景报告。

## 元认知：贯穿全程的检查

- **证据校准**：来源是否支持这个结论，还是只证明某例存在？反证是什么？是否把“没读到”当“没有”？
- **边界校准**：是否遗漏原始目标，或把局部成功外推到整个部门？是否混淆当前事实、目标设计和已运行？
- **机制校准**：解决的是损耗原因还是仅增加记录？去掉某组件结果还能改善吗？
- **迁移校准**：新场景有哪些关键不同？旧机制的前提失效了吗？
- **责任校准**：有没有把决定、资源承诺或学员应练判断交给不该承担的人/模型？
- **经济性校准**：节省的人工是否被复核、异常、维护、培训和新录入抵消？低频高后果可优先防错，不以频次简单筛掉。
- **完备性校准**：是否有取消、重复、版本修改、无权限、部分成功或未知结果没有去向？只检查与本场景有关的失败方式。

缺证据时给条件结论和有限验证，不为写“一句话本质”制造确定性。
