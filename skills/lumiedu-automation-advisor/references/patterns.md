# 元场景机制库：识别、适配、组合

按触发、输入、产出、规则稳定性和责任边界匹配，不按部门名称套模板。以下是可组合的经验模式，不是互斥穷尽分类，也不是已在当前租户验证的产品配方。成熟度必须另查。

每个选中的模式留下适配记录：`W / 现行证据 / 模式 / 必要前提 / 新场景差异 / 保留部分 / 调整部分 / 不采用部分 / 失效信号 / 验证`。关键前提未知时给条件路径。

## S1 有依据的问答与查询

- **信号与输入**：反复问已有规则或状态；输入为问题、提问者身份、上下文和权威来源。
- **机制**：识别问题与权限范围 → 检索适用版本 → 核对依据与冲突 → 给有来源的回答；不足或需要裁决时转有权角色。只读状态查询不强加审批或写表。
- **前提**：来源可信、可更新，接收者可看；能区分检索问题与专业裁决。
- **不适用/调整**：资料不存在先补证据；答案依赖实时计算组合 S7；学习场景只给提示和反馈；保密资料必须在展示前过滤，不能检索后发到无权群。
- **验证**：用正常、过期、冲突、无权限、无答案样本检查正确性、可溯源性与转人；看实际问题解决率和专家负担，不以回答量替代。

## S2 汇总与报告

- **输入**：固定或按需触发、明确用途、来源清单、统计范围/口径/截止点。
- **机制**：读取并核对覆盖 → 确定性清洗计算 → 独立复算 → 可选 AI 解释 → 结果送达并记录来源和截止点。
- **前提**：来源可取得、明细能复算，接收者确有使用动作。
- **不适用/调整**：读不全标部分覆盖，不把缺失当零；口径争议先由有权角色定；已有报表足够时只改善入口或解读，不重建。
- **验证**：从总数下钻到源明细重算；迟到数据、跨时区、重复、修改和读取失败均有规则。价值看用于何种判断及准备总成本。

## S3 监测、提醒与处置

- **输入**：时间/变更事件、对象状态、可行动的阈值、能处置的责任角色。
- **机制**：完整扫描 → 规则筛选 → 去重/抑制 → 定向告知 → 处置记录 → 关闭或超时升级。
- **前提**：异常定义可判断，接收者有动作和时间，扫描完整性可见。
- **不适用/调整**：没有处置能力时先解决责任或产能；人工补录的时延必须计入；只需定时汇总时用 S2。
- **验证**：漏报/误报、未扫描、已关闭仍提醒、无人认领、延迟处置；未扫描不得记“无异常”，失败区间不推进完成标记。

## S4 明确指令的受控执行

- **输入**：获准指令、对象唯一标识、参数、执行身份、允许动作与完成标准。
- **机制**：解析参数 → 校验对象/权限/版本/前提 → 必要的人确认 → 执行动作 → 回读 → 返回可见结果。
- **前提**：动作范围明确，重复和修改可区分，执行后能判断结果。
- **不适用/调整**：含资源承诺或有权人决定时拆开“准备”和“批准”；结构化表单足够时无需 AI 解析；无可靠自动接口就生成待应用内容。
- **验证**：正常、参数缺失、旧版本、越权、重复、部分成功、结果未知。初始化任务不等于任务已完成。

## S5 抽取、录入与同步

- **输入**：消息/文件/源系统事件、原文、目标对象、字段映射和权威方向。
- **机制**：抽取候选 → 唯一匹配 → 校验来源、字段含义、权限、版本与内容 → **通过才写；歧义/冲突先转人** → 回读目标 → 记录独立正确性证据。
- **前提**：能绑定唯一对象，知道缺字段是“不修改”还是明确清空，防止覆盖新版本。
- **不适用/调整**：名字相同不证明同一人；双向同步需先定冲突权威；财务/人事等高后果字段可仅生成候选待确认。写入未知先查询核实，不能重写试错。
- **验证**：同名对象、缺字段、重复事件、乱序、并发修改、源更正、部分成功；准确率按字段/风险分层看，关键错误不能被平均准确率掩盖。

## S6 跨角色交接与状态流转

- **输入**：已有业务对象及关联键、完成条件、接手角色、允许的状态变化。
- **机制**：当前成果达到交接条件 → 分派/认领 → 接手处理 → 复核或退回 → 交付；等待、取消、重开和升级分别有规则。
- **前提**：交接物可判断，责任有权且有能力承担；状态表达真实业务事实。
- **不适用/调整**：本质是专业产能不足时只缩短交接不能消除瓶颈；可直接处理的请求先看 S1/S4/S7。没有价值的审批优先建议取消，不自动新增。
- **验证**：交接双方知道收到什么；无人接手、退回版本、暂停计时、超时、取消、完成后新请求。看端到端周期及返工，不只看派单速度。

## S7 数据或内容加工

- **输入**：合格产物样本、素材/数据、使用场景与评价标准。
- **机制**：核对输入 → 规则负责计算/转换，AI 负责有依据的语义加工 → 独立校验 → 按风险定稿 → 交付并留版本。
- **前提**：标准可操作，依据足够，复核成本可接受。
- **不适用/调整**：目标反复变先改需求确认机制；数值用确定性计算；缺少事实的文案标空缺，不编造；AI 不替代应由学员完成的推理。
- **验证**：数据独立复算，内容按事实、适用性和可用性检验；比较修改轮次、返工原因、含复核的总工时。不能让同一模型“自评通过”充当唯一质量证据。

## S8 辅助判断、分配与排期

- **输入**：待判对象、硬条件、软判断标准、资源约束、决策责任与代价。
- **机制**：规则检查硬约束 → AI 整理证据/候选/不确定性 → 有权人作需担责的决定 → 执行决定并反馈。
- **前提**：能识别不可委托部分，有独立质量评价或有权复核人。
- **不适用/调整**：规则化筛选不等于最终批准；资源冲突、薪酬、付款、录用等不得从模型分数自动推出承诺。纯确定性的排程可不加 AI，但仍保留授权边界。
- **验证**：硬约束是否违反、边界样本、分歧如何处理、责任人能否解释；“与历史决定一致”本身不能证明历史决定正确。

## S9 候选知识到可用知识

- **输入**：经过事实核对的经验、纠错或规则及来源，预期调用位置。
- **机制**：提炼候选 → 查重/冲突 → 有权审定 → 发布适用范围/版本/失效条件 → 调用 → 反馈与撤回。
- **前提**：有审定责任、更新维护和实际使用入口。
- **不适用/调整**：不把每次对话自动沉淀；低复用价值可不建库；个人知识不能默认转企业共享。存量资料可只归位，不强制 AI 重写。
- **验证**：候选不会误作正式依据；权限、更新后下游、撤回和冲突均有效。看是否改善后续工作，不以文档数证明价值。

## 组合与遗漏检查

模式的连接依靠对象关系、输入输出和事件条件，不按 S 编号串成必经链。逐 W 检查触发、来源、处理、责任、交付、证据、异常；不需要的环节写清原因即可。S1 可以直接答复，S2 可以只读汇总，S4 可以纯规则执行，S9 可以完全不出现。

历史机制线索见 [公司案例与证据边界](references-notes.md)。使用前比较新场景条件，不能因为“带教做过”“营销用过”就复制表、机器人或审批方式。
