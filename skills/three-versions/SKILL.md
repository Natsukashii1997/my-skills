# 三版预览

常浩挑方案靠看，不靠读描述：三版要真画出来、一键切换、手机上也能打开看。定新的视觉方向时都要这样做（全局第 9 节），产品界面只做电脑版（全局第 10 节）。这个 skill 把这些固定成一套流程和一个外壳模板，自查由脚本跑，不靠记得。

## 第 1 步：吃透现状

- 读要改的页面现在的代码和样子（能打开就截一张 1440 的图），常浩给的截图和参考，项目的 `docs/DECIDED.md`。
- 读设计规范：基础规范 `~/Documents/ChatGPT/个人/work/ui-system/docs/design-spec/DESIGN.md`（换任何风格都成立的对齐、间距、颜色规则），和项目自己的版式规范（项目 AGENTS.md 导航表里写着在哪，如驿窗的 `docs/design/卡片版式规范.md`）。三版都守这两份；某一版的思路要违反其中一条，在那版的「放弃」里写明违反哪条、为什么。
- 用真实的尺寸、素材和文案画；数据用项目里真实或接近真实的数据（真实长度的名字、金额、超长标签），不写「示例文字」。
- 登记表里定过的东西（颜色、字体、导航、标题写法、组件样子），三版都原样保留，连尺寸、字号和装饰（加圆点、加描边）也不加不改。只有常浩这一轮点名要改的那一项可以动；某一版的思路必须碰到别的已定内容时，先单独发「改动确认」（全局第 15 节），问完再画。

**做完的标志**：说得出这页现在的问题在哪、哪些是已定不能动的、规范里哪几条管这次要画的东西。

## 第 2 步：定三条思路

先写下三版各自的名字、一句话思路、得到什么、放弃什么，再动手画。

- 三版差在**思路和取舍**：信息怎么分层、先看什么、布局结构、交互方式。只换颜色、圆角、字号的不算三版。
- 常浩给了方向（如「更协调更有层次」），三版都朝这个方向，各走一条不同的路。
- 选一版作推荐，写一句理由。

**做完的标志**：三句「得到 / 放弃」互相换不过去；能一句话说出推荐哪版、为什么。

## 第 3 步：定风格

- 已有项目：沿用项目现有的令牌、字体和组件（CSS 变量、DECIDED 里的风格项），三版同一套。
- 新项目或常浩没定过：用 `ui-styles`，没点名就用细线；拿不准把两三种候选给他挑。
- 常浩要比的就是风格时，三版可以各用一种，在切换按钮的小字里写明风格名。

## 第 4 步：套外壳，画三版

1. 加载 `artifact-design` skill（发布 Artifact 的页面规范）。
2. 复制 [assets/shell.html](assets/shell.html) 到项目的方案目录（如 `<项目>/方案/<页面>-三版.html`），换掉所有 `{{…}}`：标题、一句话说明、三个切换按钮（名字 + 一句话思路）、窗口栏路径、底部三段取舍（推荐那版保留 `class="rec"`）。
3. 三版的产品界面分别画进 `#va`、`#vb`、`#vc`：
   - 各版的样式只写在自己的 `#va …`、`#vb …`、`#vc …` 选择器下，互不串。
   - 按 1440×900 设计，布局用流式宽度（`minmax(0,1fr)`、百分比），1280 宽时仍完整不挤；不给子元素写死 1440。
   - 画板里只画电脑版：不写 `@media (max-width…)`、不做汉堡菜单、底部标签栏、抽屉导航。
   - 画板比 900 高时，在那块 `.board` 上写 `data-h="1200"` 这样的实际高度。
   - 按钮、输入框写 `font: inherit`；图标用同一套 SVG，不拿箭头、符号、emoji 字符当图标。
   - 画已有产品时，照真实组件的结构画：行的列宽、间隔、标签和按钮的位置抄项目代码，不另写一套排法。每版里新加的行或组件，旁边并排放一个已有的同类（如新加一种列表行，紧挨着画一条现有的同类行），让位置和样式对不对一眼看得出（DESIGN.md A-08、D-10）。
   - 改了某个元素放在哪（换了列、换了行、挪进或挪出某一块），在切换按钮的说明或底部取舍里单列一句「这一处放在哪」，不和配色、文案等别的改动混在一起写。
4. 外壳的切换（按钮、键盘 1/2/3、`#a` `#b` `#c` 直达）、缩放、「按 100% 查看」、只看画板模式（`#bare-a`）都由模板自带，不改。

## 第 5 步：自查（每次发布前自动跑）

```bash
node ~/.claude/skills/three-versions/scripts/check.mjs <三版页面.html> --out "<项目证据目录>/three-versions-<日期>"
# Codex 用 ~/.agents/skills/three-versions/scripts/check.mjs
```

脚本一次查完：模板占位都换掉了、三块画板都有内容；三版产品界面各按 `#bare-x` 单独打开，借 `ui-preflight` 的脚本在 1280、1440 查横向溢出、同列对齐、截断折行、0 高容器、窄栏、默认字体、字符图标、对比度；外壳每版在 1440 和 390 宽截整页图，查横向溢出和页面报错。证据目录用项目约定的持久目录，不放 /tmp。

然后自己看图，至少两轮：

1. 打开每版 1280 和 1440 的截图（ui-preflight 报告目录）和外壳 390 的截图，对照第 1 步的现状图和常浩的参考，找不对齐、挤、空、层次乱、和已定内容不一致的地方；
2. 改完重跑脚本，再看一轮。

**做完的标志**：脚本退出码 0，`three-versions-check.md` 全是「通过」；两轮看图都做了，第二轮没有新问题。

## 第 6 步：发布，给一个链接

- 用 Artifact 工具发布这一个 HTML 文件（`icon` 用 `layout`）。之后改版用同一个文件路径重发，链接不变；不为每版单发链接，不发截图或本地路径代替链接。
- 回复常浩：链接；三版各一句「得到 / 放弃」；推荐哪版和理由；自查结果写「替身通过（无头 Chrome，1280 / 1440 / 390）」，并说明真实环境（他的浏览器、正式页面）还没验；有已定内容被碰到的，单独列出。

## 第 7 步：他选了之后

- 当轮把选定登记进项目的 `docs/DECIDED.md`：日期、定了什么、他的原话（如「选 B」）、三版页面链接、基线截图路径（选定那版的 1440 截图）。
- 他要「B 再改改」：在同一页面上改，B 的按钮小字写明改了什么，重跑第 5 步，用同一路径重发。
- 选定后做成正式页面是另一件事：照项目流程实现，交付前用 `ui-preflight`。
