# three-versions evals

每条都来自常浩 2026-11 的真实请求，项目细节换成能独立运行的材料。盲测时执行者只拿到 skill 目录（含它依赖的 ui-preflight、ui-styles）和每条的「请求」「给的材料」；不真的发布 Artifact，把要发布的文件路径和要回复常浩的话写出来代替。

## E1 已有页面出三版（最常见）

- **请求**：「这一页的排列乱七八糟的，帮我优化。给我3版，更协调更有层次的板式」
- **给的材料**：一个待办列表页面 `todo.html`（1440 宽，左侧导航 + 待办列表，每条有用户名、阶段、待办内容、到期时间票）；项目 `docs/DECIDED.md` 里登记了：主色黄只做底色、时间票固定 100×38、阶段六种颜色。
- **期望行为**：读现状和 DECIDED；定三条布局思路不同的方案（不是换颜色）；三版都保留时间票、阶段颜色和主色用法；用 `assets/shell.html` 做成一个页面；跑 `scripts/check.mjs` 并通过；看截图；回复里给一个链接位、三版取舍、推荐和理由、「替身通过」的说明。
- **判定标准**（全部满足才算过）：
  1. 产出一个 HTML 文件，里面三版可切换（`#va` `#vb` `#vc` 都有内容），没有剩下 `{{…}}`；
  2. 三版的布局结构不同（不只是颜色、圆角、字号不同），每版写了得到 / 放弃；
  3. DECIDED 里的三项在三版里都没变；
  4. 跑了 `check.mjs`，结果全部通过（附结果表）；
  5. 回复里自查结论写成「替身通过」，并说明真实环境没验。
- **不该出现**：三个链接或三个文件；画板里写窄屏断点或手机布局；自查只说「看过了没问题」没跑脚本。

## E2 新功能定视觉方向

- **请求**：「做一个班主任的课表导出页面，先给我看看几种方向」
- **给的材料**：无项目风格（新页面）；需求：选日期范围、选学员、预览课表、导出 PDF / 图片。
- **期望行为**：没有项目风格，用 ui-styles（没点名用细线，或给出所选风格和一句理由）；三版思路不同（如：先选后看 / 边选边看 / 日历为主）；产品界面按 1440 电脑版画；其余同 E1。
- **判定标准**（全部满足才算过）：
  1. 说明了用的风格和原因，来自 ui-styles 的定稿风格；
  2. 三版的交互或信息组织思路不同，并给出推荐；
  3. 画板里是电脑版布局，1280 宽时完整（check.mjs 的 1280 结果通过）；
  4. 只给一个页面、一个发布位。
- **不该出现**：自创一种不在 ui-styles 里的风格；做成手机竖屏界面。

## E3 飞书卡片（不该用本 skill）

- **请求**：「把每周进度做成飞书卡片的形式，出三版」
- **给的材料**：无。
- **期望行为**：认出这是飞书卡片样式，不做网页三版；说明按常浩 11-25 的要求，卡片三版要做成真卡片私发他飞书确认，转去拼卡片 JSON。
- **判定标准**（全部满足才算过）：
  1. 没有产出三版预览网页、没有发布 Artifact；
  2. 说明卡片要用真卡片私发确认。
- **不该出现**：用 shell.html 画卡片的网页模拟。

## E4 已有卡片加一种新行（画已有产品，测位置）

- **请求**：「等待处理卡里要加一种『积压事项』行：等了超过一天还没回的事，给我3版看看怎么摆」
- **给的材料**：项目目录：`card.html`（360 宽的深色卡片，两条现有的 ASK、REPLY 行：图标列 18px、间隔 12px，第二行是「类型签 + 小字」）、`AGENTS.md`（导航表指向版式规范）、`docs/卡片版式规范.md`（类型签只在标题下面一行的起点，不进图标列）、`docs/DECIDED.md`（两条对齐线、签的颜色和尺寸、卡片宽和底色）。来自驿窗 2026-11-28：积压行的类型签被画进图标列，错先出在预览里。
- **期望行为**：读基础设计规范 DESIGN.md 和项目版式规范；三版的积压行都照现有行的结构画，旁边并排留着现有的 ASK / REPLY 行；三版差在思路（如单独一块 / 混排加标记 / 折叠），不差在把签挪进图标列；说明里单列一句「积压行的签（或标记）放在哪」；其余同 E1。
- **判定标准**（全部满足才算过）：
  1. 产出一个 HTML 文件，三版可切换，没有剩下 `{{…}}`；
  2. 每版的卡片里，新的积压行和至少一条现有的 ASK 或 REPLY 行画在一起；
  3. 每版积压行的第一列只放图标（或空着），类型签、标记如果有，都在标题下面一行的起点，和现有行的签左边对齐；第一列宽和间隔与现有行一样（18px、12px）；
  4. 说明或取舍里有单独一句讲积压行的签或标记放在哪；
  5. 回复里写明读了 DESIGN.md 和项目版式规范，DECIDED 里的几项三版都没变；跑了 `check.mjs` 并通过。
- **不该出现**：签或标记放进图标列；积压行另写一套列宽；只画积压行、不画现有行。
