# Hairline 细线

一句话：**像精心打磨的产品专题页，不像文档。** 用细线和留白分层，用超大字号和编号建立节奏，用一种识别色串起一条主线，用真实业务过程的演示代替装饰动效。

参考实现：[assets/reference.html](assets/reference.html)（「AI 落地三步法」第八版，2026-11-05；截图已换成灰色占位）。写新页面前先通读它的 CSS 和一个演示的 JS，组件照着用，不要凭印象重写。

## 一、动手前先定三件事

1. **主线是什么，有几段。** 页面必须有一条读者一眼能说出来的主线（例如「三个环节 · 三套提示词 · 三份产出」）。首屏就把主线画出来，后面每章一一对应。用户给了几段就是几段，不拆碎、不另加框架、原则清单、术语表之类的东西。
2. **每段给谁看、要演示什么过程。** 每段最多一个演示，演示的必须是一个真实发生的过程：一次对话、一句话被系统处理成卡片、一天的时间推进、一份数据流过几个环节。找不到值得演示的过程，就不做演示。
3. **哪些内容会重复。** 同一层意思全页只说一次。常见重复有三种：首屏和章节头都写「读者 / 输入 / 产出」，章末要点复述正文，收尾又做一张总表。动手前先删掉。

## 二、设计令牌（照抄，不即兴调色）

```css
:root{
  --bg:#F3F4F6; --surface:#FFFFFF; --ink:#101318; --ink2:#434A55; --ink3:#5F6672; --rule:#D7DAE0; --rule2:#E6E8EC;
  --dark:#15181D; --dark2:#1D2128; --dark3:#262B33; --darkrule:#2E343D; --dink:#ECEEF2; --dink2:#A7AEBA; --dink3:#8D95A2;
  --s1:#DD5129; --s1t:#FBE8E1; --s1d:#AE3714;   /* 朱红：主线第 1 段 */
  --s2:#2D53D2; --s2t:#E6ECFB; --s2d:#1D3BA3;   /* 钴蓝：第 2 段 */
  --s3:#0A8470; --s3t:#DBF0EA; --s3d:#05604F;   /* 青绿：第 3 段 */
  --c:var(--ink); --ct:var(--rule2); --cd:var(--ink);   /* 当前段的 主色 / 浅底 / 深色字 */
  --ease:cubic-bezier(.22,.7,.2,1);
  --w:1240px; --g:40px;
}
.s1{--c:var(--s1);--ct:var(--s1t);--cd:var(--s1d)}  /* .s2 .s3 同理；组件一律用 --c/--ct/--cd */
```

- 识别色只有三种用法：**主色**（编号、顶线、按钮、当前态）、**浅底**（标签、占位符、高亮块）、**深色字**（浅底上的文字、小号彩色字）。小号文字不用主色，用深色版。
- 主线超过 3 段时，再加的颜色要同等饱和度、明显不同色相，并用同样的三级派生。
- 只做浅色一套，这是有意为之。`body` 写死 `background:#F3F4F6`，颜色全部明确写出。
- 深色只出现在两处：演示带和收尾的「下一步」条。深色区里的文字用 `--dink*`。
- 辅助小字最浅用 `#5F6672`（在 #F3F4F6 上对比度约 5.5:1），不能再浅。

## 三、字体

```html
<link rel="stylesheet" href="https://fonts.googleapis.com/css2?family=Archivo:wght@500;700;800&family=JetBrains+Mono:wght@400;500;700&family=Noto+Sans+SC:wght@400;500;700;900&display=swap">
```

| 角色 | 字体 | 用法 |
|---|---|---|
| 正文、标题 | Noto Sans SC | 正文 16px / 1.75；标题 900 粗、`letter-spacing:-.015em`；首屏 h1 `clamp(42px,6.4vw,86px)`，同一标题里用一段 400 细体灰字（#7A818C）做对比 |
| 数字、编号 | Archivo 800 | 章节大编号 `clamp(110px,15vw,200px)`、`line-height:.78`、`letter-spacing:-.05em`；数字条 28–40px |
| 标签、代码、元信息 | JetBrains Mono | 11–12px，大写，`letter-spacing:.08em`；行号、时间、文件路径、状态码 |

全页开 `font-variant-numeric:tabular-nums`。

## 四、版式构件

每个构件在参考实现里都有完整的 HTML 和 CSS，类名照抄。

| 构件 | 类名 | 样子 | 什么时候用 |
|---|---|---|---|
| 顶栏 | `.top` | 56px 高，半透明冷灰加毛玻璃，左边是三色竖条加品牌字，右边是带编号的锚点导航 | 每页都要 |
| 首屏 | `.hero` | 40px 细网格底，往下渐隐；左边是超大标题和副标题，右边是 2px 黑顶线的引用块 | 每页都要 |
| 主线骨架 | `.spine` / `.sp-col` | N 列白卡，4px 色顶线，内部用细线分格，列间是黑色箭头；悬停时上移 3px、描边变主色 | 首屏下方，把主线画出来 |
| 核心思路 | `.idea` | 白底整带；左边是 h2，右边三列，顶上 2px 黑线、列间 1px 细线；每条配一个小视觉（标签、对照、链条） | 主线背后的逻辑，最多 3 条 |
| 章节头 | `.st-head` | 超大 Archivo 色编号配粗黑标题，标题里的关键词用主色，底部 1px 黑线；`.rev` 让编号移到右边 | 每段一章，左右交替 |
| 区块标题 | `.blk-k` + `.bk-t` + `.bk-d` | 16px 色短线，接四字标签（识别色），竖线分隔，再接一句说明（黑色），整行 21px、900 字重 | 章内分块。全页同级标题都用这一个构件，格式一律是「四字标签｜说明」 |
| 现状 → 目标 | `.goal` / `.g-row` | 两行同字号：「现状」灰色等宽小标签，写表层问题；中间是识别色「↓ 所以」；「目标」用识别色标签，文字加粗，左侧加 3px 竖线，写深层目标 | 一步要解决什么。用标签、颜色和字重表达由表及里，不靠字号大小 |
| 输入 → 产出 | `.flow3` | 三格，最后一格是主色实底白字 | 说明这一步的对象、输入、产出，每章一处 |
| 方法三行 | `.method` / `.m-row` | 左侧 190px 标签栏：大号 A/B/C、四字标题、一行说明，滚动时 sticky 跟随；右侧依次放三块：判断三列 `.jdg`（风险用浅底小标签）、决策对照 `.dec-r`（判断 → 写法 → 段落按钮 `.seg-tag`，点击后跳到对应段落并高亮）、公式 `.fx`（识别色块用 × 连接，后面接一句“缺了哪块会怎样”） | 讲清“为什么这样做”，放在“怎么做”之前 |
| 批注视图 | `.rv` / `.seg` | 代码评审样式：左边是带行号的等宽正文，按段落拆分，`{{占位}}` 用浅底高亮，XML 标签行用浅灰小字；右边 340px 灰底批注，顶部写段落名，下面一句作用；关键段落左侧加主色边线，并打「最关键的一句」；顶部放复制按钮（复制原文） | 提示词、配置、规则这类需要逐段解释的文本 |
| 报告范本 | `.rep` | 封面卡加报告目录。封面 `.rc` 依次放：原页缩略图、标题、主标语、日期、对象、体量、打开原页。目录 `.toc` 按逻辑分 3–4 段，段头写段名、一句作用和来源小标签；每章一行，依次是编号、章节名、核心句。可选目录顶部数字条；`.rev` 让封面换到右边 | 展示一份真实产出。用本页构件重画它的结构，原图只当封面缩略图 |
| 数字条 | `.nums` | 顶上 2px 黑线，5 列 Archivo 大数字配小字口径，重点数字用主色并带比例条 | 关键数据；每个数字都要写口径 |
| 窄链桥 | `.bridge` | 白底窄带，4 格横向链条，人工步骤用虚线框 | 两段之间有一个不由 AI 完成的中间步骤时 |
| 演示带 | `.blk.band.dark` / `.blk.panel.dark` | 深色区：band 横跨全宽、尺度最大，panel 收在内容宽度内；里面放浅色 `.win` 应用窗口（8px 圆角、黑描边） | 每段的演示；三段要换着用，不要都一样 |
| 接力卡 | `.ch3` / `.c3` | N 张竖卡：大编号、翻译方向、对象 / 输入 / 产出小字，底部是主色实底的“交给下一步”；卡之间放箭头，人工步骤用虚线框 | 总结时把各段串起来 |
| 要素矩阵 | `.mx` | 行是要素（左列灰底），列是各段（顶部是识别色粗线），格子左侧有一道 3px 浅色边，最后一行放各段的公式；矩阵下面接一句粗体结论 | 提炼通用方法：每段在同几个问题上分别怎么填 |
| 切换示例 | `.mig` + `.sw-l` | 左边是竖排选项（选中项加粗、左侧加竖线），右边是灰底定义表 | 同一结构套到几个不同场景 |
| 前提三栏 | `.pre` | 顶部 2px 黑线；三栏之间用细线分隔，每栏依次是编号、粗体前提，以及一句灰色标签“不满足时”的调整办法 | 方法的适用条件 |
| 文件卡 | `.sk` | 仿文件头：三色小条加文件名；每行左边是等宽键名，右边是值（标签、分段流程） | 展示一份配置、skill 或规格的骨架 |
| 收尾 | `.next` + `.foot` | 深色条写一句下一步，下面两栏放来源和免责说明 | 每页都要 |

### 版式节奏

- 区块之间用留白（区块 64px，章节 112–120px）和 1px 细线分隔。**不用卡片阴影，不用大圆角**：圆角只有应用窗口用 8px，按钮 2–3px。
- 各章区块顺序可以一致，但构图必须变化：演示的位置（前、中、后）、尺度（band 或 panel）、章节头方向（正或 `.rev`）至少换两样。三章完全同构就会像文档。
- 段落最多 3 行；能用构件表达的不写成段落。白底整带（`.idea`、`.bridge`、总结 `.sum`）和灰底交替出现，形成节奏。

### 常浩定下的四条规则（以后每页都要守住）

1. **同级标题格式完全一致。** 字体、字号、色短线、间距都要一样，命名也要对齐：同组标签字数相同（例如全部四个字），说明句的句式相近、长度相近。
2. **有逻辑层级的信息，要用视觉区分开。** 比如一浅一深、一因一果，用标签、颜色、字重、符号区分，不靠字号大小。写之前先想清楚两段之间是什么关系。
3. **不直接放原始截图的大图。** 风格和清晰度都和本页不协调。要用本页的构件重画它的结构，原图最多当一张封面缩略图。
4. **先讲“为什么”，再给“是什么”。** 给出模板、提示词、规则之前，先交代判断依据和设计决策；只有结论没有方法，别人无法复用。

## 五、动效规则（最重要）

**只允许三类：**
1. **业务过程演示**：对话一条条出现，系统侧的步骤逐个点亮，卡片生成后写回，时间指针前进，清单逐条打勾。
2. **交互反馈**：标签切换、悬停、复制成功、按钮按下。时长 0.15–0.3s，统一用 `--ease`。
3. **新内容进场**：`.enter`，0.42s，上移 8px 并淡入。只在演示里给新出现的元素用。

**禁止：** 流动虚线、脉冲或呼吸光圈、漂浮的小点、背景动画、滚动视差、数字滚动计数，以及任何「为了让页面动起来」的效果。静态结构图就保持静态。

**演示控制器**照搬参考实现里的 `Demo(root,cfg)`。它带来这些行为：
- `cfg.render(k,mode)` 按第 k 步画出整个画面，`total`、`delay` 定义步数和节奏，`modes` 支持 A/B 切换。
- 控件有「播放 / 暂停」「重播」「逐步 →」，模式切换放在 `.seg-sw`，右侧显示进度 `k / N`。
- 进入视口 35% 时自动播放一次；用户手动操作过就不再自动播放。
- 初始渲染第 0 步，第 0 步也要有可读内容或占位提示，不能是一片空白。
- `lock()` 遍历所有模式和所有步骤，取最大高度作为 min-height，避免播放时页面跳动。
- 开启 `prefers-reduced-motion` 时直接显示最终态，CSS 去掉全部动画和过渡。
- 演示结束出现 `.dm-end` 结论句，带一条主色竖线。
- 演示中的人名、对话、客户信息标注「示意」。

## 六、技术约束（发布为 Artifact 时）

- 文件从 `<title>` 开始，不写 `<!doctype>`、`<html>`、`<head>`、`<body>`。title 用页面名，2–4 个词。
- 外部资源只有 Google Fonts。图片压成 JPEG（每张 ≤180KB）后用 data URI 内嵌。不用 iframe、fetch、alert、print。
- 复制按钮先走 `navigator.clipboard.writeText`。失败时用临时 textarea 只放纯文本，选中后执行 `execCommand('copy')`，提示语写「已选中，请复制」。
- 可拖动的元素加 `touch-action:pan-y`，或者只让手柄可拖，不要吞掉页面滚动。
- 单列网格一律写 `minmax(0,1fr)`；400px 宽时不能横向滚动。用户默认只看电脑版，手机能读就行。

## 七、自检（交付前必须做）

1. 先包一层 `<!doctype html><html><head><meta charset="utf-8"></head><body>…</body></html>` 生成预览文件，再用无头 Chrome 截整页长图（macOS 没有 `timeout`，用 perl alarm）：
   ```bash
   perl -e 'alarm 100; exec @ARGV' "/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" --headless=new --disable-gpu --hide-scrollbars --user-data-dir=$TMP/chr --window-size=1440,14000 --virtual-time-budget=8000 --screenshot=$TMP/full.png "file://$TMP/preview.html"
   ```
   无头 Chrome 的虚拟时间不会推进 CSS 过渡，截图前在预览副本里关掉 transition。截完切片逐段看：溢出、错位、文字墙、空白演示、看不清的截图。
2. 用 `python3 -I` 加 `html.parser` 查标签是否闭合；400px 宽的情况放进宽 400 的 iframe 里测 scrollWidth。
3. 对照第一节：主线段数和用户给的一致，没有重复内容，没有被禁止的动效。
4. 修完再截一次图确认。改动较大或用户之前否决过的页面，交给另一个只拿需求、不看你思路的 agent 独立审一遍。
