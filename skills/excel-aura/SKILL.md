# Excel-Aura

目标：读表的人一眼看出层次，很快找到要看的数，看久了不累。

做法：颜色和版式都定好标准，执行时只做判断和选择，不即兴调色。判断靠下面三件事；选择靠「底线」和「默认值」。底线不能碰。默认值多数表照用，有理由就调，并在预览里写明理由。

```bash
A=~/.claude/skills/excel-aura/scripts      # Codex 用 ~/.agents/skills/excel-aura/scripts
python3 $A/aura.py list                    # 10 套配色
python3 $A/aura.py tokens S02 --colors 3   # 某套的派生色，不要自己调色
python3 $A/aura.py preview layout.json --cells 原表.xlsx --png preview.png                    # 写入前预览 + 风险检查（本地表）
python3 $A/aura.py preview layout.json --cells cells.json --info info.json --png preview.png   # 同上（飞书表回读）
python3 $A/aura.py feishu layout.json --out-dir ./aura-styles                                 # 飞书样式分片
python3 $A/aura.py xlsx layout.json in.xlsx out.xlsx                                          # 本地 Excel
python3 $A/aura.py audit out.xlsx [--before 原表.xlsx]                                          # 审查一张本地表
python3 $A/aura.py audit cells.json --info info.json [--before 原表cells.json]                # 审查一张飞书表
```

本地 xlsx 直接给文件路径：值、公式、样式、合并、隐藏行列、行高列宽都从文件里读，不用自己转 cells.json，也不用 `--info`。

## 先看这件事归不归本 skill 管

本 skill **只管表格长什么样**：配色、字体字号、对齐、数字显示格式、行高列宽、边框、合并、冻结。

不管的事：加行加列、写或改公式、改值、排序筛选、透视、图表、清洗数据。这些按 xlsx skill（本地表）或 lark-sheets（飞书表）的做法来。

- **请求只涉及数据或公式**（例如「最后加一列把两周销售额加起来」）：不走本 skill 的流程，不借机给整张表重新配色、改版式。回复里先说一句，例如：「加列、写公式不归 excel-aura 管，它只管表格长什么样；这次按 xlsx 的做法加列，原表样式不动。」新加的行列照抄相邻列的样式，不套套组色。
- **数据和样式都要改**（例如「加一列再美化一下」）：先按 xlsx 或 lark-sheets 把数据写对，再按本 skill 美化，回复里把两步分开说。
- 只有样式要改，或新建一张给人看的表：往下走。

## 一、动手前先想清楚三件事

1. **谁读，用来做什么**。查一个数、横向比较、看趋势、照着填、拿去汇报，各要不同的层次。先说出「这张表最重要的是哪几个数或哪几列」，配色就是把它们托出来，其余退后。这句话要写进给用户的回复，点名具体的数或列（如「最重要的是合计行的销售额和各线成交数」），不要只说「一眼看到总量」。
2. **这是什么表型**。按下表认，详细写法见 [references/table-types.md](references/table-types.md)。一页里有好几种时，每块各按自己的表型处理，但全页共用一个套组、颜色在全页只代表同一种意思。

   | 表型 | 一眼认法 |
   |---|---|
   | 明细清单 / 台账 | 一行一条记录，行数多、会往下加 |
   | 汇总统计 | 行是维度（业务线、月份），有小计、合计 |
   | 测算模型 | 有假设输入，公式算出结果，常是「指标｜数值」小块 |
   | 档位价目 / 方案矩阵 | 行是档位，列是几种方案或版本的价格，常有好几块上下堆叠 |
   | 交叉表 / 透视表 | 行头和列头都是维度，中间全是数 |
   | 排期 / 甘特 | 列是日期或周，格子表示进度 |
   | 看板 / KPI 卡 | 少量大数字加小表，给人扫一眼 |
   | 方案对比 | 每列一个对象（方案、竞品），每行一个比较维度 |
   | 录入模板 | 给别人填的，有可填区和说明 |
   | 长文本表 | 需求清单、FAQ、会议纪要，单元格里是句子 |

3. **新建还是美化已有表**。新建按第二节；**已有表一定按 [references/retrofit.md](references/retrofit.md) 走**：先回读备份、不插行列、先洗掉旧样式、处理旧合并、写前预览、写后核对值和公式。审查别人美化过的表，也用 retrofit.md 里的验收清单加 `audit`。

## 二、新建表的流程

1. **先把数据写对**：飞书用 lark-sheets，本地用 openpyxl / xlsx skill；数字写成数字，合计写成公式。飞书新建时先建空页，不在 `+workbook-create` 里预写内容（预写的会带上文本格式）；值和公式用 `+cells-set` 写，只写非空的连续段。
2. **定表型、套组、色数**，按第三到五节。
3. **写 layout.json**：字段见 [references/layout.md](references/layout.md)，各表型的写法片段见 table-types.md。
4. **预览**：`aura.py preview`（新建表可用 `--cells` 指向已经写好数据的 xlsx，或飞书要写的值）。自己先看一遍，要给人看的表把预览图发给用户。
5. **应用**：飞书对每个 `aura-styles/styles-NN.json` 跑 `lark-cli sheets +styles-put --url <表> --styles @./aura-styles/styles-NN.json`。lark-cli 的 `@文件` 只认当前目录下的相对路径；一次最多 100 项操作，脚本已按 70 项分片。不要先生成 xlsx 再导入飞书：导入会把行高列宽放大约 1.25–1.35 倍。
6. **核对**：本地表跑 `audit out.xlsx`，飞书表回读后跑 `audit cells.json --info info.json`，在浏览器里看一眼整页；Excel 打开查有没有 `####` 和截断。

## 三、底线（什么表都不能碰）

1. **不改值、不改公式**。只动样式、行高列宽、合并、冻结；已有表改完要用 `audit --before` 核对。为了版式要插行插列，先问用户。
2. **写入前给用户看预览**，写明套组、色数（写出具体数字，如「S02，2 色」）、改了哪些合并和尺寸、数字显示有没有变。真实业务表等用户确认再写。
3. **看得清**：深色带配白字对比度 ≥ 4.8，浅底配深字 ≥ 5（脚本已算好）；不用纯黑字，不铺纯红、纯绿大底。
4. **一页只有一个深色**。标题带、分区带、重点值都用 ① 的深色；别的颜色只出现浅色级。
5. **颜色有含义，全页一致**。一种底色只代表一种意思（例如奶油底 = 人填的假设），不能这块表示「输入」、那块又表示「双11 分组」。表头分组色和角色色撞了，让分组退回 ① 的深浅。
6. **不留旧样式**。美化已有表要先洗掉旧底色、斜体、旧边框，包括空格子；合并带不能比表格宽。

## 四、默认值（有理由就调，调了在预览里说明）

| 项目 | 默认 | 什么时候调 |
|---|---|---|
| 套组 | 拿不准用 S02；经营测算、财务、价格用 S01 | 用户点名；原表颜色有固定含义时映射过来（见第六节） |
| 色数 | 1–2 色 | 同时有「输入」和「计算」两种要区分才用 3 色；4–5 色只给并列的分组 |
| 字体字号 | Arial；标题 15、分区 11、表头 10 加粗、正文 10、注释 9 | 看板的重点大数字可到 18–24，只用在 key 格；投屏、打印整体 +1 |
| 行高（px） | 标题 52、分区 32、表头 40、正文 34、合计 36、注释 24、间隔 12 | 长清单（> 50 行）用 `density: compact`；少行卡片、测算用 `airy`；长文本让行高自动或在 `row_sizes` 里写 |
| 列宽 | 按内容估（中文 15px/字、其他 8px、加 28px），卡在列类型的上下限里 | 几块共用一列时取各块所需的最大值；要手填的列留宽；太长的换行，不无限加宽 |
| 对齐 | 表头居中；序号、日期、状态、短分类、代码居中；文本左；金额、数量、百分比右；全部垂直居中 | 档位类的行头（课时数、档位）居中；单个 KPI 居中 |
| 数字 | 同列小数位统一，千分位；金额 `#,##0` 或 `¥#,##0`；百分比 `0.0%` | 已有表默认保持原显示；业务上本来就取整的折扣可以 `0%`；编号、日期标签写成文本 |
| 斑马纹 | 正文超过 10 行才加，比表头浅两档 | 短块、交叉表、排期不加 |
| 边框 | ① 派生的极浅细线，四边都画；合计行顶部一条加粗线 | 看板、卡片可以只留底线 |
| 冻结 | 超过一屏的单块表冻结表头；宽表再冻结首列 | 一页多块上下堆叠时不冻结（冻哪行都不对） |
| 页边距 | 新建表左边 20px 空列、顶上 12px 空行；并排区块之间 24px 空列 | 已有表不插行列（`gutter: false`） |
| 合并 | 只用于标题、分区标题、多行表头 | 交叉表的行头分组可以竖向合并；数据区一律不合并 |
| 状态 | 只上文字色：完成绿、进行中黄棕、计划中蓝灰、暂停灰；风险红字加浅红底 | 不调 |

## 五、颜色怎么分配

**先数这张表有几种「要读者区分的东西」**，再分配颜色，不是先挑颜色再找地方用。常见的有：结构（标题、表头）、人填的假设、公式结果、重点结论、并列的分组、状态。

色序有固定含义：**① 主色、② 辅色（和 ① 冷暖相对）、③ 中性色、④ ① 的邻近色、⑤ ② 的邻近色**。每套最多两个色相家族加中性色，用到 5 色看起来也只有两家，不会像彩虹。

- **1 色**：只用 ①。深色带给标题、分区、重点值；浅色级给表头、斑马纹、合计。大多数清单、明细表 1 色就够了。
- **2 色**：① 管结构，② 标「人填的假设」，或标第二类区块。
- **3 色**：再加 ③ 标「公式结果」，就是参考表「藏青 + 黄底输入 + 绿底计算」的结构。公式列占了大半张表时别用：满屏绿底等于没有重点。
- **4–5 色**：只给真有 4–5 类并列对象的分组表头或并排区块。分组表头按序号取色，超过色数就循环；`input` / `calc` 不循环。
- 状态色全套共用，不算在色数里。

同屏预算：彩色底只出现在表头、输入格、计算格、合计这几处结构位置，正文大面积保持白底；正文不按类别铺多色底，类别写成文字就好，非要区分也只用 ① 的深浅。

## 七、继承原表，还是换成标准

- 用户要求继承原表风格：先继承（lark-sheets「继承原表风格」原则优先），只补原表缺的维度，例如对齐、数字格式、行高。
- 原表颜色有业务含义（例如按活动分组、红字表示底价）：保留含义，把它映射到套组色上，例如「底价」映射成 `input` 或 `target`，几个活动分组映射成 `header_groups`。不能直接丢掉含义，也不能原样保留一堆杂色。
- 用户点名某个颜色：按用户的来，其余部分仍按本标准。

## 测试与示例

`scripts/demo.py OUT_DIR` 生成一份完整的测试工作簿：总览 1 页，加 10 套各 1 页，每页内容相同、只换配色。它也是怎么写 layout.json 的完整示例。改了脚本后，用它的 layout 跑 `feishu`，和改前的产出对比。

demo 是色卡展示页，为了把 ①–⑤ 都露出来，同一页里 ② 既当「输入」又当「分组表头」。这违反底线第 5 条，真实表格不要照抄。
