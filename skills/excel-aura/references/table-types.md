# 表型手册

每种表都按同一个顺序想：**读者要做什么 → 哪些东西要托出来 → 分几层 → 用几色、颜色落在哪 → 尺寸、冻结、合并**。下面的写法都是默认做法，碰到不一样的表，按这个顺序重新想一遍，不要硬套。

一页里有几种表型时，每块按自己的表型处理，但全页共用一个套组，同一种底色在全页只代表一种意思。

---

## 1. 明细清单 / 台账

**认法**：一行一条记录（订单、报名、任务），列是字段，行数多、会往下加。
**读者要做什么**：找某一条、筛选、看状态。
**层次**：标题 → 表头 → 正文；有合计就加合计行，备注放表下注释行。
**颜色**：1 色就够。状态列用 `tags` 上文字色；正文白底，不按类别铺色。
**尺寸**：正文 34；超过 50 行用 `density: compact`（正文 28）。文本、备注列用 `text`，会换行，不无限加宽。
**冻结**：冻结到表头行；首列是名称、表又很宽时，再冻结首列。
**坑**：行数会增长，斑马纹和边框的范围要留余量，或者约定新增行后重刷一次。

```json
{"density": "compact", "freeze": {"rows": 6},
 "blocks": [{"header": "B6:J6", "body": "B7:J200", "total": "B201:J201"}],
 "tags": [{"range": "G7", "tone": "good"}]}
```

## 2. 汇总统计

**认法**：行是维度（业务线、月份、校区），列是指标，有小计、合计。
**读者要做什么**：比较各行，看总数和占比。
**层次**：表头 → 正文 → 小计 → 合计。小计用 `total`（浅底加粗），合计在最后，顶部有一条加粗线。
**颜色**：1 色。「计划 / 实际 / 差异」这类并列分组用两行表头加 `header_groups`，色数按分组数。
**尺寸**：数字列按最长数字估宽，同列小数位统一。
**坑**：小计行不要整行铺深色，深色只给标题和分区。

```json
{"blocks": [{"header": "B6:I7", "body": "B8:I15", "total": "B16:I16",
  "header_groups": [{"range": "D6:E7", "hue": 2}, {"range": "F6:G7", "hue": 3}]}],
 "merges": ["B6:B7", "C6:C7", "D6:E6", "F6:G6"]}
```

## 3. 测算模型

**认法**：有人填的假设（预算、单价、转化率），公式算出结果，常常是几个「指标｜数值」小块并排。
**读者要做什么**：改假设，看结果怎么变。
**层次**：假设（`input`）→ 中间计算（`calc`）→ 最终结果（`key`）；目标值用 `target`。
**颜色**：2–3 色。② 浅底加粗 = 可以改的假设；③ 浅底 = 公式；① 深色带 = 最终结论，只给一两格。
**尺寸**：小块之间留 24px 间隔列；行数少，可以用 `density: airy`。
**坑**：只有真正会带动计算的假设才标 `input`；逐行录入的明细数据不算。

```json
{"gap_cols": ["K"], "density": "airy",
 "blocks": [{"section": "L5:M5", "header": "L6:M6", "body": "L7:M15",
             "columns": {"L": {"type": "label"}, "M": {"type": "kpi"}}}],
 "roles": [{"range": "M7:M8", "role": "input"}, {"range": "M9", "role": "calc"}, {"range": "M15", "role": "key"}]}
```

## 4. 档位价目 / 方案矩阵

**认法**：行是档位（课时数、规格、人数），列是几种方案、版本或活动下的价格和推导值（单价、折扣、补贴）；常有好几块上下堆叠，每块档位相同、方案不同。
**读者要做什么**：按档位横向比较几种价格，确认定价有没有算对。
**层次**：分区（基准价、优惠价、某活动）→ 块表头 → 正文。档位列是行头，居中。
**颜色**：2 色最清楚。① 管结构；② 浅底加粗只标**人定的价格**（促销价、底价、某版本价），改它会带动单价和折扣；推导出来的单价、折扣、补贴保持白底。推导列占了大半张表时，不要给它们上 ③ 绿底。
**尺寸**：几块共用同一列，但同一列在各块的意思不同（D 列这块是「促销价」，那块是「课时单价」）：列宽按各块里最宽的需要来定，在页级 `columns` 写 `"max"`；对齐和格式写在各块自己的 `columns` 里。块之间用 12px 间隔行。
**冻结**：多块上下堆叠时不冻结。
**合并**：分区带只合并到表格实际的最右列；「学科 / 竞赛」这类块标题做成两行表头的上层，合并到整块宽度。
**坑**：
- 没有表头的辅助列（例如「原价单价 − 底价单价」）用 `muted` 灰字，不要让它和正式价格一样醒目；同时提醒用户补表头。
- 同一列手填和公式混着（某一格是写死的数）：不改它，在预览说明里提出来。
- 原表常按活动给表头上各种颜色：映射成 `header_groups` 时，别让分组色和 ②「输入」撞色。

```json
{"gutter": false, "gap_rows": [20, 28],
 "columns": {"A": {"type": "category", "max": "课时数"}, "D": {"type": "amount", "max": "常规课时单价"}},
 "blocks": [
   {"section": "A1:Q1", "header": "A2:J3", "body": "A4:J10"},
   {"header": "L2:Q3", "body": "L4:Q10", "columns": {"L": {"type": "category"}}},
   {"section": "A11:Q11", "header": "A12:L12", "body": "A13:L19", "columns": {"I": {"type": "percent"}}}],
 "merges": ["A2:J2", "L2:Q2"],
 "roles": [{"range": "D4:D10", "role": "input"}, {"range": "J4:J10", "role": "muted"}]}
```

## 5. 交叉表 / 透视表

**认法**：行头和列头都是维度（校区 × 月份、渠道 × 产品），中间全是同一种数。
**读者要做什么**：找交叉点，看哪里高、哪里低。
**层次**：列头、行头都上表头色，左上角那格写清两个维度（「校区 \\ 月份」）；最后一行、最后一列是合计。
**颜色**：1 色。大小用条件格式的**单色深浅**（① 的 L1 → L3）表示，不铺红绿；斑马纹不加，会和深浅打架。
**尺寸**：数据列统一宽度，看起来整齐。
**冻结**：冻结行头列和列头行。
**合并**：行头有分组时可以竖向合并，数据区不合并。

```json
{"blocks": [{"header": "B5:N5", "body": "B6:N20", "total": "B21:N21", "zebra": false}],
 "roles": [{"range": "B6:B20", "role": "hue1"}], "freeze": {"rows": 5, "cols": 2}}
```

（`hue1` 角色用 ① 的标记底，把行头列和表头连成一圈；数据区的深浅用飞书条件格式另配。）

## 6. 排期 / 甘特

**认法**：前几列是任务、负责人、状态，后面一排列是日期或周。
**读者要做什么**：看谁在什么时候做什么，哪里冲突、哪里延期。
**层次**：任务信息列正常排版；时间轴列窄（24–36px），表头写日期。
**颜色**：时间格用 ① 的 L2 / L3 填色表示进行中的区间，里程碑用 ① 深色；周末列用中性浅灰底；状态列只上文字色。超过 2 色会像调色盘。
**尺寸**：时间轴列用 `width` 直接写死；正文 `density: compact`。
**冻结**：冻结表头行和任务信息列。
**坑**：斑马纹不加；不要给每个负责人一种颜色。

## 7. 看板 / KPI 卡

**认法**：页面上方几个大数字，下面跟几张小表，给人扫一眼。
**读者要做什么**：几秒内看完核心指标和异常。
**层次**：KPI 卡（指标名小字 + 大数字）→ 分区标题 → 小表。
**颜色**：大数字用 `key`（① 深色带配白字），或白底配 ① 深色大字，全页只选一种做法；异常值用 `target`（风险红字）。
**尺寸**：KPI 格字号可到 18–24（写在 `paint` 或页级 `fonts` 里），行高 48–60；小表按各自表型。`density: airy`。
**边框**：KPI 卡只留底线或干脆不画，小表照常画浅细线。
**坑**：深色卡不超过一排；大数字写成公式引用明细，不要手抄。

## 8. 方案对比

**认法**：每列一个对象（方案 A / B / C、竞品），每行一个比较维度。
**读者要做什么**：横向比，挑一个。
**层次**：首列是维度名（`label`，左对齐）；对象列等宽、居中；维度多时按组加分区行。
**颜色**：1 色。推荐的那一列整列用 ② 的标记底（`hue2`），只标一列；优劣不铺红绿，写「✓ / —」或文字。
**冻结**：冻结首列和表头行。

## 9. 录入模板

**认法**：给别人填的表，有可填区、填写说明，常配下拉。
**读者要做什么**：照着填，不填错。
**层次**：说明（注释行或右侧说明列）→ 表头 → 可填区。
**颜色**：2 色。可填格用 `input`（② 浅底），不可改的公式格白底或 `muted`；必填项在表头用 `target` 红字标出。
**尺寸**：可填列要留够宽度（按要填的内容估，不按空格子估）；正文 34。
**坑**：下拉、校验按 lark-sheets 做；锁定区域和保护范围另外配置，本 skill 只管样式。

## 10. 长文本表

**认法**：需求清单、FAQ、会议纪要、风险登记，单元格里是一两句话以上。
**读者要做什么**：逐条读。
**层次**：短字段（编号、状态、负责人）在左，长文本列在右。
**颜色**：1 色；状态只上文字色。
**尺寸**：长文本列用 `longtext`（240–360px，自动换行）；行高不要写死成 34，按最长一格估（每行字约 18px），写进 `row_sizes`，或在飞书里设成自动。
**对齐**：长文本列在飞书里改顶部对齐更好读（`paint` 里写 `align` 只管水平方向，垂直对齐需要时另用 `+cells-set-style`）。
**坑**：不合并单元格来「排版」长文本；超长的拆到附注或文档里。

## 碰到没列出的表

按开头的顺序重新想一遍，再对照 SKILL.md 的底线检查。最常见的是把两种表型混在一块里，例如在明细清单里塞了测算格：先拆成两块，再各按各的处理。
