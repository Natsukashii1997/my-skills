# excel-aura evals

每条都来自真实请求，数据全部是虚构的占位。盲测时新开一个 agent，只给它这个 skill 的目录，以及每条的「请求」「给的材料」两栏，不给其他上下文；打分由出题以外的一方按「判定标准」做。

E2、E3 用的原表由 `python3 evals/make_fixture.py <目录>` 生成（需要 openpyxl）。这张表是一份周报：标题是红色 18 号字，正文是斜体，G4、G6 和空格子 E9 有黄色旧底色，C 列「内部备注」是隐藏的，第 10 行合计用的是 `SUM` 公式。

## E1 新建一张给老板看的汇总表

- **请求**：把下面这份各业务线 10 月线索汇总做成一张给老板看的 xlsx，做得好看一点，不要一看就那么难受、杂乱。
- **给的材料**：

  ```csv
  业务线,新增线索,有效线索,成交,销售额（元）
  A 线,252,176,20,409500
  B 线,163,111,10,223400
  C 线,86,68,8,123600
  ```

- **期望行为**：判断表型是汇总统计；先说出最重要的数是什么；用 `aura.py` 取套组色，不自己调色；写 layout.json，跑 `preview` 出预览，再用 `xlsx` 产出文件；数字写成数值，合计写成公式，比率用百分比格式；最后核对。
- **判定标准**（全部满足才算过）：
  1. 说出了表型（汇总统计）；回复里有一句明说「最重要的是……」（或同义的「重点是……」），点出具体是哪几个数或哪几列。只说「老板一眼能看到总量」这类泛指不算。
  2. 配色来自 `aura.py`（`tokens`、`preview`、`xlsx` 任意一种），没有手写的、不属于套组的色值；色数 ≤ 2，整页只有一种深色。
  3. 产出了 xlsx 和预览图（png 或 html 都算）。
  4. xlsx 里数字是数值；有合计行，而且合计是公式；如果加了有效率、成交率这类列，用的是百分比格式。
  5. 交付前做了核对：跑了 `audit`，或者回读 xlsx 检查过值、公式和格式。
- **不该出现**：纯黑字；纯红或纯绿的大面积底色；数据区里的合并单元格。

## E2 美化一张已有的表

- **请求**：这张表帮我美化一下，配色舒服点，别那么杂乱。
- **给的材料**：`10月周报-原表.xlsx`（由 make_fixture.py 生成）
- **期望行为**：按 retrofit.md 走：先另存备份，审一遍原表，列出要洗掉的旧样式；写 layout 时不插行列（`gutter: false`），并洗掉旧样式；不给隐藏列设宽；写到新文件，原文件不动；把预览和说明交给用户，等确认后再替换原表。
- **判定标准**（全部满足才算过）：
  1. 原文件没有被覆盖或改动。
  2. 给了预览（图或 html），附带说明：用了哪套配色、用了几种颜色（要写出具体数字，如「2 色」），改了哪些尺寸或合并，数字显示有没有变；并请用户确认后再替换原表。
  3. 如果产出了新文件：所有值和公式跟原表完全一致，第 10 行的合计仍然是 `SUM` 公式；斜体和旧黄底（包括空格子 E9 的）都洗掉了，**隐藏的 C 列格子也算**，C3:C8 不能还是斜体；C 列仍然是隐藏的；没有插入行或列。执行者写进输出目录的每个 xlsx 都按产出判，标了「未交付」「自检试写」的也算；回复里对文件的描述要和文件实际一致。
  4. 指出了原表的旧样式问题：斜体、残留的底色、红色大标题，至少点到两项。
- **不该出现**：改值或改公式；把隐藏列显示出来；直接覆盖原文件。

## E3 加一列汇总公式（不该用）

- **请求**：在这张表最后加一列，把每条业务线两周的销售额加起来。
- **给的材料**：`10月周报-原表.xlsx`（由 make_fixture.py 生成）
- **期望行为**：识别出这是写数据、写公式，本 skill 只管表格长什么样；说明应该按 xlsx 或 lark-sheets 的做法处理（也可以直接按那个思路做），不借这个机会给整张表重新配色、改版式。
- **判定标准**（全部满足才算过）：
  1. 下面两条满足其一：（a）回复里说明了加列、写公式不归 excel-aura 管，它只管样式，或者明确说按 xlsx / lark-sheets 的做法来处理；（b）行为上只做了加列：产出文件除新加的一列外，原有格子的值、公式和样式与原表零差异。
  2. 没有给整张表重新套配色、改版式（如果新加的那一列和原表样式对齐，可以接受）。
- **不该出现**：把这个请求当成美化任务，跑完整的 aura 流程。

**不过的条目**

- E1 第 1 条（临界）：说了表型，但没有明说「最重要的是哪几个数」，只有一句「老板一眼能看到总量」。其余 4 条打分人逐格核过，都过：色值全部来自 S02 的 1 色派生，合计是公式，没有纯黑字和数据区合并。
- E2 第 2 条：说了用 S02，但没有说用了几种颜色（layout 里是 2 色）。
- E2 第 3 条：自检试写的文件里，值、公式、隐藏列、黄底都对；但隐藏的 C3:C8 还是斜体。原因是按 retrofit.md 拆两份 layout 时，`reset` 跳过了隐藏列，而回复写的是「去掉全部斜体」，和文件不符。
- E3 第 1 条：做法是对的，只加了一列，原表样式零差异；但回复里没有说加列、写公式不归 excel-aura 管。

**这次暴露的 skill 缺口（下一版要改）**

1. 没有本地 xlsx 的回读工具：`preview`、`audit` 只认飞书 `+cells-get` 的 cells.json，执行者三条都得自己写 xlsx 转 cells.json 的脚本。
2. retrofit.md 里「拆两份 layout」是按飞书 `+styles-put` 写的，本地 xlsx 要经过中间文件跑两遍，没写。
3. 隐藏列规则前后矛盾：一边说 `reset` 不跨隐藏列，一边说旧样式必须清掉、验收时不能有斜体，却没写隐藏列里的旧样式怎么清。
4. `preview` 画不出不合并的标题向右溢出的样子，标题在预览里被截断。
5. 「只管样式，写数据按 xlsx 或 lark-sheets」只写在 description 里，正文没有，也没写不适用时要对用户说什么。

**下一轮要改的判定标准**（这一轮按原标准判，没改；已在 #61 跑第二轮之前单独提交，改后的写法见上面 E1–E3）

1. E1 第 1 条：写明要说出「最重要的是……」这句话。
2. E2 第 2 条：写明要给出颜色数。
3. E2 第 3 条：等缺口 3 定下隐藏列的清法后，再写明隐藏格子算不算；并写明标了「未交付」的自检试写文件算不算产出。
4. E3 第 1 条：同时接受行为证据（只加列、不动原样式）和口头说明，二者满足其一即可，前提是先在正文补上缺口 5。
