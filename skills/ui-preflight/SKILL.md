# 界面交付前自查

界面返工大多是常浩看正式页才发现的：表头没跟着数据右对齐、1280 宽卡头折成两行、超期数据把标签撑长、报错状态把一列挤成竖排、审核意见被挤进三个字宽的窄栏、按钮还是浏览器默认字体。这些靠肉眼扫一遍容易漏，靠量能查出来。这个 skill 分两半：**脚本量得出的交给脚本**，**量不出的按清单逐条看**。两半都做完、都写进交付说明，才算自查过。

```bash
S=~/.claude/skills/ui-preflight/scripts/ui-preflight.mjs   # Codex 用 ~/.agents/skills/ui-preflight/scripts/ui-preflight.mjs
```

## 第 1 步：准备要查的页面

- **用真实数据起一份隔离服务**：页面的问题多半只在真实数据下出现（超出 113 个工作日的标签、八位数金额）。按项目 AGENTS.md 的「隔离数据」做法起服务：正式库只读备份成副本、外部命令换成假的，不连正式端口、不写正式数据。项目没写做法的，先问常浩，不自己去读正式库。
- **列出要查的页**：改动直接涉及的页面，加上用到同一组件、同一样式的页面（第 4 步第 3 条）。
- 页面清单两种给法：
  - 项目有 `docs/design/pages.json`（起步骨架的基线截图清单）：脚本直接读它，`setup` 会起隔离服务、`ready` 等页面画完、`clock` 固定时间。默认是骨架演示数据，查真实数据时另起服务、用 `--url`。
  - 没有就用 `--url <地址> --name <名字>`，可写多次。

## 第 2 步：跑脚本

```bash
cd <项目根目录>
node $S                                            # 读 docs/design/pages.json
node $S --url 'http://127.0.0.1:5290/#/business' --name business --ready main \
        --out "$HOME/Library/Application Support/<项目>/evidence"
```

- 宽度固定 1280 和 1440（高 900），不接受更窄的宽度：产品界面只做电脑版。
- Playwright 从项目里解析；项目没装就 `npm i -D @playwright/test && npx playwright install chromium`，或用 `UI_PREFLIGHT_PLAYWRIGHT=<装了它的目录>` 借用。
- 证据目录用项目约定的持久目录（pages.json 的 `evidence` 或 `--out`），不能在 /tmp（G-01）。每次跑在里面新建 `ui-preflight-<时间>-<随机>/`，放 `report.md`、`report.json`、整页截图和标注截图。
- 收起的 `<details>` 默认全部展开再查（折叠里的表格最容易漏）；`--no-details` 关掉。
- 有意的设计用 `--ignore <选择器>` 排除，或写进 pages.json：顶层 `"preflight": { "ignore": [...] }` 管所有页，某页里写只管那页。只排除确认过的有意设计，不拿它压掉真问题。
- 项目有 `scripts/ui-baseline.mjs` 和 pages.json 时，查完会自动调项目里那份的 `compare`（不另写一份），结果并进同一张表；`--no-baseline` 关掉。
- 要登录的项目：pages.json 的 setup 按骨架约定把登录状态写到 `UI_BASELINE_STATE` 指的文件。在命令前指定一个临时文件（`UI_BASELINE_STATE=$(mktemp) node $S`），跑完自己删掉；脚本只读它，不建也不删。
- 退出码：0 全部通过；1 有不通过（含基线不一致、页面打不开）；2 用法或环境错误。

脚本查的八项（后四项对应 ui-system 的基础设计规范 `docs/design-spec/DESIGN.md`：T-07 / C-07、D-08、D-04、T-02 / K-06）：

| 检查项 | 不通过 | ⚠️ 提示（多半是有意的） |
|---|---|---|
| 横向溢出 | 整页能横向滚动；元素超出视口 | 容器内出现横向滚动条 |
| 同列对齐 | 表格某列表头和数据没对齐（数据右对齐、表头左对齐这类）；纵向排的同级元素左边缘差 1～4px | — |
| 截断与折行 | 文字被固定高 / 外层容器裁掉；标题（≤40 字）、按钮、表头、标签（≤30 字）折成两行以上；卡头、工具栏这类本该一行的横排折成两行 | 省略号截断、限行截断（line-clamp） |
| 0 高容器 | 有内容却 0 高 / 0 宽、把内容藏掉的容器；0 高的 svg、canvas、img | — |
| 正文挤成窄栏 | 8 个字以上的一段字折成 3 行以上、每行不到 4 个字宽（常见原因：文字直接放在 grid / flex 容器里，掉进了窄的那一格） | — |
| 默认字体漏出 | 按钮、输入框、下拉框的字体族或字号还是浏览器默认值，和所在容器不一样（没写 `font: inherit`） | 字体族是另定的、和所在容器不一样 |
| 字符当图标 | — | 整个元素只有一个箭头、符号或 emoji 字符（图标要出自同一套） |
| 文字对比度 | — | 小字低于 4.5、大字（≥24px，或 ≥18.66px 且加粗）低于 3；渐变、图片底上的会注明「量不准」。禁用的控件不查 |

**文字对比度目前只出提示，不影响退出码**：已经验收过的页面里也常有对比度不够的地方，先不拦。它量的是文字颜色对最近一层不透明底色，量不出铺在文字后面的兄弟元素、伪元素。

**样式清单**：报告最后一节列出每页实际用到的字号、字重、字体族（按字符数）和间距、圆角（按处数），各有几种、各是什么。只供参考，不计入通过或不通过：种类多不等于有问题，用它看有没有相近的值（12px 和 12.5px）、有没有不在这次设计层级表和刻度里的值。

## 第 3 步：读报告、处理

- **❌ 不通过**：先打开标注截图（红框带编号，对应明细表的 #）看是不是真问题。真问题就修，修完重跑，直到这一项通过。判断是误报的，写清为什么，再用 ignore 排除，并在交付说明里列出来。
- **⚠️ 提示**：逐条确认是有意的，而且用户能看到全文（悬停、展开、详情页）。确认过的写进 ignore；看不到全文的，按不通过处理。
- **文字对比度的提示不按「确认有意」处理**：对比度不够不是设计意图。这次改动涉及的文字，把颜色加深到够（彩色小字用加深后的版本，色块上的字单独定颜色）；不是这次改的、或属于已定内容的，列进交付说明留给常浩定，不写进 ignore，也不自己去改已定的颜色。注明「量不准」的打开截图人工看。
- **字符当图标的提示**：换成项目那一套图标；确实只想用一个箭头字符的，确认后写进 ignore。
- **页面没能查完**：多半是 `ready` 选择器没出现或服务没起来，修好再跑，不跳过。
- 脚本只看页面打开后的样子，用的是无头 Chromium，截图只作自查参考，不能单独当验收（G-11）。

## 第 4 步：自查清单（脚本量不出的，逐条看）

每条做完写结论：看了什么、在哪看的、结果怎样。没做的写「未做」和原因，不能空着。

1. **真实数据和极端数据各看一次**。真实数据用第 1 步的副本；极端数据至少覆盖：
   - 超期 / 逾期（天数是三位数、状态标签最长的那种）；
   - 0 值、负数、缺数据（显示「—」还是空白、图表会不会塌）；
   - 空态：一条记录都没有；报错状态：读取失败、没权限；
   - 最长文本：最长的名字、标题、备注，八位数以上的金额。
   造极端数据只在隔离副本里改，不碰正式数据。改完的数据状态再跑一次第 2 步。
2. **正式运行引擎再看一遍**。项目正式运行在 Safari、WKWebView（原生壳、macOS 上的 Tauri、「添加到程序坞」）里时，在那个引擎里也打开看：最快是 `swiftc` 写个最小 WKWebView 探针加载页面，最终在装好的真实窗口里看；动画类改动隔 2 秒截两张对比（G-33）。只在 Chromium 里看过的，交付说明写「WKWebView 未验」。
3. **同一素材、同一写法的其他出现处**。搜一遍改动用到的组件、类名、图标、样式变量，列出其他用到它的页面，逐个打开看，或加进第 2 步的页面清单。
4. **改动点相邻的状态**：悬停、键盘聚焦、展开 / 收起、选中、加载中、报错、弹窗打开，以及前后两个时间段（上个月 / 下个月、切换人员）。交互用真实点击或按键，不拿合成事件当证据（G-11）。

## 第 5 步：交付时写清

交付说明里贴：

- 自查表（报告里的总表）和报告路径；不通过项怎么处理的，排除了哪些、为什么；
- 文字对比度的提示有几条、改了哪些、留给常浩定的是哪些；
- 基线对比结果（项目有基线时）；
- 第 4 步四条的结论；
- 一句「只做了电脑版，查了 1280、1440」。

## 边界

- 只做电脑版：不加窄屏断点，不用手机宽度截图验收。脚本拒绝 1280 以下的宽度。
- 用户顺手要一张手机宽度（如 375）的截图时也一样：不在自查里截，也不绕过脚本另写一段去截、去量，标成「只作参考」「不计入结论」也不行。照常查 1280、1440，说明产品界面只做电脑版；要看手机上的效果，请他点名做手机版，那是另一件事。
- 基线截图只调项目里已复制的 `scripts/ui-baseline.mjs`，不在这里另写一份；项目还没有基线的，不在自查时顺手拍基线（拍基线要常浩验收界面的当轮做）。
- 脚本只读页面、只写证据目录；隔离服务由项目的 setup 或你按项目做法起，跑完关掉。
