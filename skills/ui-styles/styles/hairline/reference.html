思路方法提示词为什么这样写
A先行判断这一步面对的局面
判断 01

做访谈的是技术同事，没有一线经验。风险问不到点上，或者把受访者带进我们的预设。

判断 02

受访者是一线销售，不懂技术。风险对“侧边栏”“智能化”这种抽象说法无从回应。

判断 03

这次要的不是评价，是工作流。工作流梳理清楚，待办会自然浮现。

B设计决策判断 → 写法 → 对应段落
判断所以提示词要对应段落 · 点击跳到提示词
受访者需要一个具体的画面才能开口
→
交代进展和卡点；要求给受访者看的内容讲清现在的流程、做到哪一步、下一步可能做到什么程度
受访者听不懂技术语言
→
写明他们熟悉业务、不是技术人员，内容要图文并茂，能对着图来表达
我们没有一线经验，替他出题只会问出我们已知的东西
→
明说做访谈的是技术团队；不出具体业务问题，设计引导性问题，围绕工作流程展开
AI 需要依据才能判断访谈重点
→
附上会议复盘，让 AI 知道之前已经讨论出了什么
C骨架公式缺了哪一块会怎样
处境 × 对象 × 立场 → 引导式访谈

缺了“处境”，AI 只能出一份通用问卷；缺了“对象”，产出是给技术看的文档；缺了“立场”，AI 会替一线出题。导师说第三句最重要。

目标方向这一步要解决什么
现状

访谈拿回大量业务原话，研发却无从下手；工作台还没做出来，一切都很抽象。

↓所以
目标

把“业务说的事”对到哪条数据、哪个事件、哪个页面。

对象管理层 + 技术团队已会用 Hermes 等基础工具
→
输入访谈报告 + 聊天记录加上访谈转写、会议复盘
→
产出工作台整体设计数据本体 + 侧边栏
思路方法提示词为什么这样写
A先行判断这一步面对的局面
判断 01

产出的对象从业务换成了管理层和技术团队。业务说的“该联系了”“答应了家长的事”，技术接不住，要翻译。

判断 02

真正的难点是抽象：技术功能和业务是什么关系不清楚，要做的工作台也还没做出来。

判断 03

业务最终看到的都是一个个业务单元（本项目为待办卡）。所以翻译的抓手是：每个业务单元从哪来、到哪去。

B设计决策判断 → 写法 → 对应段落
判断所以提示词要对应段落 · 点击跳到提示词
这份报告要对接下一步开发
→
开头先说清任务：把反馈翻译成技术方案，对应到开发工作
对象已经懂基础工具和概念
→
交代他们已掌握的工具、现有看板基于什么搭建，直接用熟悉的概念来讲
抽象是最大障碍
→
直接写出抽象在哪：功能与业务的关系、需求怎么落成功能页面
需求要落到数据上
→
抓两条线：业务流对数据节点，数据流对产生业务单元的数据或状态变化（本项目为触发待办的企微消息）；先画图谱再分析
架构师要能直接对上
→
写明要落到哪几端，多用对象关系图和流程图表达
研发要能开工
→
回答数据本体、每个业务单元（本项目为待办）从取数到写回本体的完整链路，以及事件表怎么建
C骨架公式缺了哪一块会怎样
任务 × 汇报对象 × 难点 × 两条线 × 落点 → 可开工的方案

缺了“两条线”，方案会变成功能清单；缺了“落点”，架构师对不上；缺了“写回”，业务单元（本项目为待办）没有闭环。

    三步串联每一步换一个对象，产出接力往下传
    01

    技术 → 业务

    对象
    一线
    输入
    现状和会议复盘
    产出
    访谈提纲
    交给下一步访谈转写或报告
    实地访谈人来完成
    02

    业务 → 技术

    对象
    管理层和技术团队
    输入
    访谈报告和过程数据
    产出
    技术方案
    交给下一步已定方案（如本项目的待办流转、数据回流、业务流打通）
    03

    方案 → 每个人每天

    对象
    一线和主管
    输入
    方案和过程数据
    产出
    执行规范
    交给下一步上线后的新反馈，回到环节二或三
    通用公式四个问题，三步各有填法
    情境现在走到哪
    对象给谁看
    方法怎么分析
    形式怎么呈现
    提示词骨架
    01访谈提纲
    已打通什么、上线什么、卡在哪
    一线销售，非技术
    引导式提问，围绕一天的工作流
    图文并茂、先看后问
    处境×对象×立场→引导式访谈
    02技术方案
    对象会什么、抽象在哪
    管理层和技术团队
    业务流 × 数据流，先画图谱
    数据本体、对象图、流程图
    任务×汇报对象×难点×两条线×落点→可开工的方案
    03执行规范
    新的反馈是什么、已定了什么
    一线和主管
    用已定方案和行为数据，从用户视角分析
    按人群分套、按时间组织
    已定方案×新情况×用户视角×人群与时间→可执行的规范

    写任何一步的提示词前，先把这四格填满；哪一格填不出来，说明这一步还没想清楚。

    场景迁移换一个业务，四格换一套填法

    迁移示意选一个业务，看四格各换成什么。

    适用前提满足这三条，三套提示词换个业务也能直接套用
    前提 01有一线执行角色。

    不满足时环节一的访谈对象换成实际使用者或业务负责人。

    前提 02工作能拆成一个个可追踪的业务单元。

    不满足时先在环节二定义清楚业务单元，再谈链路。

    前提 03有过程数据可以分析。

    不满足时环节三改为先补数据采集，或者用访谈记录代替，并标注结论可信度较低。
