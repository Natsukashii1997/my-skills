# 终端（terminal）

整页是一个深色终端窗口里的一次命令行会话：每个区块是一条命令加它的输出，全页只用一种等宽字体，靠琥珀、蓝、绿、红四种语法色分层。

参考页面：[reference.html](reference.html)（三步法样张，首页 + 内容页；截图是灰色占位）。CSS 规则以 `.st-3` 开头。动手前先通读它的 CSS 和 `TPL[3]` 模板，组件照着用，不要凭印象重写。

## 气质

- 冷、硬、像工程师自己的工作记录。没有卡片，没有装饰图形，信息全部是“命令 → 输出”。
- 结构靠命令本身表达：读文件用 `cat`，看结构用 `tree`，讲理由用 `why`，跑演示用 `replay`，看统计用 `wc`。命令名就是区块标题。
- 唯一的“窗口感”来自外层一个 10px 圆角的终端窗口，窗口里面全是直角。

## 适合 / 不适合

适合：
- 给研发、数据、运维看的技术方案、接入说明、排障复盘。
- 提示词、配置、规则逐段讲解（文件 + 注释行的形式天然合适）。
- 日志、事件流、状态推进类的过程演示。

不适合：
- 给业务一线、管理层看的汇报页：命令行包装会成为阅读门槛。
- 以长段中文叙述为主的页面：等宽字体排长段落很累。
- 需要大图、品牌感、营销转化的落地页。

## 色值令牌（照抄，不即兴调色）

```css
:root{
  /* 底色 */
  --bg:#0D1014;          /* 页面底 */
  /* 表面 */
  --card:#12161B;        /* 终端窗口正文底 */
  --bar:#1B2027;         /* 窗口标题栏、tmux 面板标题、底部状态栏 */
  --filebar:#161B21;     /* 文件头条；也用作文件内段落分隔线 */
  --file:#0A0D10;        /* 文件正文底（比窗口再深一级） */
  --dot:#3A424D;         /* 标题栏三个圆点 */
  /* 文字 */
  --fg:#D9DFE7;          /* 正文、命令本身 */
  --fg2:#AEB8C5;         /* 次要正文、表格第二列 */
  --mut:#7D8896;         /* 注释行、表头、元信息 */
  --tree:#4A5462;        /* 只给 ├── └── │ 这类树形符号 */
  /* 线 */
  --line:#29313B;        /* 窗口描边、面板分隔、表头虚线 */
  --row:#191E25;         /* 表格行分隔 */
  /* 强调色（语法色，各有固定语义） */
  --acc:#FFB547;         /* 琥珀：光标、重点值、按钮、当前态、标题里的关键词 */
  --blue:#79C6FF;        /* 蓝：路径、键名、{{占位}}、链接、P1 */
  --ok:#7EE787;          /* 绿：提示符 user@host、[ ok ]、复制按钮、批注行 */
  --red:#FF7C88;         /* 红：warn、P0、“最关键”标记 */
  /* 三段识别色（只在首页目录树里用） */
  --c1:#79C6FF; --c2:#FFB547; --c3:#FF7C88;
  /* 状态 */
  --flash:rgba(255,181,71,.12);  /* 段落被跳转定位时的闪烁底 */
}
```

- 琥珀是唯一的“行动色”：光标 `▌`、`.tm-go` 按钮实底、tmux 当前面板标题、状态栏当前步、`.tm-fx` 的结果块。别处要强调也用它，不另找颜色。
- 蓝、绿、红按终端语法用，不互换：绿只给提示符和成功，红只给警告和 P0，蓝只给路径、键名和占位符。首页目录树里的三段识别色 `--c1`–`--c3` 是例外，只在目录树里用。
- `#4A5462` 在窗口底上对比只有 2.37:1，只能画树形连线符号，不能写字。
- 最浅可读字是 `#7D8896`（在 `#12161B` 上 5.05:1），注释、表头都用它，不再更浅。
- 实底色块（`.tm-go`、`.p0`、`.p1`、`.tm-fx b`）上的字一律用底色 `#0D1014`，不用白。

## 字体

```html
<link rel="stylesheet" href="https://fonts.googleapis.com/css2?family=Noto+Sans+SC:wght@400;700&family=JetBrains+Mono:wght@400;700&display=swap">
```

| 角色 | 字体 | 用法 |
|---|---|---|
| 全部文字 | JetBrains Mono，中文回落 Noto Sans SC | 正文 14.5px / 1.75；只有 400 和 700 两种字重；不用斜体（`em` 一律 `font-style:normal` 改成琥珀色） |
| 命令行 | 同上 | `.tm-cmd` 与正文同号；命令本身 700，提示符 400 |
| 表格、代码 | 同上 | `.tm-tbl` 13.5px；`.tm-code` 13.5px；tmux 面板 13px；演示里的 `.code` 12.5px |
| 元信息 | 同上 | 标题栏、状态栏、面板标题 12px；文件头 12.5px |

全页只有一个字族。中文字符由 Noto Sans SC 补上，所以 link 里两个都要。

## 标题

- **首屏 h1**（`.tm-h1`）：`clamp(34px,4.4vw,60px)`，行高 1.2，700，`letter-spacing:-.02em`。分两行：第一行前面自动加琥珀色 `> `；第二行缩进 2ch，开头一段用 `.tm-dim2`（灰、400）做明暗对比。h1 上面放一行 `# 眉题` 注释（`.tm-dim`）。
- **章节标题**（`.tm-h2`）：`clamp(28px,3.4vw,44px)`，700，行高 1.3；关键词包在 `em` 里变琥珀色。它出现在 `cat GOAL.md` 的输出里，不单独成行。
- **区块标题**：就是 `.tm-cmd` 命令行本身——绿色 `nat@ai-landing`、蓝色 `:路径`、`$`、加粗命令。命令下一行可跟一条 `# 说明` 注释。全页同级标题都用这个格式，不加别的标题样式。

## 形状

- 圆角：只有外层 `.tm-win` 用 10px，标题栏圆点 11px 正圆；其余全部直角。
- 描边：1px solid `#29313B`；表头下边用 1px dashed；表格行用 1px solid `#191E25`；`.tm-box` 用红色 1px 描边，`.n2` 换蓝色。
- 阴影：只有 `.tm-win` 一处，`0 30px 60px -30px rgba(0,0,0,.8)`。
- 间距：窗口正文 `padding:22px 28px 28px`；命令之间 `margin-top:18px`；输出行间 6px；输出整体左缩进 2ch；页面上下 `padding-block:32px 72px`。
- 色块标签（`.p0`、`.p1`、`.tm-fx b`、`.tm-go`）是直角实底，左右内边距 5–10px。

## 版式

**首页**：整页只有一个终端窗口（标题 `~/ai-landing — zsh — 160×48`），依次是四条命令：
1. `whoami --audience` → `.tm-kv` 键值对，写读者和目标；
2. `cat README.md` → 眉题注释、h1、副标题（重点词琥珀色）、`/* 引用 */` 注释块；
3. `tree -L 2` → 主线画成目录树，每段是一个目录（用该段识别色），下面是 `prompt.md --骨架参数` 和 `output/产出.html`，段与段之间一行 `↓ 产出作为下一步输入`；
4. `cd` → `.tm-go` 按钮进入内容页。
窗口最后留一行空提示符加琥珀光标。

**内容页**：同一个窗口，命令顺序是 `cat GOAL.md`（标题、现状/目标、输入→产出管道）→ `why --judgments` → `why --decisions | column -t`（表格）→ `echo $SKELETON`（公式和 warn 行）→ `cat prompt-02.md`（文件 + 注释行批注）→ `replay ... --trace`（tmux 三栏演示 + 状态栏）→ `head output/...`（灰度缩略图 + 键值）→ `wc --stats` → `tree output/chapters`。

**窄屏（≤820px）**：窗口正文内边距收到 14px，输出取消 2ch 缩进；tmux 三栏改单列、栏间改上边线；状态栏 6 格改 3 格；产出头部图文改上下排；表格自身 `overflow-x:auto`；`.code` 取消左缩进。

## 关键组件

| 构件 | 类名 | 样子 | 什么时候用 |
|---|---|---|---|
| 终端窗口 | `.tm-win` + `.tm-bar` + `.tm-body` | 10px 圆角深色窗，标题栏三个灰点、标题居中 | 每页一个，包住全部内容 |
| 命令行 | `.tm-cmd`（`.ps` `.pw` `.dl` `.c`） | 绿提示符、蓝路径、`$`、加粗命令 | 每个区块的标题 |
| 输出 | `.tm-out` | 左缩进 2ch，行间 6px | 命令下面的全部内容 |
| 键值 | `.tm-kv` | 两列网格，键蓝色带冒号 | 读者、目标、现状/目标、元信息 |
| 目录树 | `.tm-tree` + `.tr` + `.tm-dir` + `.fl` | 灰色树形符号，目录名 17px 用段色 | 首页主线、产出章节目录 |
| 管道 | `.tm-pipeline` | 1px 框串成一行，`──▶` 连接，最后一格琥珀框 | 输入 → 产出 |
| 列表 | `.tm-list` + `.tm-tag` | `[A]` 琥珀标签加粗体判断，下一行灰色解释 | 判断、要点 |
| 表格 | `.tm-tbl` | 灰色 400 表头（参考页用大写英文列名）、虚线表头线、无竖线 | 决策对照、业务流 × 数据流 |
| 段落跳转 | `.seg-tag` | 琥珀下划线文字，悬停变实底 | 决策指向提示词某一段 |
| 公式 | `.tm-fx` + `.tm-warn` | `A × B → [结果]`，结果琥珀实底；下面 `warn:` 红字逐条 | 骨架公式与缺项后果 |
| 文件 | `.tm-filebar` + `.tm-file` + `.tm-seg` | 文件头条 + 更深的正文底；每段先一行绿色 `# ──【段名】` 注释，再是代码 | 提示词、配置逐段批注 |
| 关键标记 | `.tm-note em` | 红底深字小块 | 段落里最关键的一句 |
| tmux 演示 | `.tm-tmux` + `.tm-panes` + `.tm-pane` + `.tm-pt` | 三栏分屏，当前栏标题琥珀实底 | 过程演示 |
| 日志行 | `.tm-log` + `.st` | 行首 `[    ]` / `[ >> ]` / `[ ok ]` 三态 | 演示里的系统步骤 |
| 待办框 | `.tm-box` + `.p0` / `.p1` | 红（或蓝）1px 框，优先级实底小块 | 演示里生成的结果卡 |
| 状态栏 | `.tm-status` | 底部 6 格，完成绿字、当前琥珀实底 | 演示进度 |
| 按钮 | `.btn` / `.tm-go` | `.btn` 是 `[ 播放 ]` 方括号文字；`.tm-go` 琥珀实底 | 演示控制 / 翻页入口 |

## 这个风格特有的禁区

1. 窗口里不放卡片：不加圆角、阴影、背景色块来分组，分组只靠命令行和缩进。
2. 不换字体：标题也用 JetBrains Mono，不引入无衬线或衬线标题字。
3. 命令要对得上内容：`cat` 读文件、`tree` 看结构、`why` 讲理由；不要堆和内容无关的花哨命令，也不要每行都写成命令。
4. 语法色不串用：红只表示警告和 P0，绿只表示提示符和成功；不要为了好看把标题染成蓝或绿。
5. 不做打字机逐字效果：入场只用 `.enter` 的 0.2s、`steps(2,end)` 两帧闪现。
6. 输出行要短：一行一件事，长解释拆成多行注释或表格，不在输出里放大段中文。
