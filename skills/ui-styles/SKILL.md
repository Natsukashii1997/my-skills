# UI 风格库

做给人看的页面时，按四步走：**选风格 → 读那种风格的 STYLE.md 和参考页面 → 守共用底线和动效规则 → 截图自检**。一页只用一种风格，不混搭。

每种风格一个文件夹 `styles/<英文名>/`：`STYLE.md` 写气质、适合场景、色值令牌、字体、标题、形状、版式、关键组件和这个风格特有的禁区；`reference.html` 是能直接打开的单文件参考页面（截图都换成了灰色占位）。**动手前先通读所选风格的 STYLE.md 和参考页面的 CSS，组件照着用，不要凭印象重写。**参考页面顶部的「首页 / 内容页」切换栏（`.sw`）是查看用的外壳，不属于风格，不要抄进页面。

## 一、选风格

- 用户点名了就用那种。旧说法照样认：「Hairline」「细线」「上次三步法讲解页那种网页质感」都是细线；「马克笔高亮」「黄色高亮那种」都是荧光笔；「精密暗色」「柔光」「终端」等按下表对应。
- 没点名就用**细线**。只有页面主体明显不是讲解（例如以筛选、排序为主的数据页，多页手册），细线不合适时，才按下表「适合」列另选，并在开头用一句话说明选了哪种、为什么，用户可以改。
- 拿不准时，把两三种候选的名字和一句理由给用户挑，不要自己混出一种新风格。

| 风格 | 文件夹 | 气质 | 适合什么页面 |
|---|---|---|---|
| 细线（默认） | [hairline](styles/hairline/STYLE.md) | 冷灰底、1px 细线、方角、超大粗黑标题，一种识别色串一段主线 | 方法论、方案讲解、流程复盘、专题说明 |
| 终端 | [terminal](styles/terminal/STYLE.md) | 整页是一次命令行会话，全等宽字，四种语法色分层 | 给研发看的技术方案、脚本与配置讲解、日志类过程 |
| 柔光 | [soft](styles/soft/STYLE.md) | 白卡浮在浅底上，大圆角胶囊，产品演示当主角 | 面向一线业务的工具或功能介绍页 |
| 精密暗色 | [precise-dark](styles/precise-dark/STYLE.md) | 近黑底四级表面，细线克制，只有一种紫蓝强调 | 内部平台、AI 工作流的产品说明页 |
| 文档站 | [docs](styles/docs/STYLE.md) | 左目录、中正文、右大纲，白底细线配一种青绿 | 手册、操作指南、规范、提示词与配置的逐段对照 |

| 便当卡片 | [bento](styles/bento/STYLE.md) | 大小不一的圆角瓦片，一格只讲一件事 | 方案亮点、成果汇报、给管理层的一页总览 |
| 数据表格 | [data-table](styles/data-table/STYLE.md) | 表格即主体，紧凑工整：可排序、可筛选、行内展开 | 清单、台账、方案对比、进度排期、以数据为主的页面 |

| Material 层级 | [material](styles/material/STYLE.md) | M3 色调表面加高程阴影，规整圆润，系统感强 | 偏应用界面的功能说明、帮助中心、多章节操作指南 |

| 大字动效 | [poster](styles/poster/STYLE.md) | 纯黑底、海报级大标题、白色胶囊按钮，滚动时逐块浮现 | 项目发布首页、节数少的成果展示页 |
| 荧光笔 | [marker](styles/marker/STYLE.md) | 浅底两团静止柔光、深墨标题左对齐，一支荧光笔只压结论词，产品窗口当主角 | 产品发布与功能介绍专题页、带产品演示的讲解页、复盘与方案评审、社媒长图 |

**以后加风格**：加一个文件夹 `styles/<英文名>/`，放 `STYLE.md`（照现有风格的小节结构写，色值、类名都要能在参考页面里找到原样）和单文件 `reference.html`（截图换灰色占位，用 `scripts/shot.mjs` 在 1440 和 400 宽各截一次，无横向溢出、无报错），再在上表加一行。改完在 CHANGELOG 记一条，按规则升次版本，重跑 evals。

## 二、所有风格共用的底线

**内容组织**

1. **先想清楚主线。** 页面要有一条读者一眼能说出来的主线；用户给了几段就是几段，不拆碎，不另加原则清单、术语表这类框架。
2. **同一层意思全页只说一次。** 常见重复：首屏和章节头都写「读者 / 输入 / 产出」，章末要点复述正文，收尾又做一张总表。各段读者不同时，读者只写在各章章节头，不要在最后一章末尾或收尾前再加一块「各段读者 / 产出」对照。
3. **先讲为什么，再给是什么。** 给模板、提示词、规则之前，先交代判断依据和设计决策。
4. **同级标题格式完全一致。** 字体、字号、装饰、间距一样；同组标签字数相同，说明句句式相近、长度相近。
5. **有逻辑层级的信息要在视觉上区分开**（一浅一深、一因一果），用标签、颜色、字重、符号区分。这条管同一处并列信息之间的关系；页面整体的标题层级照常用字号区分。
6. **不直接放原始截图的大图。** 用本页的组件重画它的结构，原图最多当封面缩略图。段落最多 3 行，能用组件表达的不写成段落。
7. **数字只来自材料。** 可以加由材料算出的派生字段（例如花费 ÷ 线索数得出单条线索成本），但要在页面上写明算法（列头注释或脚注）；材料里没有、也算不出来的数字不编。

**颜色与文字**

- 只用所选风格 STYLE.md 里的色值令牌，不即兴调色。令牌里确实没有、又必须用的颜色（例如某种风格没写状态色），先在页面 `:root` 里按该风格的同色系补一个令牌并注释用途，组件里只引用令牌，不散写色值。
- 正文和要读的辅助小字（说明、标签、表头、日期、脚注）对背景的对比度不低于 4.5:1；大字不低于 3:1。大字按 WCAG 的口径算：32px 以上的字，或 19px 以上且 700 字重以上的标题；32px 以下字重不到 700 的、窄屏会缩到 19px 以下的，都按小字算。行号、分隔符、未激活态这类不用读的标记不限。STYLE.md 里标了「低于 4.5:1」的浅灰只能用在这类标记上；参考页面里有几处拿它写了要读的小字，各 STYLE.md 写了新页面该换成哪个色，照新的做。
- 全页开 `font-variant-numeric:tabular-nums`。字体只用所选风格 STYLE.md 列出的 Google Fonts。

**技术约束（发布为 Artifact 时）**

- 文件从 `<title>` 开始，不写 `<!doctype>`、`<html>`、`<head>`、`<body>`。title 用页面名，2–4 个词。
- 外部资源只有 Google Fonts。图片压成 JPEG（每张 ≤180KB）后用 data URI 内嵌。不用 iframe、fetch、alert、print。
- 复制按钮先走 `navigator.clipboard.writeText`；失败时选中原文，提示「已选中，请复制」。
- 可拖动的元素加 `touch-action:pan-y`，或者只让手柄可拖，不要吞掉页面滚动。
- 单列网格一律写 `minmax(0,1fr)`；400px 宽时不能横向滚动。默认只做电脑版，手机能读就行。
- 各风格的颜色都写死、只有一套（深色风格就是深色，浅色风格就是浅色），这是有意为之；`body` 写明背景色。

## 三、动效规则（最重要）

**只允许三类：**

1. **业务过程演示**：对话一条条出现，系统侧的步骤逐个点亮，卡片生成后写回，时间指针前进，清单逐条打勾。演示的必须是真实发生的过程；找不到值得演示的过程，就不做演示。每段最多一个演示。
2. **交互反馈**：标签切换、悬停、复制成功、按钮按下、排序筛选、展开收起。时长 0.15–0.3s。
3. **新内容进场**：演示里新出现的元素淡入并上移几像素（细线是 0.42s、8px）。

**禁止：** 流动虚线、脉冲或呼吸光圈、漂浮的小点、背景动画、滚动视差、数字滚动计数，以及任何「为了让页面动起来」的效果。静态结构图就保持静态。

**唯一例外：风格自带的进场方式。** 所选风格的 STYLE.md 写了「进场方式」一节、而且那一节满足下面全部条件时，才可以让内容随滚动出现（目前是大字动效和荧光笔）；没写这一节的风格一律不做随滚动的进场。条件：

- 首屏不等动画也完整可读；
- 每块只出现一次，不循环、不做视差、不随滚动位置连续变化，往回滚不重播；
- 粒度是「一块」或「一个标题里的高亮」，不拆到每张卡、每个字；STYLE.md 写明每节最多几块；
- 开启 `prefers-reduced-motion` 时直接显示；
- 有兜底，一段时间后全部显示。

进场只照 STYLE.md 那一节写的做，不自己加。演示内部的特殊效果（例如荧光笔的镜头推近、「生成中」微光）也一样：只在 STYLE.md 写明它的风格里用，照那里的边界做。

**演示要有这些行为**（各风格参考页面都实现了：细线用 `Demo(root,cfg)`，荧光笔用 `Demo(root,n,render)`，其余风格用参考页面里的 `initDemo`）：

- 控件有「播放 / 暂停」「重播」「逐步 →」，旁边显示进度。
- 进入视口约三分之一时自动播放一次；用户手动操作过就不再自动播放。
- 第 0 步也要有可读内容或占位提示，不能是一片空白。
- 按所有步骤里最高的那一帧锁定高度，播放时页面不跳。
- 开启 `prefers-reduced-motion` 时直接显示最终态，去掉全部动画和过渡。
- 演示结束出现一句结论。演示中的人名、对话、客户信息标注「示意」。

## 四、截图自检（交付前必须做）

1. 用自带脚本截图：
   ```bash
   node <本 skill 目录>/scripts/shot.mjs page.html <输出目录>            # 默认 1440 和 400 两个宽度
   node <本 skill 目录>/scripts/shot.mjs page.html <输出目录> --hash ch  # 页面靠 #后缀 切换时
   ```
   脚本会自动包一层 doctype，等字体加载完再截整页长图（高于 8000px 的页面分段截成 `-p1`、`-p2`…），每个宽度打印一行结果：页面高度、`scrollWidth`、是否横向溢出、控制台报错数；有溢出或报错时退出码为 1。默认模拟「减少动态效果」，演示直接显示最终态；要看动画过程加 `--motion`。
2. 切片逐段看：溢出、错位、文字墙、空白演示、看不清的截图。再把所选风格的 `reference.html` 也截一次，同一种组件对照着看，至少查两轮。
3. 用 `python3 -I` 加 `html.parser` 查标签是否闭合。
4. 对照第二、三节：主线段数和用户给的一致，没有重复内容，颜色都来自令牌，没有被禁止的动效。
5. 脚本失败（超时、报错）或某一步没做成时，在给用户的答复里如实写明哪一步没做、为什么。
6. 修完再截一次图确认。改动较大或用户之前否决过的页面，交给另一个只拿需求、不看你思路的 agent 独立审一遍。
