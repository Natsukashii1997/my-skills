# ui-styles evals

每条都来自真实请求，内容全部是虚构的占位。盲测时新开一个 agent，只给它这个 skill 的目录，以及每条的「请求」「给的材料」两栏，不给其他上下文；打分由出题以外的一方按「判定标准」做。

0.3.0 起按风格库的新结构重写：E1、E2 沿用细线的两条（E1 去掉了风格名，改测「没指定就用细线」），E3 测点名别的风格，E4 测没指定风格时按选型表另选，E5 是不该用的。

## E1 没指定风格，做一页流程讲解页

- **请求**：把下面这个周报自动化流程做成网页讲解页，给团队看。
- **给的材料**：

  > 周报自动化分三段。① 采集：每周日 22:00 从 CRM、工单系统、广告后台拉取上周数据，读者是运营。② 汇总：按业务线汇总并算环比，异常（环比跌超 20%）标红，读者是运营。③ 推送：周一 9:00 把一张汇总卡片推到管理群，读者是管理层。以前每周一上午要 2 个人各花 3 小时手工做。

- **期望行为**：没指定风格，按 SKILL.md 默认用细线；读 `styles/hairline/STYLE.md` 和参考页面，先定主线三段；照抄细线令牌和三种字体，首屏把三段主线画出来；异常行用状态色令牌；演示只演真实业务过程；交付前用 `scripts/shot.mjs` 截图自检。
- **判定标准**（全部满足才算过）：
  1. 文件以 `<title>` 开头，没有 `<!doctype>`、`<html>`、`<head>`、`<body>`；外部资源只有 Google Fonts。
  2. 用的是细线风格：页面里出现的每个色值都在 `styles/hairline/STYLE.md` 的令牌代码块里（`#F3F4F6` 底色，三段识别色 `#DD5129`、`#2D53D2`、`#0A8470`；「标红」用 `--bad` 系列，不用 `--s1`）；三种字体（Noto Sans SC、Archivo、JetBrains Mono）都用上了。`rgba()` 透明度写法若是令牌色加透明度，算令牌色；`#fff` / `#FFF` 这类简写等于令牌里的 `#FFFFFF`，算令牌色；STYLE.md「形状」一节写明的阴影值算令牌色。页面 `:root` 里自己新增的令牌，只有 STYLE.md 令牌里确实没有同用途的色、并写了注释说明用途时才算过；能用现有令牌替代的（例如另起一个和 `--rule2` 几乎一样的灰），算不过。
  3. 主线正好是三段（采集、汇总、推送）：首屏下方的主线骨架画出了三段，后面三章一一对应。没有另加原则清单、术语表这类框架。
  4. 没有被禁止的动效：`infinite` 动画、脉冲、流动虚线、背景动画、视差、数字滚动计数都没有。演示的是真实过程（例如数据流过三个环节、卡片生成后推送），并带播放控件。
  5. 有顶栏、首屏、收尾（下一步加来源）。「读者 / 输入 / 产出」同一种说明在每章最多一处，首屏和收尾不再重复；在最后一章末尾或收尾前再加一块「各段读者 / 产出」对照，也算重复。
  6. 交付前截图看过整页（1440 和 400 宽），并说明了检查结果。
- **不该出现**：卡片阴影或大圆角（应用窗口 8px 除外）；比 `#5F6672` 更浅的小字（32px 以上大字用 `#7A818C` 是 STYLE.md 写明的例外，不扣分；表格里的「—」按小字算）。

## E2 审一张号称细线风格的页面

- **请求**：这页说是按细线风格做的，你帮我看看有什么问题，列出来就行，先别改。
- **给的材料**：`evals/flawed.html`
- **期望行为**：逐条对照 SKILL.md 共用底线、动效规则和 `styles/hairline/STYLE.md` 找问题，按严重程度列出来，每条写出违反了哪条规则、应该怎么改；不动文件。
- **判定标准**（全部满足才算过）：
  1. 找出了被禁止的动效，下面三项至少点到两项：圆点 `pulse` 无限循环、背景渐变流动、数字滚动计数。
  2. 找出了卡片阴影加 16px 大圆角。
  3. 找出了重复内容：卡片里的「读者 / 输入 / 产出」和末尾的「回顾一下」表重复了。
  4. 找出了下面四项里的至少两项：辅助小字 `#9CA3AF` 太浅；13px 的小字用了主色而不是深色版；缺顶栏、主线骨架或收尾；数字没有写口径。
  5. 没有改动 flawed.html。
- **不该出现**：把禁止的动效说成可以保留；直接改文件。

## E3 点名用终端风格

- **请求**：用终端风格做一页网页，给工程师讲讲我们的数据库每日备份脚本是怎么跑的。
- **给的材料**：

  > 备份脚本每天 03:00 由定时任务启动，分三步。① 导出：对主库做一致性快照导出，约 12 分钟，产出 1 个 .sql.gz。② 加密：用备份专用公钥加密，校验文件哈希。③ 上传：传到对象存储的 backup 桶，保留 30 天，超期的自动删除；任何一步失败就往值班群发告警。

- **期望行为**：识别出点名的是终端风格，读 `styles/terminal/STYLE.md` 和它的参考页面，用终端风格的令牌、字体和组件做；共用底线、动效规则照守；截图自检。
- **判定标准**（全部满足才算过）：
  1. 文件格式同 E1 第 1 条。
  2. 用的是终端风格：底色、文字色、强调色都来自 `styles/terminal/STYLE.md` 的令牌（简写、透明度、「形状」里的阴影按 E1 第 2 条的口径算），字体是那份 STYLE.md 列出的字体；没有细线的冷灰底 `#F3F4F6` 和三色识别色。
  3. 用到了终端风格 STYLE.md「关键组件」表里的至少 3 种组件（类名或同样的结构）。
  4. 三步主线（导出、加密、上传）清楚，没有另加框架；如果有演示，演示的是真实过程（例如脚本逐行输出），没有被禁止的动效。
  5. 交付前截图看过（1440 和 400 宽），并说明了检查结果。
- **不该出现**：混用两种风格；默认改回细线。

## E4 没指定风格的数据页

- **请求**：把下面这份投放渠道清单做成一个网页，能按渠道类型筛选、按花费排序，点开一行能看备注。
- **给的材料**：

  > 渠道｜类型｜本月花费（元）｜线索数｜备注
  > 渠道 A｜信息流｜48,200｜312｜9 月起加投
  > 渠道 B｜搜索｜36,900｜405｜品牌词为主
  > 渠道 C｜信息流｜22,100｜96｜素材疲劳，下周换
  > 渠道 D｜社群｜8,400｜133｜靠老带新
  > 渠道 E｜搜索｜15,700｜88｜竞品词出价偏高
  > 渠道 F｜达人｜30,000｜51｜一次性合作，已结束
  > （以上是示意数据）

- **期望行为**：没指定风格，但页面主体是可筛选、可排序的表格，不是讲解；按选型表选数据表格，开头一句话说明选了哪种、为什么；读 `styles/data-table/STYLE.md` 和参考页面来做；截图自检。
- **判定标准**（全部满足才算过）：
  1. 文件格式同 E1 第 1 条。
  2. 选了数据表格，并在回复里用一句话说明了理由（主体是表格数据，不是讲解）。
  3. 色值、字体来自 `styles/data-table/STYLE.md`（口径同 E1 第 2 条）；没有套用细线的主线骨架、章节大编号、演示带。
  4. 筛选（按类型）、排序（按花费）、行内展开（看备注）三项都能用，数据 6 行齐全且和材料一致，标了「示意」。
  5. 交付前截图看过（1440 和 400 宽），并说明了检查结果；400 宽没有整页横向滚动（表格自身可以在容器里横向滑动）。
- **不该出现**：硬做成细线讲解页；自己编材料里没有的数据。
