# worktree 清理

目标：把堆积的 worktree 清掉，腾出磁盘，也免得 AI 改错了是哪一份代码；**任何没进默认分支、没提交、没推送的东西一行都不丢**。

用户只需要说「清一下 worktree」。用户不读代码：给他的是结论和要他拍板的事，不是脚本原文。

```bash
S=~/.claude/skills/worktree-sweep/scripts/worktree_sweep.py   # Codex 用 ~/.agents/skills/worktree-sweep/scripts/worktree_sweep.py
python3 $S list --fetch                  # 只出报告；默认扫 ~/Documents/ChatGPT/个人/work，也可以在后面写别的根目录
python3 $S show <worktree 路径>           # 看一个 worktree 没提交 / 没推送 / 只有它有的本地文件
python3 $S sweep --confirm               # 只删上次 list 清单里、此刻复核仍可安全删除的
python3 $S sweep --confirm --skip <目录名或路径>   # 排除某几个（可重复）；--only 只删某几个
```

`--fetch` 只更新本地记录的远端状态（`git fetch --prune origin`），不改任何工作目录里的文件；不加的话，刚在 GitHub 上合并的分支会被当成没合并（只会更保守）。

## 流程

1. **列清单**：跑 `list --fetch`。没有 `gh` 或没登录时 PR 那一项自动跳过，不影响分档。
2. **讲给用户听**，结论先行：
   - 一句话总数：几个仓库、几个 worktree，三档各几个，能腾出多少空间。
   - 「可安全删除」：按仓库说个数和大小即可，用户要看再逐条列。
   - 「需要看一眼」：逐条说清原因和**删了会丢什么**（几个文件没提交、几个提交没推送、哪个本地文件只有这里有）。拿不准的先 `show`。
   - 「保留」：一句话带过原因分布（主工作区、锁定、近期活跃、有程序在用）。
3. **问用户拍板**：「这 N 个确认删吗？有要留的吗？」等用户明确说删（「清掉」「删吧」），才往下走。用户点名要留的用 `--skip`。
4. **执行**：`sweep --confirm`。脚本会按清单逐个复核，变了的自动跳过。把结果转述给用户：删了几个、腾出多少、没删的和原因；删掉的本地分支附带找回命令，告诉用户「要找回跟我说」即可。
5. **「需要看一眼」档脚本不删**。用户要处理哪个，先 `show` 给他看会丢什么，再按他的决定办：要保留改动的，提交并推送（只提交这个 worktree 里自己的改动，见 G-04）；用户点名说某一个里的改动不要了，才对**那一个**单独删，并告诉他用了什么命令。不批量处理这一档。

## 分档规则

从上往下判断，先命中的算：

| 情况 | 档 |
|---|---|
| 主工作区（仓库本体） | 保留 |
| 查的时候出错，有项没查清 | 需要看一眼 |
| 被 `git worktree lock` 锁定 | 保留 |
| 目录已经不在了（只剩 git 里的登记） | 可安全删除：只清登记；分支已合并才删 |
| 有程序的当前目录在里面（`lsof`） | 保留 |
| 有做到一半的 rebase / 合并 / cherry-pick（工作区可能是干净的） | 需要看一眼 |
| 有改了没提交、或没跟踪的新文件 | 7 天内动过 → 保留；更久 → 需要看一眼 |
| 已合并，但有 git 不管、主目录里也没有同样一份的本地文件（如单独改过的 `.env`；`node_modules`、`dist`、`test-results` 这类能重新生成的不算，项目在 `regen.json` 里声明的生成目录也不算，见下） | 需要看一眼 |
| 已合并，24 小时内还有动静 | 保留（可能有会话刚合并完还开着） |
| 已合并，干净 | **可安全删除** |
| 没合并，但 PR 显示已合并 | 需要看一眼（合并后又改过，或没 fetch） |
| 没合并，有提交没推到远端 | 7 天内动过 → 保留；更久 → 需要看一眼 |
| 没合并，提交都在远端 | 7 天内动过 → 保留；更久 → 需要看一眼 |

「已合并」指分支的内容已经在默认分支（`origin/<默认分支>` 或本地默认分支）里，三种都认：

- 普通合并、快进：分支的提交是默认分支的祖先。
- 变基合并：`git cherry` 显示每个提交都有等价提交在默认分支里。
- squash 合并：分支改过的每个文件，在默认分支里内容一模一样；或者默认分支里有一个提交的改动和整个分支的改动相同（`git patch-id`）。

squash 合并后原来的提交不在远端，但内容已在默认分支里，所以不算「没推送」。

「最后改动」取这几样里最新的：HEAD 提交时间、这个 worktree 的 git 记录（index、HEAD）的修改时间、没提交文件的修改时间。脚本自己查的时候不会刷新这些时间。

### 项目自己的生成目录（regen.json）

有些项目的构建会生成 git 忽略的目录（例如 postpane 的 `src/apps/desktop/src-tauri/resources`，里面是构建时打进去的程序）。脚本不认识它们，会当成「本地独有文件」，已合并的 worktree 因此一直卡在「需要看一眼」。在 skill 目录的 [regen.json](regen.json) 里声明后就不再挡：

- `paths`：按仓库名（仓库文件夹名）写仓库里的相对路径，只对这个仓库生效，它下面的子目录也算；比它大的目录不算（声明 `src/gen` 不会放过整个 `src/`）。
- `names`：对所有仓库生效的目录或文件名。
- 只加**确认重新构建就能生成**的目录；拿不准就别加。路径写错（绝对路径、`..`）脚本直接报错，不会悄悄放宽。
- 因为声明而归入「可安全删除」的，报告里会写「按 regen.json 当作可重新生成：…」。

两个时间窗可调，但不要为了多删几个去调：`--grace-hours`（已合并的先留多久，默认 24）、`--stale-days`（多久没动算很久，默认 7）。

## 安全保证（脚本里写死的，不靠自觉）

1. `list` 只读：不删、不改工作目录；只写一份清单到 `~/.cache/worktree-sweep/plan.json`（加 `--fetch` 时会更新远端记录）。`--fetch` 和查 PR 用的是本机已登录的 git / gh，脚本不读、不存任何凭据。
2. `sweep` 不加 `--confirm` 什么都不做；只删**上一次 `list` 清单**里的条目，清单 24 小时后失效、执行过一次就作废。用户没看过的不会被删。
3. 删之前逐个重新查一遍：档位必须还是「可安全删除」、HEAD 和列清单时一样、没有程序在用，否则跳过并说明原因。
4. 用 `git worktree remove`，**不加 `--force`**：万一复核之后又有人改了文件，git 自己会拒绝删除。
5. `git worktree prune` 只在它要清的登记全是清单里的条目时才跑，不会顺带清掉别的（例如外接盘没插上的 worktree）。
6. 本地分支只在复核确认已合并、分支没被挪动、不是默认分支时才删；删除记录（含 SHA）写进 `~/.cache/worktree-sweep/sweep-<时间>.json`，并打印找回命令。远端分支一律不碰。
7. 有未提交或未推送内容的 worktree 永远不会进「可安全删除」。

## 已知边界

- 「有程序在用」只看进程的当前目录。编辑器打开了里面的文件、但当前目录在别处，看不出来；靠「24 小时内有动静就保留」兜底。
- worktree 放在外接盘、暂时没插上的，会显示成「目录已经不在了」。这类请先 `git worktree lock <路径>`，脚本就会保留。
- 合并判断只认名叫 `origin` 的远端和默认分支（`origin/HEAD` 指向的，没有就 `main`、`master`）。
- 找仓库时从根目录往下最多 4 层，跳过隐藏目录和 `node_modules` 之类；worktree 本身不靠找目录，而是问每个仓库的 `git worktree list`，所以放在根目录外面的（如 Codex 的）也会列出来。
- 需要 Python 3.9+ 和 git；`gh`、`lsof`、`du` 有就用，没有就在报告「说明」里写明跳过了哪一项。
