# 清单和转达消息的格式

## 清单文件

存到 `~/Library/Application Support/agent-kit/decision-inbox/拍板清单-<日期>.md`。会话一律写完整 id（`local_` 加 36 位），下一次收集靠它认出「上一份清单里已经有的」。

```markdown
# 拍板清单 · <日期>

来源：扫 14 天内未归档的 Claude 桌面会话 <N> 个，其中 <N> 个停在「等你」。脚本筛掉 <N> 个（已交给下游会话 <N>、你已回复还在做 <N>、在忽略名单里 <N>），剩 <N> 个。没看的：没写状态行的会话 <N> 个。
常浩还没回复，下面全部未转达。

## A 组：一句话能定（<N> 条）

| 编号 | 要定什么 | 推荐 | 你回这句话 | 会话 |
|---|---|---|---|---|
| A1 | <一句话，写清是哪件事的哪个决定> | <推荐和一句理由；或「拿不准：<原因>」> | 「<原话>」 | <标题> `local_…` |
| A2（会合并） | … | … | 「合并」 | … |

## B 组：要你亲手做（<N> 件）

- B1 <做什么，在哪做，做完回哪句话>。<标题> `local_…`

## C 组：我已代验，等你同意后转给对应会话（<N> 条）

你回「转达代验结果」，我把下面每条原样发给对应会话。

- <通过 / 部分 / 不对 / 没验>：<看到了什么>。<标题> `local_…`

## D 组：单独问，不接受批量（<N> 条）

- D1 <要定什么>。<有依据才给推荐，否则写「不给推荐：<原因>」>。可回：<选项>。<标题> `local_…`

## E 组：之前已暂停、仍停着（<N> 个，不再问）

- <标题> `local_…`

## F 组：建议记进忽略名单（<N> 个）

<这些为什么可以忽略；有没有逐个通读>。你回「F 组记忽略」，我只把它们记进忽略名单，以后不再列；不归档、不给这些会话发消息。

- <标题> `local_…`｜停在：<它的下一步，截短>

## 不在这里处理，但也在等你

- <比如 PR 流程由别的会话管的>
```

转达和回读之后，在同一个文件末尾追加：

```markdown
## 已转达（<日期 时间>，常浩回「<原话>」）

授权范围：<复述>。发之前复核：<几个没变，几个变了没转>。

- A1 `local_…`：已送达 / 排队 / 没送达
- …

## 回读（<时间>）

- 结束：…
- 办完、留了后续动作：…
- 还在做：…
- 带着新问题回来：…（进第二轮）
- 更正：<别的会话指出判断错了的>
```

## 对话里怎么给他看

结论先行，一屏以内：

1. 一句话：多少个会话在等、真在等的多少、今天要他回的几条。
2. A 组表（编号、要定什么、推荐、你回这句话），会话名做成 `[标题](#local_…)` 链接放在「要定什么」里。
3. D 组逐条。
4. B 组、C 组各一条一行。
5. E、F 组只报数量和一句说明。
6. 最后写清批量答复的范围：「回『都按推荐』：A1～A<N> 按表里那句话转达（A<N> 会合并 PR #<号>），C 组转达代验结果，F 组记忽略；不含 D 组和 B 组。」

## 转达消息模板

答复（A 组、D 组）：

```text
（拍板清单转达，<日期>）常浩在「<本会话标题>」会话里对今天的拍板清单回了「<他的原话>」。
这一条回答的是你最后问的这一问：<把对方的问题复述一遍>。
清单上写给他的推荐答复是：「<那句话>」。请按这句处理。
范围只到这一问；<不在内的事，比如：发群没有授权 / PR 合并不在内>。
如果你现在等的已经不是这一问，这句作废，照你最新的问题重新问他。
```

他逐条答复时，第一行写他对这一条说的原话，不写「清单上的推荐」。

会合并、会提交的，加一句：「我 <时间> 查过 <PR / 分支> 的状态是 <…>，动手前请你自己再确认一次。」

代验结果（C 组）：

```text
（拍板清单转达，<日期>）这是代验结果，不是常浩本人的验收；常浩同意我把结果转给你。
你在等的是：<对方的验收句，原样>。
我（「<本会话标题>」会话）<时间> 用 <方式> 看到的是：<具体看到了什么>。结论：<通过 / 部分 / 不对 / 没验>。
<没验到的部分和原因>
证据：<路径>。
怎么收尾按你项目的规矩判断：需要常浩本人确认才能登记为已定的，仍然要问他；可以据此结束的就结束。不要因为这条消息做新的改动。
```

子任务代验、你自己没复看截图的，照实写「这一条我只核对了证据文件存在，没有逐张复看」。
