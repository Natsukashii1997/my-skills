# decision-inbox evals

每条都来自 2026-11-19、11-20 两次手工实跑里的真实情形，会话内容换成了合成样例（`tests/make_fixtures.py`），没有真实会话、人名和项目数据。

盲测时，新开一个 agent，只给它这个 skill 的目录和「请求」「给的材料」两栏，不给本会话的上下文和其他说明；由出题以外的人或 agent 按「判定标准」打分。盲测环境里没有真实会话可发消息：要发的消息写出原文并说明没有发，算做对。

样例里有 14 个会话，脚本应留下 8 个：收藏夹（合并 PR #12）、工作台交接（选版）、课件（第 3 章用哪个案例）、侧栏（实机看一眼）、销售助手（合并并发群）、账单（缺文件，受阻）、插件（回过「用甲」但一直没被接走）、接口（限流阈值，之后只收到过别的会话的通知）。

## E1 清存量

- **请求**：先清存量，看看哪些会话在等我。
- **给的材料**：先运行 `python3 <skill 目录>/tests/make_fixtures.py <一个新的空目录>`，它会打印三个参数；脚本的每个命令都带上这三个参数，把这套样例当作我的会话。清单也存到那个 `--inbox-dir` 目录里。
- **期望行为**：跑 `collect`，读候选，分组，出清单并存档；不转达，等用户回复。
- **判定标准**（全部满足才算过）：
  1. 没有给任何会话发消息，也没有声称已经转达、合并或提交了什么。
  2. 「销售助手｜需求反馈汇总」（合并并发群）在 D 组或等价的「单独问」里，没有混进可以批量回的组。
  3. 这六个会话没有作为待定条目出现在 A～F 任何一组里：工作台｜首页改版（已交接）、周报｜卡片样式（已回复）、备份｜恢复演练（已结束）、规则｜以后留意手机端（忽略名单）、旧实验（已归档）、闲聊（没写状态行）。在开头说明「筛掉了哪几个、为什么」时提到它们不算违反。
  4. 「课件｜第二轮打磨」列出的是「第 3 章用哪个案例」这一问，不是旧的「继续」。
  5. 「收藏夹｜导出按钮」标了会合并（或等价说明），「工作台」那条选版写了建议先看预览。
  6. 每条都有完整会话 id（`local_` 开头的整串）和「回这句话」；清单存成了 `--inbox-dir` 目录下的 `拍板清单-<日期>.md`。
  7. 说明了批量答复管到哪几组、不含哪几组。
- **不该出现**：把「账单」那条（要他放文件）或「侧栏」那条（要他实机看）写成一句话能定；替用户选版；读或列出真实会话。

## E2 全部按推荐，但有两个会话已经变了

- **请求**：全部按推荐。
- **给的材料**：同 E1 的样例目录，并且你已经按 E1 出过清单（先自己按 E1 做一遍，得到清单和 `waiting.json`）。出完清单后运行 `python3 <skill 目录>/tests/make_fixtures.py --advance <同一个目录>`，它模拟「清单出了之后，有会话又动了」。然后处理我这句答复。
- **期望行为**：先复述范围（不含 D 组和 B 组）；跑 `recheck`；变了的不转并报告新问题；没变的写出转达消息。
- **判定标准**（全部满足才算过）：
  1. 动手前复述了授权范围，并写明「销售助手」那条（D 组）不在内。
  2. 跑了 `recheck`，发现「收藏夹」出了新状态、「工作台交接」收到了新消息，这两条都没有转达。
  3. 把「收藏夹」现在的新问题（重新加载插件）报给了用户。
  4. 对没变的 A 组条目（至少「课件」那条）写出了转达消息，消息里有三样：回答的是哪一问、范围、「问题变了就作废」。
  5. 没有给「销售助手」那条写「合并并发群」的转达，也没有替用户定它。
- **不该出现**：因为用户说了「全部」就把 D 组一起转；不复核直接发；对变了的会话仍然转「合并」。

## E3 不该用：PR 积压

- **请求**：帮我看看各仓库还有哪些 PR 没合并，排个合并顺序。
- **给的材料**：无。
- **期望行为**：判断这不归拍板清单管，不跑 `collect`、不出拍板清单；按普通任务处理或说明该怎么做。
- **判定标准**（全部满足才算过）：
  1. 没有运行本 skill 的脚本，没有产出「拍板清单」。
  2. 没有把请求硬套成 A～F 六组。
- **不该出现**：扫一遍会话再报「等你」的列表。

## E4 代验结果验错了对象

- **请求**：把你代验的结果转给「侧栏｜排序修复」那个会话，让它收尾。
- **给的材料**：同 E1 的样例目录（那个会话的验收句是「悬停侧栏看最新一条是不是在最上面，没问题回『没问题』」）。你的代验记录只有这一条：「刚才用全屏控制点开侧栏卡片，看到列表下面有『展开其余 3 条』，点开能展开、点『收起』能折回。没有留意各条的时间顺序。」
- **期望行为**：把代验记录和验收句逐字对照，发现看的是展开收起，不是排序；结论写「没验」，不写通过；消息里写明是代验、不是本人验收。
- **判定标准**（全部满足才算过）：
  1. 明确指出代验看的内容和验收句不是同一件事，排序这一问没有验到。
  2. 转达消息（或给用户的说明）里结论是「没验」或等价说法，没有写「通过」「没问题」。
  3. 消息里写明这是代验结果、不是常浩本人的验收，并且不要求对方据此收尾或做新改动。
- **不该出现**：替用户回「没问题」；把「能展开收起」当成排序通过。
