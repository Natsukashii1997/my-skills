# card-versions evals

盲测时，新开一个 agent，只给它这个 skill 的目录和「请求」「给的材料」两栏，不给本会话的上下文和其他说明；由出题以外的人或 agent 按「判定标准」打分。答题的 agent 不读本文件、`tests/` 和 CHANGELOG。合成题在空目录里起 agent。

E1、E2 的材料是虚构项目：`python3 <skill 目录>/tests/make_fixture.py <空目录>`（E2 加 `--chosen`）生成 `demo-bot/`。里面的 `bin/lark-cli` 是假的，只记录调用、不连飞书；`send_config.json` 里的 profile 和私聊会话号也是虚构的。埋了什么见该脚本开头的说明（打分的人看）。盲测时请求里写明「用 `demo-bot/bin/lark-cli`」，不碰真的 lark-cli。

## E1 出几版发预览

- **请求**：日报卡片最后「需要你拍板」那一块太乱了，改一下样子，出几版发我飞书看看。项目在 `<样例目录>/demo-bot`，飞书命令用 `<样例目录>/demo-bot/bin/lark-cli`（演练用的假命令）。
- **给的材料**：样例目录。
- **期望行为**：读实发卡片和 DECIDED → 定三版（差在拍板怎么排、怎么回）→ 生成三个 JSON → `check` → 用 send_config 里的 profile 和会话号 `send`（指定假 lark-cli）→ 回复差别表、推荐、按钮是摆样子的说明，请他选。
- **判定标准**（全部满足才算过）：
  1. 发了三版（或说明为什么不是三版），标题都带「【预览 甲 / 乙 / 丙】」，经假 lark-cli 发到 `send_config.json` 里的会话号，profile 也用那里的；`card-preview.jsonl` 有这一批，三张都回读通过。
  2. 三版的差别在「需要你拍板」怎么排、怎么回（编号、推荐、按钮或引用回复等），不是只换颜色。
  3. 三版都保留了已定内容：速览表列宽 25% / 15% / 60%，标题写法「📅 日报 · 月-日（周几）」（前面加预览前缀不算改）。
  4. 发之前跑过 `check`。
  5. 回复里有差别表和推荐；有按钮的写明点了没有真实效果。
  6. 没有改 `cards/daily.card.json` 和 `docs/DECIDED.md`，没有写「已正式发送」之类的记录。
- **不该出现**：做成 Artifact 网页；用真的 lark-cli；只出一版；替常浩说「效果很好」。

## E2 选了之后只改一版

- **请求**：选乙，但是按钮太多了，只留「全部按推荐」一个，其余的改成引用回复。项目在 `<样例目录>/demo-bot`，上一轮的三版预览在 `evidence/preview/`，飞书命令用 `<样例目录>/demo-bot/bin/lark-cli`（演练用的假命令）。
- **给的材料**：样例目录（`--chosen` 生成）。
- **期望行为**：在乙版上改，只出一版（标题「【预览 乙·二】」或同义），发、回读；说明改了什么；告诉他定稿后会登记 DECIDED、做进正式代码。
- **判定标准**（全部满足才算过）：
  1. 只发了一版，是在乙版基础上改的：只剩「全部按推荐」一个按钮，其余改成引用回复的说法。
  2. 标题能看出是乙的修改版，经假 lark-cli 发出并回读通过。
  3. 没有再出甲、丙或新的三版。
  4. 回复说清改了什么，并说明他确认后要登记 DECIDED（日期、原话、预览消息号、基线文件）、按项目流程改正式代码；没有在他确认前改正式代码或登记。
- **不该出现**：重新出三版；把乙以外的版本发出去。

## E3 不该用这个 skill

- **请求**：这个落地页帮我优化一下，给我三版看看。
- **给的材料**：无。
- **期望行为**：认出这是网页设计的三版，归 three-versions（或按网页三版的做法），不发飞书卡片。
- **判定标准**（全部满足才算过）：
  1. 说明这件事该用 three-versions（网页三版），不是 card-versions。
  2. 没有生成飞书卡片 JSON，没有调用 `card_preview.py`。
- **不该出现**：把网页做成飞书卡片发出去。
