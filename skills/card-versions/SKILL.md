# 卡片几版预览

飞书卡片的样子只能在飞书里看：网页模拟不出灰底、折叠、链接和手机上的效果（常浩 2026-11-16 定：直接发真卡片，不做 Artifact）。过去每改一张卡都当场写一段发送和回读的脚本，这个 skill 把这一段收成固定做法和一个脚本。

```bash
P=<本 skill 目录>/scripts/card_preview.py
```

## 0. 硬规矩

- **只发到常浩本人的私聊**，用项目正式发这张卡的那个机器人。不发群、不发别人、不发给别的机器人。私聊会话号和飞书应用（lark-cli 的 profile）从项目里正式发这张卡的脚本或配置里取，不猜、不写进本 skill。
- **预览不算正式发送。** 不写项目里记「今天已发」的那些记录（如 delivery 文件），不触发正式发送的定时任务，不改线上在用的卡片代码。
- **好不好看只有常浩能判。** 回读只证明发到了、是卡片、标题对；不替他下「效果不错」的结论。
- **已定内容不动。** 先查项目的 `docs/DECIDED.md`：这张卡定过的东西（版式、列宽、文字写法），几版都保持不变；某一版要动它，先按改动确认单独问，问完再出。
- **卡片里的数据用真的。** 用这张卡最近一次实发的内容，或项目里现成的事实快照、测试样例；没有就写明是示例数据。

## 1. 吃透现状

- 读这张卡的拼装代码、最近一次实发的卡片 JSON（项目通常留了 `*.card.json` 或发送记录），以及 `docs/DECIDED.md` 里它定过的东西。
- 把常浩这次的意见逐条对到实发卡片上：哪一块、现在什么样、他要什么。对不上的、说得含糊的，先问。
- 判断该不该出卡片：内容结构（有哪几块、每块讲什么）还没定时，先用文字把结构发给他确认，不出卡片。

## 2. 定几版

- 默认三版，叫甲、乙、丙。常浩说了几版就出几版，说「只给我一版」就一版。
- 几版的差别在**信息怎么排、他怎么回**（分块方式、表格还是列表、按钮还是引用回复），不在换颜色、换图标。
- 几版之间不同的地方，写成一张差别表，等会儿回复用。

## 3. 生成卡片

- 用项目自己的卡片零件生成（如数字分身的 `card_parts.py`），不另写一套样式。每版存一个 JSON 文件，放项目约定的证据目录。
- 发之前先检查：

  ```bash
  python3 "$P" check 甲.json 乙.json 丙.json
  ```

  报「不能发」的（没标题、正文组件超过 199 个）先改。提醒里说有按钮的，回复里要写明「预览卡上的按钮点了没有真实效果」。

## 4. 发到私聊并回读

```bash
python3 "$P" send --card 甲.json --card 乙.json --card 丙.json \
  --profile <项目发这张卡用的 lark-cli profile> --chat-id <常浩和这个机器人的私聊 oc_…> \
  --out <项目证据目录>
```

- 脚本给每张卡的标题加「【预览 甲】」这样的前缀，以机器人身份发出，逐张回读核对三样：是卡片、在这个私聊里、标题对得上；发送记录追加到 `<证据目录>/card-preview.jsonl`。
- 退出码 `0` 全部回读通过；`1` 有一张没发出或回读对不上（输出里写了哪张、为什么），先查原因，同一批重跑不会重复发（按卡片内容算幂等键）；`2` 卡片本身不能发，或参数不对。
- 先 `--dry-run` 看一眼会发什么也可以。

## 5. 回复常浩

- 一句话：几版已发到哪个私聊、回读都通过（或哪张没通过）。
- 差别表：每版一行，写这版怎么排、他怎么回、适合什么情况。
- 推荐一版并说一句理由；有摆样子的按钮、示例数据的，写明。
- 请他回「选甲」「乙，但是……」。

## 6. 他选了之后

- **选了一版、还要改**：只在选中那版上改，出一版，标题写「【预览 乙·二】」，用同样的办法发、回读。不再出三版。回复里写清改了什么，并说明他回「定稿」之后会做哪两件事：在 `docs/DECIDED.md` 登记（日期、定了什么、他的原话、预览消息号、基线卡片 JSON 路径），以及按项目的 issue、分支、PR 流程改正式代码。他回之前这两件都不做。
- **卡片正文的字要和预览对得上。** 按钮是摆样子的，卡片上就不要写「点按钮就算定了」这类话；要写回法，写成定稿后的样子，并在回复里说明预览阶段点了无效。
- **都不满意、也说了怎么改**：在他指的那版（没指就是现状）上照改一版重发；没说怎么改，先问差在哪。
- **定稿**：照项目流程把选定的版式做进正式代码（项目里正式改卡片是另一件事，按项目的 issue、分支、PR 走）。定稿当轮在 `docs/DECIDED.md` 登记：日期、定了什么、他的原话（如「选乙」）、预览消息号（在 `card-preview.jsonl` 里）、基线卡片 JSON 的路径。项目有卡片的整卡快照测试（如数字分身的 `test_card_bytes.py`）的，把定稿版补进快照。
