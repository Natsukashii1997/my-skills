## 0.3.0 - 2026-11-27

来源：agent-kit 深度梳理方案第五项（agent-kit PR #128），my-skills#135。

- 修复：取用户原话的 4 个过滤漏洞，每个都用 2026-11-13～11-26 本机真实记录的结构做了回归样例（`tests/fixtures/claude_origin`、`codex_exec`）。
  1. 首块是应用注入的 `<system-reminder>` 的真人消息整条被丢掉：现在先剥掉提醒再判断。
  2. 没有 `origin` 字段的记录全放行，side-session 首条任务、CI 事件、`claude -p` 派单被当成用户原话：现在看 `turnOrigin`、`entrypoint`。
  3. 驿窗侧栏（`origin.name=agent-hud`）整类被跳过：现在取 `pluginPrompt.text`，排除 ChatGPT 回送（审核意见、思维评审回信）、接力出错通知和别的 agent 经驿窗发来的消息。
  4. Codex `codex exec` 派单的「用户消息」被当成用户原话：现在按 `originator=codex_exec` 跳过，工具调用照常统计。
- 修复：所有用户消息跨文件按 `uuid` 去重（分叉会话复制旧记录）。以前只对命中纠正 / 决定的消息去重。
- 新增：第五类信号「重复」（`signals.md` 第四节、`signals.json` 的 `signals.repeats`）：亲手短话（≤ 20 字）聚类，≥ 5 次列出，标出等于上一轮 wrap_up 按钮、等于推荐按钮的次数和来源（输入框 / 驿窗侧栏 / Codex）；长消息里同一段出现在 ≥ 3 条消息里的列出。
- 新增：D 类提案「自动化」。
- 改动：不带 `--out` 时，默认目录里已有上次的 `signals.json` 就改写到 `<目录>-2`（依次加号），不再静默覆盖上次复盘的信号文件。盲测 E2 踩到。
- 新增：用户原话事件带 `channel`；覆盖统计加 `non_human_messages_skipped`、`agent_hud_relays_skipped`、`dispatch_messages_skipped`。
- 改动（盲测第 1 轮后）：出处写全路径；用 `context` 查到的行可作依据，标「（context）」；D 类的重复信号要按来源拆分，按意思合组的要逐个列说法；硬规矩加「不动任何仓库」。
- 改动（盲测第 2 轮后，常浩 2026-11-27 选「甲」）：来源拆分从 D 类挪成通用写法「引用重复次数」，提案任何位置和对话里写到 S 组次数都要带拆分，交付回读逐处查；`scan` 加 `--short-min`（默认 5），不用再写包装脚本改门槛。
- 改动（盲测第 3 轮后）：示例数字换成虚构的（原来用的就是 E2 的答案）；SKILL.md 不再链接 evals.md，盲测改给去掉 evals.md 的副本；「引用重复次数」写明合组结论、分段补扫也要拆；D 类写明全局指令、DECIDED、《工程流程》都算已定内容；`提案.md` 写完设为仅本人可读。
- 改动（盲测第 3 轮后，常浩 2026-11-27 选「甲：收窄规则加机检」）：「引用重复次数」从处处都拆收窄为每组全窗口次数第一次写到时拆，合计、分段、再提只写数字；新增 `check` 子命令查提案里的来源拆分，交付回读必跑；E2 判定同步。
- 修复（盲测第 4 轮评分后）：`check` 不再把「（2 次等于推荐）」这种没有来源的括号当成拆分；帮助文字和 SKILL.md 写明它认不出的写法、查不出次数本身写错。
- 修复（ChatGPT 工程审查第 1 轮）：`check` 名字和次数之间只许空格、冒号、「共」，「5 个会话」「5 个项目」不再当成次数；来源拆分逐项解析，同一来源写两次、来源名认不出都报；默认输出目录用独占创建的占位文件预留，两个扫描同时跑不会写进同一个目录。
- 清理：本仓库是公开的，文档、评测记录、测试注释里的本机真实统计全部去掉，评测期望数字改放仓库外的 `~/session-retro/evals-本机答案.md`；E2 判定改为每一条 D 类都要写全。
- 改动（E2 在 第 7 版 上复测后）：D 类重复信号的写法和「第一次写到时带拆分」对齐：列 S / L 编号，单组写次数和等于按钮、等于推荐，合组写合计和合计的等于按钮、等于推荐；E2 判定同步（上一版判定要求每条 D 类都写拆分，和收窄后的规则冲突）。已定内容补上项目 AGENTS 约定、ADR、合并策略的安全约束。
- 新增（E2 复测又漏 D 类字段后）：`check` 一并查 D 类五项，以及重复信号里有 S 组时等于按钮、等于推荐都写出来（为 0 也写）；格式示例改成合规写法。
- 改动（常浩 2026-11-27 定「对齐规则」）：E2 判定第 1 条的对话部分改成「写到哪一组的全窗口次数，第一次就带拆分」，不再要求对话里非写「合并」不可。
- 修复（ChatGPT 工程审查第 2 轮）：`check` 数字后面要么是「次」，要么紧跟标点、括号或行尾，「5 条消息」「5 %」不再当次数；括号里一个合法来源都没有、但叫法像来源的（「侧栏 5」）报认不出的来源；D 类重复信号要列 S / L 编号（子项里列也算），等于按钮、等于推荐后面要有数字；默认目录占位改在 `finally` 里交还；脚本注释里的示例数字换成虚构的。
- 修复（ChatGPT 工程审查第 3 轮）：`check` 的「次」后面也要紧跟空白、标点、括号或行尾（「5次以上」「5次/周」不算）；半角括号的拆分也认；写错的来源改按「每项叫法 + 数字、加起来等于这一组次数、叫法不是这一组的项目名」判，不再用词表；D 类只认没有缩进的顶层字段；骨架注明示例数字是虚构的。
- 修复（ChatGPT 工程审查第 4 轮）：`signals.json` 每组短话加 `project_names`（完整项目名单），`check` 判「按项目拆分」用完整名单；旧版 signals 没有完整名单且前 5 个已满时不据此报；「等于按钮」「等于推荐」这两个统计说明不当成来源（第 5 轮 P2-08：只认这两个确切的词，别的「等于…」叫法照样报）。
