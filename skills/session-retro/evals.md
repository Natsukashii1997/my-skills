# session-retro evals

存量 skill 补的评测题（0.3.0，2026-11-27）。请求来自常浩的真实说法；窗口和项目名是真实可跑的，跑的是本机记录。本仓库是公开的：本机跑出来的真实次数、原话、提案片段一律不写进本文件，期望数字放仓库外的 `~/session-retro/evals-本机答案.md`。

盲测时，新开一个 agent，只给它这个 skill 目录的一份副本（去掉本文件，放在临时目录里）和「请求」「给的材料」两栏，不给本会话的上下文和其他说明；由出题以外的一方按「判定标准」打分。第 3 轮发现执行者能 grep 到本文件里的期望答案，所以要去掉；skill 的示例数字也不能用本机真实数据。

## E1 一周复盘（最常见）

- **请求**：复盘一下最近一周的会话，看看我老纠正 AI 什么。
- **给的材料**：无
- **期望行为**：用默认窗口（最近 7 天）跑 `scan`；读 `signals.md` 四节；对拿不准的信号用 `context` 看上下文；写 `提案.md`，按 A/B/C/D 分类，每条附出处和对照结论；对话里结论先行，不贴整份提案。
- **判定标准**（全部满足才算过）：
  1. `提案.md` 写在输出目录（不在 git 仓库里），每条提案都有「文件:行号（时间）」出处，且能在 `signals.md` 里找到；标了「（context）」的，用 `context` 子命令能查到。
  2. A、B 类每条都有层级五项。
  3. 没有修改任何 CLAUDE.md、AGENTS.md、LESSONS.md 或 Vault 文件。
- **不该出现**：直接 `cat` / `grep` 原始会话文件；把驿窗回送的「ChatGPT 对「…」的审核意见」当成用户的纠正。

## E2 重复回的话（新功能）

- **请求**：看看我这两周老是重复回 AI 什么，哪些可以不用我回。
- **给的材料**：窗口 2026-11-13 到 2026-11-26（含）。
- **期望行为**：`scan --start 2026-11-13 --end 2026-11-27`；读第四节「重复」；按次数和「等于推荐」占比挑出高频放行短话；出 D 类提案，每条写重复信号、常浩在替 AI 做什么、建议做法（改规则 / skill / 钩子或定时任务）、落点、怎么量。
- **判定标准**：
  1. `提案.md` 里给出「合并」的全窗口次数，第一次写到时区分了输入框和驿窗侧栏两个来源，数字和 `signals.md` 一致；对话答复里写到哪一组的全窗口次数，第一次就带来源拆分（只写合组合计不算写到某一组，不要求非写「合并」不可；常浩 2026-11-27 定，和「引用重复次数」规则对齐）（本机的期望数字放在仓库外的 `~/session-retro/evals-本机答案.md`，不进仓库：本仓库是公开的）；`check` 子命令对 `提案.md` 通过（退出码 0）。
  2. 至少一条 D 类提案，而且每一条 D 类都写全五项：重复信号列了涉及的 S / L 编号，单组的写了次数、等于按钮、等于推荐，合组的写了合计和合计里的等于按钮、等于推荐（各组来源拆分按「第一次写到时带」，在总表等处写过就算，不要求在 D 类里重复；L 组只看条数和会话数）；涉及改已定内容的（含项目 AGENTS 约定、ADR、合并策略的安全约束），都注明要先发改动确认。
  3. 只出提案，没有改任何规则、钩子或定时任务。
- **不该出现**：把 side-session 首条任务（「Background (from the session that started this one)」）或派单内容算成常浩的话。

## E3 不该用（单个项目的事后复盘）

- **请求**：帮我复盘一下这次驿窗 v0.3 发版出的事故，写个事后报告。
- **给的材料**：无
- **期望行为**：说明这是单个项目的事后复盘，不归 session-retro；不跑扫描，按一般事故复盘的做法问清材料或直接做。
- **判定标准**：
  1. 没有调用 `session_retro.py scan`。
  2. 说明了不用这个 skill 的原因。
- **不该出现**：产出 A/B/C/D 提案。
