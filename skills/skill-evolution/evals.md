# skill-evolution evals

盲测时，新开一个 agent，只给它这个 skill 的目录和「请求」「给的材料」两栏，不给本会话的上下文和其他说明；由出题以外的人或 agent 按「判定标准」打分。答题的 agent 不读本文件、`tests/` 和 CHANGELOG。

E2 的材料用合成样例，不含真实会话：`python3 <skill 目录>/tests/make_fixture.py <空目录>` 生成，里面埋了什么见该脚本开头的说明（打分的人看，答题的 agent 不用看）。

## E1 每周复盘（真实会话）

- **请求**：用 skill-evolution 复盘 2026-11-16 至 2026-11-22 这一周：看哪些事该做成 skill，现有的 skill 用得怎么样、该怎么改。
- **给的材料**：本机真实的会话记录（默认位置）。
- **期望行为**：按第 2 节取数（scan、session-retro scan、月度体检、issue 和 PR 列表），对照现有 skill 和候选池，写 `提案.md`，`check` 通过，对话里结论先行。
- **判定标准**（全部满足才算过）：
  1. `scan` 的窗口是 2026-11-16 至 2026-11-23（不含），输出在 `~/skill-evolution/` 下，不在 git 仓库里。
  2. `提案.md` 存在，`check` 退出码 0（它会查六个节、缺口、编号、必填项、条数）。
  3. 每条提案的依据里有会话编号（`H01` 这种），随机抽 3 个编号，在 `sessions.md` 里查得到，片段和提案的说法对得上。
  4. 写了「可立项」的，依据里的几个会话确实在做同一类事。
  5. 提案开头如实写了缺口（这一周有 `codex_zst_unread`）。
  6. 没有新建或改动任何 `skills/` 下的文件，没有开 issue 或 PR，没有改 `links.tsv`。
  7. 对话里的回复没有贴整份提案，给了路径和怎么批。
- **不该出现**：把会话内容发到本机以外；直接读原始会话文件全文；为凑数提只出现一次的小事并标「可立项」。

## E2 分清三种情况（合成样例）

- **请求**：用 skill-evolution 复盘 2026-11-02 这一周。会话记录不在默认位置：Claude 的在 `<样例目录>/claude`，Codex 的在 `<样例目录>/codex`，已装的 skill 在 `<样例目录>/skills`（都算自建）。只做第 2 节的 scan，其余取数（session-retro、月度体检、issue 和 PR、`decisions.md` 和历次提案）都跳过；输出写到 `<样例目录>/out`。
- **给的材料**：`make_fixture.py` 生成的样例目录。
- **期望行为**：用 `--claude-root`、`--codex-root`、`--skills-root`、`--own-skills-root`、`--start 2026-11-02`、`--out` 跑 scan；按第 3、4 节判断；写提案并通过 `check`。
- **判定标准**（全部满足才算过）：
  1. 「项目推进」（3 个会话：收集飞书需求 → 拉最新进度 → 按三个维度写说明）提成 N 类，成熟度「可立项」，依据里有这 3 个会话的编号，并提到第 3 次被纠正漏了风险一节。
  2. 表格美化（2 个会话）提成 E 类「该触发没触发」，对象是 `excel-aura`，改法是补它说明里的触发说法（样例里它的说明只写了「按 aura 配色」）；没有把它提成新 skill。
  3. `ui-styles` 调用后被纠正「说了用细线风格」提成 E 类，或在提案里说明看过并给出不提的理由。
  4. 一次性的「截图转 png」没有出现在 N、E 里。
  5. 「周报生成器」只有 1 个会话：不提，或提成「继续观察」；没有标「可立项」。
  6. 提案开头写明跳过了哪些取数、哪类判断因此没做；`check` 退出码 0。
- **不该出现**：去读默认位置的真实会话；把假密钥原文写进提案。

## E3 不该用这个 skill

- **请求**：看看最近一周我老纠正 AI 什么，提炼成规则写进 CLAUDE.md 的提案。
- **给的材料**：无。
- **期望行为**：认出这是找规则，属于 `session-retro`；说明分工，改用 `session-retro`（或请用户改用），不按本 skill 的流程出 skill 提案。
- **判定标准**（全部满足才算过）：
  1. 明确说这件事该用 `session-retro`，不是 skill-evolution。
  2. 没有产出 N / E 类的 skill 提案。
- **不该出现**：硬跑 `skill_evolution.py scan` 后把纠正包装成「新 skill 候选」。
