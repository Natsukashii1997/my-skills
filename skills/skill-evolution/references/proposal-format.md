# 提案.md 的格式

写在输出目录下，和 `sessions.md` 放在一起。整份文件只给常浩本人看，不外发。

## 骨架

下面的会话编号、次数、skill 名都是虚构的示例。

```markdown
# skill 进化提案：2026-11-02 至 2026-11-08

- 覆盖：有真人发话的会话 42 个（Claude 35、Codex 7），项目 proj-alpha、proj-beta 等 6 个
- 缺口：codex_zst_unread=3（Codex 有 3 份已压缩的记录没读到，Codex 上的活可能没看全）；没取到 issues.json（没网），候选池没对照
- 结论：新候选 2 条、改进 2 条；最值得做的是 N1

## 一、最值得做的

1. **N1 项目推进说明**：同一套三步做法这周做了 3 遍，每遍都从头讲，第 3 遍还被纠正漏了「风险」一节。
2. **E1 excel-aura**：两次美化表格都没用上它，说明里少了「美化一下」这种说法。

## 二、新 skill 候选

### N1 项目推进说明（暂定名 project-push）

- **做什么**：常浩说「推进一下 XX 项目」时，先收集飞书群里这周的需求反馈，再拉多维表格里的最新进度，然后按功能、风险、下周计划三个维度写一份推进说明。输入：项目名、群、表；判断点：哪些反馈算需求、哪些只是提问；输出：一份三节的说明。
- **依据**：S01、S02、S03 三次走法一致（都是 lark-cli 查消息 → 查表 → 写文档）；S03 里被纠正「风险要单独列一节，上次就说过了」（行 12）。
- **成熟度**：可立项
- **为什么是 skill**：步骤固定，但哪些反馈算需求、怎么归到三个维度每次都要判断，脚本做不了；不是到点就做的事，由常浩发起。
- **和现有 skill 的分工**：business-notice 只管成稿的语气和发送前预览，不管去哪收集、按什么维度组织；这个候选产出初稿后可以交给它成稿。
- **怎么做**：开立项 issue 写边界 → 把三次会话里一致的步骤写成 SKILL.md，三个维度的写法各放一个例子 → 拿 S01–S03 的原始请求当 evals（另加一条不该用的）→ 审计、盲测、PR。约半天。
- **推荐**：做

### N2 周报生成器（暂定名 weekly-gen）

- **做什么**：……
- **依据**：S09 一次。
- **成熟度**：继续观察（只出现 1 次，下周再有同类会话就够立项）
- **为什么是 skill**：……
- **和现有 skill 的分工**：……
- **怎么做**：先开候选 issue 记一笔，不动手写。
- **推荐**：观察

## 三、现有 skill 改进

### E1 excel-aura：该触发没触发

- **skill**：excel-aura（自建，1.0.0）
- **问题**：该触发没触发
- **依据**：S05、S06 的起始请求都是「把这张表美化一下，配色舒服点」，两个会话都没有调用它，改用了临时写的脚本。
- **改法**：`description` 原句「用户说『按 aura 配色』『把表格做好看』时使用」→ 加上「美化一下这张表」「配色别太刺眼」。
- **推荐**：做

## 四、上次的提案现在怎样

- N2（2026-10-26 周，继续观察）：这周又出现 1 次（S09），累计 2 次，已升为本周的 N2。
- E3（2026-10-26 周，常浩批了「做」）：PR #88 还开着，没合并。

## 五、转交（不适合做成 skill 的）

- 「合并前先跑全量测试」被纠正 2 次（S14、S17）：是规则，建议跑一次 session-retro。
- 每天早上手动查一遍服务状态（S20、S21、S22）：每步都确定，该做成定时任务，不是 skill。

## 六、筛掉的

看过但没提的 5 组：一次性的小事 3 组；已有 skill 覆盖而且用上了的 2 组。

---
怎么批：回复「做 N1、E1」「N2 继续观察」「都不要」。
```

## 写法要求

- **编号**：新候选 `N1`、`N2`……，改进 `E1`、`E2`……，标题用三级标题 `### N1 名字`。两类加起来不超过 7 条。
- **必填项**，每项一行，写成 `- **名字**：内容`，`check` 会查：
  - N 类：做什么、依据、成熟度、为什么是 skill、和现有 skill 的分工、怎么做、推荐
  - E 类：skill、问题、依据、改法、推荐
- **依据**里必须有 `sessions.md` 里的会话编号（`S01` 这种），让常浩能回到出处。引用原话用清单里已脱敏的片段，加行号。跨周累计的写候选 issue 号（`#123`）。
- **成熟度**以「可立项」或「继续观察」开头。「可立项」要有 2 个以上会话编号，或 1 个会话编号加 1 个候选 issue 号。
- **做什么**要写出输入、步骤、判断点、输出，让没看过会话的人知道这个 skill 会干什么。
- **怎么做**写到能直接开工：下一步是什么、拿哪几个会话当 evals、大概多大的活。
- **改法**尽量给原句和改后的句子；改动大的写清改哪一节、加什么。
- **推荐**只写「做」「观察」「不做」之一，后面可以跟一句理由。
- 空的节写「无」。六个节的顺序不变。
- 没有任何值得提的：一、二、三节都写「无」，结论写「本周没有值得做的」。
