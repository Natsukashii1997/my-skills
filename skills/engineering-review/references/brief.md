# 送审包怎么写

ChatGPT 读不到本机文件，但装了 GitHub 连接器，能自己打开 PR。送审包要让它不问任何问题就能开审。

## 1. 首次送审

```
<项目>｜<任务短名>（风险级 Lx：<一句话说明为什么是这一级>）

PR：<被审 PR 的完整链接>          ← 必须是全文第一个 PR 链接
分支：<分支名>；repo：<owner/repo>；base_sha：<完整 SHA>；head_sha：<完整 SHA>；关联 issue #<号>

## 1. 目标
<这次改动要解决什么，一两句；来由写到 issue 或常浩原话>

## 2. 改了什么、为什么
<按文件或模块列，每条一句「改了什么 + 为什么这样改」；刻意没做的也写>

## 3. 测试
<命令 + 原样结果（通过数、失败数）；实测了什么；写明哪些是你本机跑的>

## 4. 改动本身
<diff 原文；太长就写摘要 + 关键片段，完整改动让它看 PR>

## 5. 希望重点看
<2–4 条，最担心出错的地方，具体到函数或规则>

请按严重程度（P0–P3）列问题，回信最后两行依次写「审查出口：通过 / 返修 / 证据不足暂停 / 决策升级」和「结论：通过 / 需修改」（通过配通过，其余配需修改）。
```

要点：

- `base_sha`、`head_sha` 用 `git rev-parse origin/main HEAD` 取完整值，送之前确认 HEAD 已推送。
- 第一行写清风险级和理由。理由站不住，审查方会先质疑定级。
- 「刻意没做的」写出来，比如没安装、没发布、留给另一张单的事，免得被当成遗漏。
- 本会话之前送过别的审查时，在 `PR：` 那一行**之后**加一句「这是新的 PR，和本会话之前审过的那一单分开」。旧 PR 不写链接，也不写 `owner/repo#号`，最多写项目名，免得驿窗把它当成被审 PR、轮数接错。如果两单相互无关、又担心旧内容干扰判断，就换一个会话送。

## 2. 续审（预算还有，回信是「返修」）

不重发整份，只写这一轮变了什么：

```
<项目>｜<任务短名>（风险级 Lx｜第 N 轮：只验收第 N-1 轮意见的处理）

PR：<同一个 PR 链接>
head_sha：<新的完整 SHA>（上一轮审的是 <旧 SHA 前 8 位>）

## 本轮处理
| 意见 | 处理 | 位置 / 证据 |
|---|---|---|
| P1-01 … | 采纳：… | 文件:行，新增测试 … |
| P2-02 … | 不采纳：… | 反证 … |

## 测试
<全量测试原样结果>

## 增量 diff
<只贴本轮改动>

请只核对上面的处理是否到位，不做全面复审；回信最后两行同首次送审。
```

## 3. 超预算续审（常浩已授权）

`extra` 填「常浩要求再审一次：<原因>」。第一行写「第 N 轮（超出预算，常浩已授权）｜只验收 <常浩指定的范围>」，正文同续审。范围按常浩说的，不扩大。

## 4. 外发核对

送出前过一遍：送审包和 PR 里不放凭据、token、私人数据；知识库里标为受限或没标注敏感度的内容，不放原文，改写成结论或写「此项在本地核实」。
