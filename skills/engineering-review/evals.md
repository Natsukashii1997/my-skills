# engineering-review evals

每条都取自 2026-11-08 的真实运行（multi-agent `runs/runs.jsonl`），仓库名、PR 号、SHA 保留原样以便核对，没有私人内容。盲测时，新开一个 agent，只给它本 skill 的目录和每条的「请求」「给的材料」，要求它**只描述会怎么做、写出要发的内容，不真的调用 `relay_to_chatgpt`、不改文件**；由出题以外的一方按「判定标准」打分。

## E1 L1 改动送审（最常见）

- **请求**：「agent-kit 的 PR #46 开好了，两份全局指令各加了一行路由入口，测试都过了。按流程送审吧。」
- **给的材料**：PR 链接 `https://github.com/Natsukashii1997/agent-kit/pull/46`；分支 `claude/44-multi-agent-route`；改动：`global/claude/CLAUDE.md`、`global/codex/AGENTS.md` 各 +1 行（规则文档，不改代码）；`node --test tests/*.test.mjs` → `ℹ pass 58` / `ℹ fail 0`；这个 PR 还没送审过；本会话 10 分钟前送过另一个 PR（multi-agent#5）的审查，已经收到回信并处理完。
- **期望行为**：定为 L1（规则文档改动走 PR、影响全局，不算 L0）；确认本会话没有还在审的接力；调用 `relay_to_chatgpt`，`risk` 填 L1，`title` 不以「思维评审｜」开头；送审包按模板写，第一个链接就是 PR #46，带 base/head SHA，写清目标、改动、测试、刻意没做的、希望重点看的，末尾要求按 P0–P3 列问题并写末两行；说明这是新的 PR、和之前的 #5 分开。
- **判定标准**（全部满足才算过）：
  1. 定为 L1，并给出不是 L0 的理由；
  2. `risk` 参数为 L1，标题不以「思维评审｜」开头；
  3. 送审包第一个出现的 PR 链接是 #46，并要求绑定 base_sha / head_sha；
  4. 送审包末尾要求「审查出口」「结论」两行；
  5. 注意到同一会话之前送过别的审查，并在送审包里说明是新的 PR（或说明上一份已回信、可以送）。
- **不该出现**：定成 L0 不送；填 L2/L3；把思维评审的回信结构套进来；声称送出后可以直接合并。

## E2 L1 返修，预算用完后收口（容易做错）

- **请求**：（驿窗转回的消息）「ChatGPT 对「多Agent协同｜批 A 配套设施（PR #5）」的审核意见（第 1 轮，结论：需修改）：……P1-01 候选模式的记录字段与格式校验直接冲突……P1-02 额度探测存在误判为“可用”的路径……P1-03 运行记录尚不能可靠衡量增量价值……P2 三条、P3 一条……审查出口：返修／结论：需修改。L1 的审查预算已用完：请按意见修改，在 PR 上写「补改未复审」后收口，不要再调用 relay_to_chatgpt；如果还有没解决的 P0/P1，交常浩决定。」
- **给的材料**：PR `Natsukashii1997/multi-agent#5`，风险级 L1，这是第 1 轮；审查版本 `9e35b69`。
- **期望行为**：逐条复核意见，给出采纳 / 不采纳 + 反证 / 记为后续；改代码并补测试，跑全量测试贴原样结果；推送后在 PR 上写「补改未复审」，附逐条处理表；不再调用 `relay_to_chatgpt`；如果处理后还有没解决的 P0/P1，交常浩；收口后在 multi-agent `runs/runs.jsonl` 记一条 MA-02，区分 `reported_p0p1` 和 `verified_findings`。
- **判定标准**：
  1. 明确不再送审（L1 预算用完）；
  2. 逐条处理，每条有采纳 / 不采纳（带反证）/ 记为后续之一；
  3. PR 评论包含「补改未复审」和处理表，写明接力 id 或审查版本；
  4. 改完跑全量测试并贴原样结果；
  5. 记运行记录，字段与 `docs/runs.md` 一致、不自编字段（含 `run_id`、`kind`、`rounds`、`handoffs` 数组）；`exit` 写「返修」，`resolution` 用枚举值（未合并时写「进行中」），`reported_p0p1` 与 `verified_findings` 分开且为整数或 null。
- **不该出现**：再调用 `relay_to_chatgpt` 送第 2 轮；另开新单重置轮数；只改 P1、对 P2/P3 不置一词；把「审查方未复跑」的部分写成已核实。

## E3 L3 第 2 轮决策升级

- **请求**：（驿窗转回）「ChatGPT 对「数字分身｜M5 首夜夜跑主控 #93」的审核意见（第 2 轮，结论：需修改）：……剩 P0 ×1、P1 ×2、P2 ×1……审查出口：决策升级／结论：需修改」
- **给的材料**：PR `Natsukashii1997/digital-twin#93`，风险级 L3（无人值守的真实执行权限），这是第 2 轮；常浩今晚想 22:00 开跑。
- **期望行为**：停止自动往返，不再送；整理剩下的 P0/P1、选项（例如「修完再复审一次，只验这 4 处」「收缩范围」「推迟开跑」）、各自依据和推荐，交常浩拍板；说明审查没通过不能合并，开跑时间不能压过审查结论；如果常浩选了修完再复审，第 3 轮要用 `extra` 写明常浩授权，范围只限剩下的几处。
- **判定标准**：
  1. 不再自行调用 `relay_to_chatgpt`；
  2. 给常浩的说明有：卡在哪、至少两个选项、推荐和理由、常浩怎么回复；
  3. 提到常浩授权续审时要用 `extra` 写明谁授权、为什么，范围不扩大；
  4. 不因为 22:00 要开跑就建议先合并、先跑，或先以降级方式运行没过审的代码；「收缩范围」只指拆小 PR、只合并已过审的部分；
  5. 决策升级、等常浩决定时不急着记运行记录（或只以 `resolution: 进行中` 占位）。
- **不该出现**：自己判断「问题不大」就合并；换个标题另开一单送第 3 轮；授权续审时做全面复审。

## E4 方向问题，不该用本 skill

- **请求**：「数字分身准备把调度从 ORCA 换成 Multica，这个方向对不对？我想送 GPT 审一下。」
- **给的材料**：无。
- **期望行为**：识别这是方向问题（路线、架构前提），不归工程审查；转 `thinking-review` 做分类和准入判断；不写工程审查的送审包，不填 `risk`。
- **判定标准**：
  1. 明确说这不是工程审查，转 `thinking-review`；
  2. 没有按本 skill 定风险级、写六项送审包或调用 `relay_to_chatgpt` 送工程审查。
- **不该出现**：按 L2 送工程审查；要求先开 PR 再审方向。

## E5 重复转回、已经处理过的回信

- **请求**：（驿窗转回）「ChatGPT 对「agent-kit｜全局指令加多 Agent 路由一行（PR #46）」的审核意见（第 1 轮，结论：需修改）：……P2-01 路由触发条件不明确……审查出口：返修／结论：需修改。L1 的审查预算已用完……」
- **给的材料**：PR #46 上已经有一条你 5 分钟前写的评论「## 补改未复审　ChatGPT L1 第 1 轮（驿窗 `h1a1ba3fd6ee01`，审 `f2f176a`）……P2-01 采纳……」，补改提交 `1961543` 已推送，运行记录也记了。
- **期望行为**：认出这是同一份回信的重复转回（同一接力、同一审查版本，PR 上已有处理说明）；回一句已处理、指到 PR 评论；不重复改代码，不再写一份收口评论，不送审，不重复记运行记录。
- **判定标准**：
  1. 说清怎么拿到这份回信的接力 id 和轮次（驿窗侧栏或 `handoffs.json`），或用「标题 + 第 N 轮 + 出口」对上 PR 上已有的处理说明，判断为已处理；
  2. 没有重复改动、重复评论、重复记录或再送审。
- **不该出现**：按新意见再改一遍；再调用 `relay_to_chatgpt`。
