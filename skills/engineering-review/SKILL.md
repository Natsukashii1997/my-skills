# 工程审查

让实现者以外的一方判断「这次改动能不能被接受」，并且**按风险结束**，不无限往返。

规则的唯一真源是 multi-agent 的 MA-02 契约：`/Users/nat/Documents/ChatGPT/个人/work/multi-agent/modes/MA-02-engineering-review.md`（风险分级、审查预算、四档出口、停止条件、人工必须决定的事）。本 skill 只写怎么做；两边有出入时以契约为准，并告诉常浩。

角色：Claude（或当前执行的 agent）实现、自测、送审、返修、收口；ChatGPT High 经驿窗做独立审查；常浩授权合并、决定超预算后的去向、授权 L3 的动作。**审查通过不等于可以合并**，合并只听常浩说「合并」（或项目已批准的自动合并规则）。

## 1. 用不用

| 当前要解决的 | 去向 |
|---|---|
| 实现对不对：代码、脚本、配置、规则文档的改动能不能被接受 | 本 skill |
| 方向对不对：问题定义、目标、路线、架构前提 | `thinking-review`（它判成 B 类的，转回本 skill） |
| 只想在本地按项目规范和需求查一遍差异 | `/code-review` |
| 只缺可运行的证据（没跑过、跑不了） | 先补测试或实测，不靠多审一轮补证据 |
| 不改变行为的纯文档、记账（L0） | 只做机械检查（测试、格式、链接），不送审 |

## 2. 第一步：定风险级

送审前先定级，写进送审包第一行，并在调用时填 `risk`。定义沿用 DT-ORC ARCHITECTURE「风险分级」，拿不准就往高定一级：

| 级别 | 什么样的改动 | 自动审查预算 | 送审前要有 |
|---|---|---|---|
| L0 | 不改变代码行为的管理文档、记账（CURRENT、交接记录、证据说明）。写进架构基线的执行身份、授权、合并规则**不算** L0 | 0 轮，不送 | 机械检查 |
| L1 | 小范围、低风险的代码或规则文档 | 1 轮 | 自测和增量证据 |
| L2 | 标准研发、跨文件的非敏感功能 | 最多 2 轮 | 自测、回归 |
| L3 | 身份、安全、持久状态、正式系统、不可控副作用 | 最多 2 轮 | 前置风险分析、必要的独立验证、常浩的动作授权 |

- **L1 也可以不送**：有充分的测试证据（例如隔离环境复跑全过），常浩决定跳过送审时，在 PR 或交接里写明「谁决定的、为什么」。不能自己决定跳过。
- 预算按**同一个 PR** 跨会话累计：换 head、另开一单、换会话都**不清零**。送之前先确认这个 PR 已经审过几轮。

## 3. 送审

送之前过一遍：

1. 改动已提交并推送，PR 已开，测试结果是这一版跑出来的。
2. **本会话没有还在审的接力**。同一个 Claude 会话的所有送审都进同一个 ChatGPT 对话，上一份没回信就送下一份，两份会混在一起。先等上一份回信，或换一个会话送。
3. 预算还有剩余（第 2 节）。用完了不送，见第 6 节。

然后调用 `relay_to_chatgpt`：

- `title`：「<项目>｜<任务短名>（PR #号）」。**不要用「思维评审｜」开头**，那是另一套协议。
- `risk`：第 2 节定的级别（L1–L3；L0 会被拒收）。
- `summary`：一句话，例如「改了 6 个文件 · 测试 58 全过」。
- `brief`：按 [references/brief.md](references/brief.md) 的模板写。ChatGPT 读不到本机文件，送审包要自己写全；被审的 PR 链接必须是送审包里**第一个**出现的 PR 链接（驿窗靠它跨会话累计轮数），并绑定 `repo / base_sha / head_sha`。
- `extra`：只在预算用完、常浩明确要求再审时填（第 6 节）。

发出后不轮询，回信由驿窗转回本会话。等的时候可以做和这次审查无关的事。

## 4. 处理回信：逐条判断，不照单全收

驿窗转回的消息以「ChatGPT 对「…」的审核意见（第 N 轮，结论：…）」开头，末尾附一句处理话术。先看两件事：

- **这份回信处理过没有**：转回的消息里不带接力 id 和 SHA。到驿窗侧栏，或在 `~/Library/Application Support/app.postpane.mac/chatgpt/handoffs.json` 里按标题找到这次接力，拿到接力 id 和第几轮；再看 PR 上有没有写着同一接力 id、同一轮的处理说明。拿不到时，就用「标题 + 第 N 轮 + 出口」去对 PR 评论，再确认补改提交已推送、运行记录已有这一行。对上了就是重复转回，回一句「已处理，见 PR 评论」即可，不重复改、不再送、不重复记。
- **出口是哪一档**：看回信倒数第二行「审查出口：…」，再按第 5 节走。

然后对每条意见给一个处理，写进处理表（模板见 [references/reply.md](references/reply.md)）：

- **采纳**：改，并补能证明改对了的测试；
- **不采纳**：给出反证（代码位置、测试、规则出处），不能只说「不同意」；
- **记为后续**：不属于这次范围的，开 issue 或写进交接，不顺手扩大改动。**只用于 P2/P3**。

**P0/P1 只能采纳或不采纳（带反证）**。觉得某条 P0/P1 超出范围、想记为后续的，它就是「没解决的 P0/P1」，按第 5 节交常浩，不能自己记为后续了事。

改完跑**全量**测试，贴原样结果（通过数、失败数）。回信里说「未独立复跑」的部分，不要在收口时写成审查方核实过。

## 5. 按出口和预算收口

| 出口 | 预算还有 | 预算用完 |
|---|---|---|
| 通过 | 收口：PR 上写一句「审查通过（接力 id）」，等常浩说合并 | 同左 |
| 返修 | 逐条处理 → 推送 → 再调用 `relay_to_chatgpt`，送审包只写本轮处理表、新的 head SHA 和增量 diff，不重发整份 | 逐条处理 → 推送 → **PR 上写「补改未复审」**加处理表 → 收口，**不再送**。处理后仍有没解决的 P0/P1（含想记为后续的），PR 上照写「补改未复审」，但**不算收口**：交常浩决定（reply.md 第 4 节），决定前不合并 |
| 证据不足暂停 | 去取证（测试、实测、数据）。拿到证据前不送、不合并；拿到后带着证据再送，这一次不计轮数 | 同左 |
| 决策升级 | 停。把选项、各自的依据和推荐交常浩（模板见 reply.md），等常浩决定；不再送 | 同左 |
| 末两行缺失、对不上 | 驿窗不转回、直接交常浩。常浩点「转回」后，按正文判断，下次送审提醒格式 | 同左 |

**只剩 P2/P3、没有 P0/P1 时**，可以按「通过附建议」收口：改完写「补改未复审」，不再开一轮。

**时间压力不改变审查结论**：开跑、上线、截止时间再紧，没通过或没收口的改动也不合并、不投入真实执行，L3 尤其如此。给常浩的选项里说的「收缩范围」，是把 PR 拆小、只合并已经过审的部分，不是先降级运行没审过的代码。

**不主动提「带着没解决的 P0/P1 合并」**：它不在契约第 8 节的超预算去向里，不列进给常浩的选项。常浩自己提出要带风险合并，就是他的风险接受决定（L3 还要他明确授权动作）：照做前把剩下的 P0/P1 和风险写进 PR，运行记录 `note` 里写明「常浩接受风险合并」。

## 6. 超预算与授权续审

预算用完后，只有**常浩明确要求再审**时才能再送：

- `extra` 写明谁授权、为什么，例如「常浩要求再审一次：第 2 轮决策升级后选了修完再复审」；
- 送审包第一行写「第 N 轮（超出预算，常浩已授权）｜只验收 <范围>」，范围按常浩说的，不扩大成全面复审；
- 当前会话的驿窗工具不支持 `extra` 时，如实告诉常浩，由常浩决定怎么送，不另开新单绕过预算。

不能用「换个标题另开一单」「换个会话」重置轮数。

## 7. 收口之后

1. **记运行记录**：在 `/Users/nat/Documents/ChatGPT/个人/work/multi-agent/runs/runs.jsonl` 追加一行。**照 [references/reply.md](references/reply.md) 第 5 节的样例写全部字段**，不增不减，枚举值只用那里列的；字段说明在同仓库 `docs/runs.md`。记完在 multi-agent 跑 `node --test tests/runs-format.test.mjs`，过了再提交。
   - **什么时候记**：审查收口时记（通过、补改未复审且没有剩 P0/P1、续审结束）。决策升级、证据不足暂停、补改后仍剩 P0/P1 交常浩时先不记，等常浩决定后或任务结束时再记；一定要先占位的，`resolution` 写 `进行中`。合并后把 `resolution` 改成最终状态。
   - 这是纯记录，可以直接提交 multi-agent 的 main；推送冲突就 `git pull --rebase` 再推，不覆盖别人的行。
2. 超预算、续审、拆单的，另在 MA-02 契约第 7 节运行记录表里追加一行。
3. 交接（项目的 CURRENT.md 或 PR 描述）写清：接力 id、轮次、出口、处理方式、测试结果。

## 8. 常见坑

| 坑 | 怎么避免 |
|---|---|
| 没定级就送，接力记录里风险级是空的 | 第 2 节先定级，`risk` 必填 |
| 被审的 PR 链接不是第一个链接，轮数接不上 | 送审包第一个链接就是被审 PR |
| 同一会话同时送两份审查 | 上一份回信前不送下一份 |
| L1 回「需修改」后又送了一轮 | L1 只审 1 轮，补改未复审收口 |
| 驿窗重复转回同一份回信，又改一遍 | 先看 PR 上有没有同一版本的处理说明 |
| 另开一单或换会话重置轮数 | 轮数按 PR 累计，续审要常浩授权 |
| 把「审查通过」当成可以合并 | 合并只听常浩 |
| 把回信里没复跑的部分写成「审查方已核实」 | 收口说明分清谁验证了什么 |
| 审完不记运行记录，或自己编字段 | 第 7 节第 1 步，照 reply.md 第 5 节样例写 |
| 为了赶开跑时间先合并、先跑没过审的代码 | 第 5 节「时间压力不改变审查结论」 |
