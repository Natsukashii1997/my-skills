# 档位判定

按「做完之前还要决定多少事、改动铺多开」判，不按常浩说话的语气或字数判。

## 判据

| 档 | 判据（满足就是这一档） | 不是这一档的信号 |
|---|---|---|
| 0 档 · 顺手改 | 改一两处；没有要常浩决定的事；改完一眼能验（错字、文案、颜色值、配置项、一行明显的修正） | 要先问常浩「你想要哪种」；会改变功能的行为；碰到多个文件的逻辑 |
| 1 档 · 轻量 | 能一句话说清「做完是什么样」；改动集中在一个模块或一个页面；一个会话做得完；不需要新的数据格式或页面流程 | 一句话说不清；要拆成几块分别做；要改数据格式或跨多个模块 |
| 2 档 · 标准 | 需求还模糊（有几种理解、要做取舍），或要改多处（跨模块、多个页面、改数据格式、加新流程），一个会话放不下或需要拆任务卡 | 连「做到什么样算完」都定不下来、要先做一串决定 → 3 档 |
| 3 档 · 大雾 | 全新项目（还没有代码仓库），或方向不清的大工程：不知道从哪下手，要先做很多决定才能写需求文档 | 新项目但一句话就能说清、一个会话做得完的小工具 → 按 1 或 2 档判（wayfinder 原文：只用于一个会话装不下、看不清路的工作，范围清楚的功能不用它） |

## 正反例

- 0 档：「首页标题的错字改一下」「按钮颜色改成 #1F6FEB」「把超时从 30 秒改成 60 秒」。
- 0 档的反例：「按钮颜色改一下」但没说改成什么、或这个颜色是常浩定过的 → 先问；定过的按全局规则第 15 节确认。改动本身仍可能是 0 档。
- 1 档：「体检报告每个任务再加一列『上次运行时间』」「导出按钮再支持 CSV」。
- 1 档的反例：「报告再加一列，顺便把整个报告改成按项目分组」→ 两件事、要取舍，2 档。
- 2 档：「数码世界加个功能：问一个问题能同时查知识库和聊天记录」「给工作台加登录和权限」。
- 2 档的反例：「做个个人记账系统，还没想好要哪些功能」→ 新项目且方向不清，3 档。
- 3 档：「做一个家庭财务系统，管信用卡、房贷、教育金，还没想好要哪些功能、做成什么样」「把整个工作台从网页搬成 Mac App」。
- 3 档的反例：「新建一个小脚本，每天把下载文件夹里的截图挪到桌面」→ 新项目但一句话说得清，1 档。

## 拿不准时

- 在两档之间拿不准：按**高一档**用一句话问常浩，并在那句话里说明「也可以按 X 档轻量做」。2 / 3 档本来就要问，多问一句的成本最低。
- 在 0 档和 1 档之间拿不准：按 1 档做；grilling 那一轮如果发现没什么可问的，跳过提问直接说明，再进 tdd。
- 修 bug 先看是不是半路入口：原因不明、时好时坏、昨天还好今天坏了 → diagnosing-bugs；原因一眼看得出、改一处就好 → 0 档（能补回归测试就补）。

## 半路升档、降档

- **升档**：走 1 档时 grilling 或 tdd 发现要改多处、要做取舍 → 停下，用第 2 节那句话问常浩要不要升 2 档。走 2 档时 grill-with-docs 发现方向整个看不清 → 问要不要升 3 档。升档要问。
- **降档**：发现比想的小 → 说一句「这件事比预想的小，改按 X 档走」直接降，不用等回复。
- 常浩指定的档位优先；他说「这个简单，直接做」就按他说的，风险大的地方在收尾里写明。

## 各档的细节

### 0 档
直接改、自己验，收尾三项照写，「下一步」写「本任务已结束，下一步无需任何动作」。不调用任何 Matt 技能。

### 1 档
1. 记下起点：`git rev-parse HEAD`（code-review 要用它当比较起点）。
2. **grilling** 只问一轮、最多 3 个关键问题，每题带推荐答案；tdd 要确认的「在哪里验证」（接缝）用白话并进这一轮一起问，省一次往返。
3. **tdd**：一次一个小切片，先写会失败的测试，再写刚好让它通过的代码。
4. **code-review**（`mattpocock-skills:code-review`）：比较起点用第 1 步记下的提交；Spec 那一轴的需求来源就是 grilling 的结论，直接交给它，不要求常浩先跑 setup-matt-pocock-skills。
5. 收尾。要提交、推送、开 PR 的，按常浩规则单独问。

### 2 档
grill-with-docs →（有问题必须看实物才能定时）prototype → to-spec → to-tickets → implement 逐张（或 implement-spec 一次跑完）→ code-review → pr → retro。

- 第一次走 2 档的项目，先做 SKILL.md 第 4 节的前置检查，作为第一站。
- prototype 原文要求用 handoff 进出；按 SKILL.md 第 6 节第 1 条，换成常浩的交接卡，或在本会话里做。
- implement 还是 implement-spec：任务卡少（3 张以内）、或常浩想每张都看一眼 → implement 逐张；卡多、彼此独立、常浩想一次跑完 → implement-spec。拿不准就在 to-tickets 那站的收尾里给推荐，让常浩选。
- to-spec 写完是 thinking-review 的检查节点。

### 3 档
wayfinder 画地图、逐张解决决策卡（一个会话一张，研究类除外）→ 地图清了就并入 2 档，从 to-spec 开始。wayfinder 第 2 步如果发现根本没有雾（路已经清楚、一个会话做得完），按原文停下问常浩，通常改按 2 档或 1 档走。
