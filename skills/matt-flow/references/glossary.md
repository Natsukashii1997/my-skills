# 精简术语表

给常浩解释用：第一次用到时附这一句白话，之后直接用词。项目有自己的 `GLOSSARY.md` 时，项目里的词以它为准。

| 术语 | 一句白话 |
|---|---|
| 需求文档（spec） | 把「要做什么、为什么、做到什么样算完」写清楚的一份文档 |
| 任务卡（ticket / issue） | 拆出来的一小块活，做完能单独验证 |
| 任务看板（issue tracker） | 放任务卡的地方：GitHub Issues，或项目里的 `.scratch/` 文件夹 |
| 端到端细切片（tracer bullet） | 每张卡从界面到数据一路打通一小条，而不是先只做完某一层 |
| 阻塞关系（blocking） | 这张卡要等那张做完才能开始 |
| 可开工的卡（frontier） | 挡着它的卡都做完了、现在就能做的那些卡 |
| 测试先行（TDD） | 先写一个会失败的检查，再写刚好让它通过的代码 |
| 红 / 绿（red / green） | 检查没通过 / 通过 |
| 接缝（seam） | 从外面检查功能对不对的那个位置，不伸进代码内部 |
| 回归测试 | 修好一个 bug 后加的检查，防它以后再坏 |
| 代码审查（code review） | 改完让另一个 AI 看一遍：守不守规矩、做的是不是要的 |
| 比较起点（fixed point） | 审查时「从哪儿开始算改动」的那个版本 |
| 分支（branch） | 代码的一条平行线，在上面改不影响主线 |
| 集成分支 | 几张卡的改动先汇到这条线上，一起验完再合进主线 |
| 提交（commit） | 给当前改动存一个版本 |
| 本地提交 | 只在本机存版本，还没传到 GitHub，别人看不到 |
| 推送（push） | 把本机的版本传到 GitHub |
| PR（pull request） | 请求把一条分支合进主线，附说明，等人批准 |
| 合并（merge） | 把分支的改动并进主线 |
| worktree | 同一个项目在硬盘上的另一份工作副本，几个会话各用各的，互不干扰 |
| 子 agent | 另开一个 AI 专门做一件小事，做完交回报告 |
| 上下文 | AI 这一轮能「记住」的全部内容，太满了会变迟钝 |
| ADR（决定记录） | 把一个难反悔的决定和理由记下来的短文件 |
| GLOSSARY.md | 项目的行话表：每个词在这个项目里是什么意思 |
| 分流标签 | 给 issue 贴的状态标签：待评估、待补信息、可交给 AI、要人来做、不做 |
| 原型（prototype） | 用完即弃的小样，只为回答一个问题 |
| Artifact 链接 | 一个 claude.ai 网页链接，电脑和手机都能直接点开看 |
| 重构（refactor） | 不改功能、只把代码理顺 |
| 深模块 | 对外接口简单、背后能做很多事的一块代码，好用也好测 |
| 原话区 | 需求文档和任务卡里专门放常浩原话的一节，一字不改，是这张卡的最高要求 |
| 读回 | 卡发出去后再读一遍，确认真写成了确认时的样子 |
| 撞卡 | 两个会话（或 Claude 和 Codex）同时在做同一张卡 |
| 决策卡 | wayfinder 用的卡：每张解决一个「要先定下来」的问题，产出是决定，不是代码 |
| `.env` / 密钥 | 存账号密钥的本地文件 / 不能外泄的口令，不进代码仓库 |
| CI | 每次推送后 GitHub 自动跑的检查 |
