## 2.0.0 - 2026-11-10

按三份独立评审修订（my-skills#86）。评审方：两个独立 Claude agent（逐条核对、情景推演）、ChatGPT（经驿窗，L1 一轮，结论「需修改」，补改未复审）。常浩逐条拍板：三件事都按推荐，其余全部按推荐。触发范围变了，所以升主版本。盲测 3 轮：第 1、2 轮 E10 不过，改后第 3 轮 E1–E12（14 条）全过、T 组 8/8；记录见 evals.md。

- 改动（触发范围）：description 收窄。「我有个想法」只算想做软件或功能；「下一步呢」只在开发流程进行中接。本机定时任务、后台服务、机器人没反应交给 automation-checkup；业务流程要不要用 AI 交给 ai-landing-method。常浩点名技能时直接用那个技能。
- 改动（手动技能）：只能手动的 Matt 技能不再默认读原文代做。卡片里写出常浩要回的命令（`/mattpocock-skills:<名字>`，Codex 是 `$<名字>`）；他回「好」或已说「一口气做完」，才视为授权、读原文照做。
- 改动（工程流程）：分支、issue、PR、合并一律照 agent-kit 工程流程。0 / 1 档也在本地分支上做，改完一次确认「开 issue、推送、开 PR」。2 档逐张实现时一张卡一个分支、一个 PR；一次跑完时一条集成分支、一个 PR。implement 内含审查，不再单列一站。项目 AGENTS 里旧的「Agent skills」路线，以本 skill 的档位为准。
- 改动（节奏）：
  - 2 档问透后判断一个会话做不做得完，做得完就在本会话实现；
  - 1 档答完问题后连着做到审查；
  - 升档改成三选一；
  - 「一口气做完」先列出停点，同一站的确认并成一次；
  - 卡片统一写「回复 X」；
  - 状态词：没合并的不写〔已结束〕。
- 新增：第 3 节「流程进行中」：回复按当前站理解；插进来的事怎么挂起、怎么回原站；在 `CURRENT.md` 或 `.scratch/<功能>/flow.md` 记进度。
- 新增：「下一步呢」要查 `CURRENT.md`、worktree、未合并分支、PR 和 issue；查到多条进行中的事就列出来让常浩挑。
- 新增：版本基线检查（插件不是 1.3.2 时提醒复核）。
- 修复：1 档审查拿不到改动。现在审查前先本地提交，起点自己记，不要求先跑 setup-matt-pocock-skills。
- 修复：对外写入清单补全，覆盖评论、指派、关闭、草稿 PR、各类分支推送；同一站的写入列成一张清单确认一次；子 agent 守同样的边界。
- 修复：前置检查改看配置是否可用；不建 GitHub 时，同时改 AGENTS.md 里关于 GitHub Issues 的那一段。
- 修复：1 档只借用 grilling 的问法、不加载它，避免和原文「问到底」打架。
- 修复：prototype 按全局规则第 9 节出三版、给 Artifact 链接；teach 在 `~/Sandbox/` 里做；没有测试接缝的改动用项目自己的验证方式；improve-codebase-architecture 先问一句；0 档判据的自相矛盾；3 档加 thinking-review 检查节点；retro 的提议接到 LESSONS；原型交接写明内容；不是 git 仓库时怎么办。

- 实机全链路（`~/Sandbox/2026-11-10-matt-flow-e2e/`，2 档 5 站走通，3 张卡，main 上 19/19 通过）发现 18 条问题，据此补了这些：
