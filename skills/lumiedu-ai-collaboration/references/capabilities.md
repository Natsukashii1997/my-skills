# 元能力与人机边界

## 先责任，后实现

每个动作先问：谁对结果负责？是否涉及依法/依制度保留的决定、资源承诺、关系权衡、专业判断或学习目标？本轮及现行制度允许委托到哪一步？未确定时只能作候选，不能自动生效。

把不可委托的决定与可自动准备的子动作拆开。例如“计算报销是否符合规则”可交程序，“批准并付款”由现行授权和制度决定；“提供练习反馈”可用 AI，“完成学员应练的判断”应由学员做。人负责不意味着每个低风险动作都人工审批。

边界确定后再选执行方式：稳定规则用程序；明确读写/发送用工具；非结构化理解、综合和生成用 AI；复杂取舍或无法充分校验的部分保留给人。一个动作可由程序执行并由有权人批准，这不是二选一。

## 十二项能力作为查漏工具

| 编号 | 能力 | 需要的输入 | 可检查输出 |
|---|---|---|---|
| C1 | 触发 | 事件/时间/人工请求及范围 | 可关联的事件及重复识别 |
| C2 | 理解结构化 | 原文、字段语义、业务对象 | 候选值、原文对应、歧义 |
| C3 | 检索取证 | 身份、查询对象、来源边界 | 有权限的依据、版本、覆盖情况 |
| C4 | 规则处理 | 明确规则、结构化数据 | 可复算的筛选、计算或转换 |
| C5 | 辅助判断 | 证据、标准、约束 | 候选与理由、缺口及分歧 |
| C6 | 生成 | 事实、要求、素材 | 可按标准检查的草稿 |
| C7 | 人机协同 | 对象、版本、责任、待定事项 | 有权角色的补充或决定 |
| C8 | 动作与触达 | 获准动作、目标、参数 | 实际操作及接收结果 |
| C9 | 编排 | 状态、依赖、事件及条件 | 可追踪的转移、等待、恢复 |
| C10 | 留痕与回读 | 动作与目标标识 | 写到哪里、实际值、执行状态 |
| C11 | 知识维护 | 候选、来源、适用范围 | 审定、发布、调用或撤回记录 |
| C12 | 独立校验 | 候选结果及独立规则/来源/有权人 | 内容正确、错误或仍未知的依据 |

不为每项能力新建组件。C10 证明状态/写入结果，C12 判断业务内容是否正确，两者不能互相冒充；同模型自评不是唯一独立证据。

## 委托程度：不把 AI 使用量当成熟度

以具体动作标记，不给整个部门一个等级：

| 状态 | 允许方式 | 所需依据 |
|---|---|---|
| 人工保留 | 系统辅助展示/记录，人判断并执行 | 责任、风险或学习目标 |
| 辅助准备 | 规则或 AI 给候选，人处理 | 输入与候选可供核对 |
| 确认后生效 | 系统准备，有权人确认该版本后执行 | 权限、对象绑定、可审结果 |
| 边界内自动 | 既定允许范围自动处理，异常转人 | 规则、输入、独立校验、可靠动作、恢复及验证 |

分别记录“建议目标”“起步方式”“当前已验证方式”；不预设必须逐级升级，也不以高频推导全自动。升级条件必须可观察，例如在约定样本和真实试点中关键错误率达标且未知结果能够恢复。阈值由业务风险及有权责任人确认，不能套统一百分比。

## 每个委托动作的合同

`触发/不处理范围 → 所需输入与依据 → 执行身份及权限 → 处理方式 → 独立校验/必要人工决定 → 动作 → 回读证据 → 异常接手与恢复`

输出含敏感信息时检查读权限、输出目的地权限及最小必要内容。权限保护必须在模型和工具边界执行，不能只在提示词中写“请保密”。没有合法可实现路径时，保留人工或改变数据处理路线。
