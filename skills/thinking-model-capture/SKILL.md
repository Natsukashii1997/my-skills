# Thinking Model Capture

把本轮已明确指定的思考提炼为可复核的模型候选。候选仍是待验证材料，不能因完成提炼就成为正式知识或常浩已确认的观点。

## 先确定本轮授权

- 只有明确要求“沉淀为思维模型候选”或显式调用本 Skill 时才进入。普通轮次按当前任务完成，不额外扫描历史、创建候选或等待维护任务补扫。
- 显式调用但未要求保存时，先在聊天中给出候选评估；“只分析”“先看草稿”等限制优先。明确要求保存指定内容时，沿用该授权，不重复询问。
- 输入限于本轮指定材料与必要来源；不要遍历原始会话、其他项目或私人材料。不得把本次系统优化、历史授权或可访问权限解释为知识写入授权。

## 评估是否值得复用

先识别具体机制：适用问题与触发信号、前提与输入、关键步骤和判断点、异常或失败信号、输出与验证、适用边界。只保留有来源支持的部分，缺失项明确为待验证。

- 单次做法先标为情境策略或待验证方法；存在跨场景证据再考虑稳定机制。
- 纯事实、一次性状态、没有机制的表达和既有方法的普通案例，不为凑数创建模型。
- 区分常浩原话、已确认判断、人机共同形成的内容与助手推断。未确认的推断不能写成常浩原创或已采用方法。
- 必要时对已授权范围内的现有候选或正式知识做语义去重。已有模型的新反例、边界或跨场景证据可形成修订候选；完全重复则说明关系，不覆盖旧内容。

## 写入走当前 Vault 规则

获准保存后，完整读取 `/Users/nat/Documents/Obsidian Vault/AGENTS.md`，按其中当前候选目录、字段、隐私分类、事实 Owner、检索门禁及回读要求执行。用户只要求候选时，不晋升正式知识，不改来源层、个人 Current、项目 Current 或长期记忆。

需要将 Vault 内容用于当前判断或去重结论时，先通过该文件要求的只读有效性门禁。门禁不可用、来源不足或权限不明时，保留聊天中的待核验草稿，报告缺口；不绕过、不改门禁基线，也不另建候选库。只有规则要求的检查完成后才保存。

`scripts/` 中的旧事务与校验脚本依赖旧思维模型库目录及旧字段协议，保留原文件仅为兼容既有历史调用。本入口不执行这些脚本，不把旧目录当作备用目标，不迁移、删除或补扫历史候选。其他定时任务的旧调用须在其独立维护范围内核实，不能由本 Skill 默认为已修复。

## 写后回读与停止

- 只创建本轮授权的候选；凭据、私人链接和无关敏感信息不得进入正文或来源字段。
- 按当前 Vault 规则回读实际文件、字段、正文、来源、候选状态及必要链接。回读不完整或状态未知时不报告完成，不自动重放写入。
- 交付候选路径、抽象出的机制、待验证项和实际验证范围。明确候选保存与正式知识采用是两个状态。
- 没有值得保存的机制、判定重复、缺少必要授权或完成指定候选后停止；不自动建立索引、维护任务、飞书镜像或后续提醒。
