# CHANGELOG

## 1.0.0 — 2026-11-07

首版。盲测 5 轮，第 5 轮 10/10 全过（记录见 evals.md）；常浩在 PR 上批准后合并、链接到 `~/.claude/skills`。

- 依据《Claude × ChatGPT 思维评审机制 最终需求共识 V3.0》（常浩、ChatGPT、Claude 三轮讨论收口）编写。
- A / B / A+B / C 分类，按当前问题划分，与思考来源无关；检查节点覆盖接手他人方案、方案成形、前提被证伪、两次修复失败、退出后新证据。
- 准入：五个方面 + 三级处理；一级场景「必须判断，不必然发起」，已有有效结论不重复送审。
- 支持 ChatGPT 起点：接手后先独立分析，只送增量，不把原方案发回求认可。
- 「全景 → 深化 → 收敛」三阶段，阶段不等于轮次；后续阶段新问题须过四问才扩大范围。
- 退出：认知状态与处理去向分开记；四种退出；成熟条件六条；重新进入的条件。
- 对接驿窗 `relay_to_chatgpt` 现有协议：评审出口五选一映射到「结论：通过 / 需修改 / 交常浩裁决」，不改驿窗。
- 决策记录模板。
- evals 10 条，覆盖 V3.0 第十四节要求的 10 类情境。
- 用 15 个真实案例（research/cases.md）校准：A 类在常浩已拍板、原话可裁定或可分批回退时可不发起；评审中途的单项拍板不等于收口；第一阶段先审目标用户与核心假设；内容没变不重送；决策记录加重开条件；检查节点加「反复返工贴不上实际用法」「常浩质疑方向」。明细见 research/calibration.md。
- 盲测五轮中据打分修订：准入四行写在哪、只有发起才建记录、已有有效结论按 C；A+B 中与 A 无关的 B 可先审；ChatGPT 起点部分推翻时仍成立部分列入【既定决策】；准入依据是证据而非修复次数；授权外的方向改动先撤出交常浩，要保留再评审、定向后走工程审查；重新进入时【既定决策】写实。
