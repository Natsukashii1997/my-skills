# 认知成熟与退出

## 1. 认知状态和处理去向分开记

认知状态说明这个问题想清楚到什么程度；处理去向说明下一步由谁负责、在哪做。两者不能合成一个字段。

| 待决问题（例） | 认知状态 | 处理去向 |
|---|---|---|
| 目标是否准确 | 已形成可靠结论 | 进入执行 |
| A/B 两条路径选哪条 | 主要证据支持 A | 采用 A |
| 某个用户行为假设 | 缺真实数据 | 先补证据（实验验证） |
| 两种投入方案的取舍 | 利弊已明确，涉及资源偏好 | 交常浩裁决 |
| 次要性能参数 | 不影响当前路线 | 执行中优化 |

认知状态常用值：已形成可靠结论；主要证据支持某一方；利弊已明确但需要取舍；缺关键事实；不影响当前路线。
处理去向常用值：进入执行；执行中验证；先补证据；交常浩裁决；转工程审查；执行中优化。

## 2. 状态填了，不等于问题解决了

两条护栏：

- **「执行中验证」只给错了后果可控的假设。** 写明怎么验、谁验、错了会怎样。一个关键架构假设还没验证，一旦错了会推翻整个架构，就不能标「执行中验证」退出，处理去向应是「先补证据」，退出类型是证据不足暂停。
- **「交常浩裁决」在常浩拍板之前不算成熟。** 涉及改变业务路线的重大争议标了交常浩，常浩还没决定，就是决策升级退出，不是成熟退出。

## 3. 成熟退出的条件

原则上同时满足：

1. 本次核心认知问题已有明确回答。
2. 重大方向性分歧已解决，或已明确升级给有权决策的人。
3. 关键假设有合理的证据支持，或有受控、错了也不会造成不可接受后果的验证路径。
4. 主要方案逻辑自洽，重大取舍有明确依据。
5. 剩余未完成事项不会阻碍下一阶段的合理行动。
6. Claude 已经清楚执行边界和后续的判断标准，知道下一步怎么展开，不需要再讨论基础方向。

重点不在于不确定性全部消失，而在于：**不再存在必须继续进行思维论证才能解决、且会实质阻碍当前行动的重要问题。**

一个评审完成没有，最终看 Claude 能不能依据已经形成的判断，自主、连贯地推进后续工作。不需要 GPT 把后续每个开发步骤都设计完。

## 4. 四种退出

| 退出 | 含义 | 是否评审目标达成 |
|---|---|---|
| 成熟退出 | 思维评审任务完成，Claude 继续执行 | 是 |
| 决策升级 | 选项和依据已明确，仍需常浩授权、取舍资源或接受重大风险；不代表已获批准 | 否，只是这条链当前该停 |
| 证据不足暂停 | 缺决定性信息，继续讨论不会有增量；先取证 | 否 |
| 转其他路径 | 剩下的属于工程实现、测试、质量验证或普通执行 | 认知部分已完成 |

不能把这四种合并成「通过 / 不通过」。

**ChatGPT 先想过不等于已经成熟退出。** 接手 ChatGPT 起点的方案时，仍要独立判断原方案依据是否充分、有没有新的重要认知问题。

## 5. 重新进入

退出后，不能因为 Claude 做了一个新功能、提交了一次 PR 就重新进入。只有出现下面之一才考虑：

- 目标改变
- 关键约束变化
- 原路线被证伪
- 出现重大的、事先没预料到的系统冲突
- 出现足以改变关键决策的新证据

重新进入时，在决策记录里写明：引用的原决策、发生了什么变化、这个变化为什么影响原决策。送审包的【既定决策】逐条列出原决策中**仍然有效**的结论（先读原决策记录，从里面摘出来写实，不写「待补」之类的占位；确实找不到记录的，写出已知的结论并标「未核实」），只把被推翻的部分作为待决问题。这是一次有理由的新的认知校准，不是把上一轮无限延长。不能把同一问题换个名字绕过已有的退出结论，也不能把普通执行问题重新包装成认知问题。

反过来也不能为了追求收敛，拒绝修正真正错误的历史决策。
