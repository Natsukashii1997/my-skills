# 发起接力：送审包、评审指令、回信与驿窗对接

## 1. 驿窗接力工具的实际行为（照现状用，不改驿窗）

**前提：驿窗要装有 postpane#209 的版本。** 那个版本给标题以「思维评审｜」开头的接力加了专门处理；更早的版本会把「通过」直接关掉、不转回 Claude，结论行也可能误判，不能用来跑思维评审。

据驿窗源码（`handoffs.rs`、`host/src/handoff.rs`）与 `relay_to_chatgpt` 工具说明：

- 同一个 Claude 会话第一次调用会新开一个 ChatGPT 会话，之后再调用都发进**同一个** ChatGPT 会话。
- ChatGPT 读不到本机文件，送审包必须自带全部必要信息。装了 GitHub 连接器，能打开 PR 链接。
- 同样的送审包刚送到、还没回信时不会重复送。
- **思维评审接力**（标题以「思维评审｜」开头）只看回信最后两个非空行：倒数第二行「评审出口：…」，最后一行「结论：…」，两行必须对得上（对应关系见第 3 节）。两行有一行缺失、值认不出或彼此矛盾时，驿窗不放行、不自动转回，先自动请 ChatGPT 只补一次格式（不计轮），还不对才交常浩（细则见第 4 节表末行）。正文里出现的其他「结论：」不会被采信。各评审出口驿窗怎么处理，见第 4 节。
- 工程审查接力（其他标题）按 multi-agent MA-02 v0.3 的审核门：审几轮由 ChatGPT 按问题台账判断，回信最后四行「受审版本 / 未决 / 审查出口 / 结论」。
- **轮数上限两种接力共用**：本次授权周期最多 5 轮（驿窗设置「接力审核上限」），常浩介入后从 1 重计；ChatGPT 实质回过一次就计一轮（含证据不足暂停），只补格式、传输失败不计。授权周期已计 4 轮、出口仍可能继续（继续深化或证据不足暂停）时，转回提示「下一轮是最后一轮」；第 5 轮仍没退出就停下，发到顶提示交常浩。任何一轮以「结论：通过」结束都通知常浩。思维评审只共用这些机械控制，不套用工程审查的问题台账和 P0/P1。

工具说明里的「六项」（分支、PR、git diff、按严重程度列问题）是给工程审查用的。**思维评审不按那六项写**，按下面第 2 节写。

## 2. 送审包（brief）

`title` 写「思维评审｜<项目>｜<待决问题短名>」，让驿窗卡片一眼和工程审查区分开。`summary` 写阶段和问题，例如「第一阶段 · 调度架构选型」。

brief 按这个顺序写，每项几行即可，关键是不把事实和判断混在一起：

```
思维评审｜<项目>｜<待决问题短名>（第 X 阶段）

【本次要判断什么】
<一个待决认知问题；必要时拆成 2–4 个子问题>
【本次不判断什么】
<明确不在范围内的事，例如实现细节、已定的 UI>

【背景与目标】
【目标用户与核心假设】（这件事给谁用、替他解决什么、成立的前提是什么）
【常浩的原始诉求】（尽量引原话；方向判断以此为最高证据）
【已知事实】（每条注明来源：文件、数据、测试结果、常浩原话；未核实的标「未核实」）
【约束与不可改变的边界】
【既定决策】（能核实、仍然有效、本次不重开的结论，每条注明出处：决策记录、常浩原话；没有就写无）
【待核实的历史说法】（找不到出处、只凭记忆或摘要的「之前好像定过」；可以质疑，不算基线；没有就省略）
【方案来源】Claude 提出 / 常浩与 ChatGPT 讨论形成后交给 Claude / 其他
【Claude 当前的判断与依据】（推断、假设、偏好分开写，不把个人判断写成已验证事实）
【已考虑的替代方案】（还没有就写「尚无，欢迎提出」）
【未确定的假设或分歧】
【为什么值得独立论证】
【本次希望得到的结果】

<第 3 节的评审指令原样附上>
```

**接手 ChatGPT 起点的方案时**，【方案来源】写清楚，【既定决策】列出原讨论里已经论证过的结论，【Claude 当前的判断与依据】写 Claude 独立分析后的**增量**：哪个假设可能有问题、新发现的约束、更合适的替代路径、原结论与新证据的冲突。不要把原方案整份发回去请它确认。

原方案只是部分被推翻时，**仍然成立的部分照样列进【既定决策】**（例如「用检索给回答提供上下文」这个大方向不变），被推翻的部分写进【Claude 当前的判断与依据】，说明依据。这样 GPT 知道哪些不用重开，也不会把整个方案当成作废。

**第二、三阶段**，附上决策记录里「已确认」和「需深化」两张清单，以及 Claude 对上一轮意见的处理（采纳 / 不采纳 + 反证 / 补了什么证据）。

**外发核对**：送出前过一遍。只放必要的内容；知识库里标为受限或没标注敏感度的内容、私人数据、凭据，不放原文，在授权范围内改写成摘要，或者写「此项在本地核实」。不能因为证据重要就原文外发。

**本会话之前已经接力过别的问题**时（看本会话里自己有没有调用过 `relay_to_chatgpt`；调用过，这次就会进同一个 ChatGPT 会话，里面有旧内容），第一行下面加一句「这是一个新的待决问题，与本会话之前的讨论<无关 / 有关：……>」。这句话只是提醒，并不能真正隔开旧上下文。如果新问题和旧内容无关，而旧内容可能影响判断，或者这个问题需要独立判断，就换一个新的 Claude 会话来发起（驿窗会给它新开一个 ChatGPT 会话），或者告诉常浩，由常浩决定。

## 3. 评审指令（附在送审包末尾）

```
请以独立思考者的身份做思维评审，不是代码审查：
1. 先判断问题本身是否提对了：先审目标用户、核心假设，以及它们是否符合常浩的原始诉求，再看具体设计。如果待决问题的定义、目标或边界有问题，直接重构它。
2. 不局限于我给出的方案。可以提出我没考虑的路径，挑战关键假设，指出隐藏的系统性影响，判断是否存在不必要的复杂化。
3. 方案已经成熟的部分，请明确认可，不需要为了提意见而提意见。评审价值看是否帮助形成有依据、可执行的正确方向，不看问题条数。
4. 只围绕本次待决问题，不扩展到整个项目；不按 P0–P3 列缺陷。
5. 我提供的事实中你无法核实的，请在依赖它的判断旁标出「依赖未核实事实：……」。
6. 本次处于第 X 阶段：<该阶段任务，见下>。
   - 第一阶段：尽量一次找出会实质影响结论的问题（重大遗漏、错误前提、不成立的因果、被忽略的路径、未比较的取舍、决定性风险），给出关键问题地图，每条标「成立 / 需深化 / 不值得继续讨论」。
   - 第二阶段：只处理附上的「需深化」清单，不重审已确认的部分。提出新的重大问题时，同时说明：是什么、来自什么证据、为什么改变核心判断、为什么不能留到执行阶段；说不清的写进「执行建议」。
   - 第三阶段：收敛。给出最终判断、选定路径及依据、接受的风险、留给执行阶段验证的假设（怎么验、错了后果是否可控）、需要常浩决定的事项。
7. 如果首轮已经可以收口，直接给出退出建议，不必走完三个阶段。

回信结构：
## 问题重述（如需重构问题定义，在此说明）
## 判断（逐个待决问题：认知状态 + 依据）
## 新发现（只写会改变核心判断的）
## 执行建议（不阻断，由 Claude 自行取舍）
## 交接（选定路径、执行中要验证的假设、需要常浩决定的事项）

格式要求：正文中的阶段性判断用「判断：」开头，正文任何地方都不要出现「结论：」字样。回信最后两行固定为：
评审出口：成熟退出 / 继续深化 / 证据不足暂停 / 决策升级 / 转其他路径（五选一）
结论：<按下表填写>
- 成熟退出、转其他路径 → 结论：通过
- 继续深化、证据不足暂停 → 结论：需修改
- 决策升级 → 结论：交常浩裁决
```

## 4. 结论行与驿窗的对接

以下是装有 postpane#209 的驿窗对思维评审接力的处理：

| 评审出口 | 结论行 | 驿窗怎么处理 | Claude 接着做什么 |
|---|---|---|---|
| 成熟退出 | 结论：通过 | 先把回信全文和收口话术转回 Claude，送到了再结束接力（送不到就交常浩，不关闭） | 逐条处理意见，把决策记录更新为已退出，按已定路径执行；不再送审 |
| 转其他路径 | 结论：通过 | 同上 | 转工程审查或直接执行；不再送审 |
| 继续深化 | 结论：需修改 | 转回 Claude（未到上限；到上限见下文「到顶」） | 逐条处理意见，只针对「需深化」项准备下一阶段送审包再发；内容没有实质变化不重送 |
| 证据不足暂停 | 结论：需修改 | 转回 Claude，并停止自动往返（卡片显示「证据不足暂停，等 Claude 取证」，不计等复审超时）；这一次照样计轮 | 去取证。拿到新证据前不送审、不实施被评审的部分、不自行标为成熟；证据需要常浩提供的，告诉常浩。拿到证据后带着证据再调用 `relay_to_chatgpt`：会续接原接力、发进同一个 ChatGPT 会话，自动往返随之恢复 |
| 决策升级 | 结论：交常浩裁决 | 转回 Claude，并停下交常浩 | 整理选项、各自的依据和推荐交给常浩，等常浩决定；不再送审 |
| 末两行缺失、认不出、彼此矛盾 | — | 先不放行，自动请 ChatGPT 只补一次格式（不计轮）：补好就按补出的出口照上表处理，还不对才交常浩。补格式只补末两行，不改实质判断；出口与结论矛盾时以出口为准改结论，认不出出口时不能补出「通过」 | 常浩在卡片上点「转回 Claude」后，按回信正文判断退出类型，记进决策记录；下一次送审时提醒格式 |

「通过」「需修改」只是驿窗的协议词，含义以「评审出口」那一行为准。驿窗转回时附的处理话术（自动或常浩手动点「转回 Claude」）按评审出口给出，与本表一致；有出入时以本 skill 为准。驿窗重启后自动往返接着跑：重启前已到的回信照上表处理（postpane#342）。

**驿窗到顶交还常浩时**（授权周期第 5 轮回信仍不是成熟退出或转其他路径）：这是工具层的安全上限，不是认知结论。Claude 向常浩说明当前处于哪个阶段、还剩哪些「需深化」项、建议继续还是退出及理由，由常浩决定是否继续。

## 5. 需要更独立的复核时

驿窗开的 ChatGPT 会话和常浩自己讨论方案的那段对话不是同一个会话，本身就没有原对话的推理惯性，但仍是同一模型，**不等于第三方独立验证**。

确实需要更强的独立性时（重大且不可逆的决定），让 GPT 先只看事实与约束、独立形成判断，再对照原方案：送审包里先给【已知事实】【约束】【待决问题】，把【Claude 当前的判断】和原方案放在最后，并在评审指令里要求「先独立给出你的判断，再对照下面的方案」。需要一个全新的 ChatGPT 会话时，从新的 Claude 会话发起，或者告诉常浩，由常浩决定。
