# 决策记录模板

一个认知问题一份，由 Claude 维护。放在当前项目约定的设计文档目录（`docs/design/`、`docs/adr/` 等；没有约定就用 `docs/thinking-review/`），文件名 `<YYYY-MM-DD>-<短名>.md`。不放 `/tmp`。

记录的核心是「关键判断及其依据」，不是 GPT 提了多少条意见。不要求写成长文档，但要能回答：最初的问题是什么、原始方案是谁提的、哪些结论之前已经论证、Claude 接手后新增了什么判断、有没有重要分歧、为什么发起（或不发起）接力、每次评审解决了什么、最终形成了什么有效决策。

普通执行步骤和代码改动不进这份记录。

```markdown
# <待决问题短名>

- 项目：
- 开始：YYYY-MM-DD
- 方案来源：Claude / 常浩与 ChatGPT（<会话或文档出处>）/ 其他
- 当前状态：评审中（第 X 阶段）/ 已退出（<退出类型>，YYYY-MM-DD）

## 准入
准入：A｜发起 / 不发起
待决问题：
当前判断与依据：
理由：

## 继承的结论（来自原方案或之前的评审，本次不重开）
- <结论>（出处）

## Claude 接手后的独立判断（ChatGPT 起点时必填）
- 认可的：
- 新增的异议 / 约束 / 替代路径：

## 待决问题清单
| 问题 | 认知状态 | 处理去向 | 依据 |
|---|---|---|---|

## 评审经过
### 第 1 次接力（YYYY-MM-DD，第 X 阶段）
- 本次解决了什么：
- 对重要意见的处理：<采纳 / 不采纳 + 反证 / 补证据 / 交常浩 / 记为执行建议>
- 评审出口：

## 最终决策
- 选定路径及依据：
- 接受的约束与风险：
- 执行中验证的假设（怎么验、谁验、错了后果）：
- 常浩已裁决 / 待裁决：
- 执行边界：
- 重开条件：<出现什么证据时应当重新进入，例如「真实使用中 X 场景占比超过 Y」「压测峰值超过 Z」；收口不等于永久冻结>

## 变更与重新进入
- YYYY-MM-DD：原判断 → 新证据 → 影响范围 → 修正后的决策
```

不发起评审时只填「准入」一节，其余省略。
