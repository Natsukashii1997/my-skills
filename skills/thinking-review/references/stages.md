# 递进评审的三个阶段

整个过程应当从发散走向聚焦、从质疑走向论证、从论证走向决策。注意力和问题范围随阶段逐步收缩。阶段不等于轮次：一次回信可以走完多个阶段；某个阶段也可能要暂停，等 Claude 去补实验或业务证据。不能为了凑满「第三轮」而多发一次接力。

## 第一阶段：全景审视

**回答**：问题提对了吗？Claude（或原方案）的目标、关键假设、路径选择和整体逻辑成立吗？

**范围**：只围绕本次待决问题及其必要的上下游展开，不是对整个项目做全景。

**先审最底层**：目标用户是谁、要替他解决什么、核心假设是什么，以及这些和常浩的原始诉求、真实使用方式是否一致。这一层不成立，下面的设计再精细也没用。真实案例里出现过这样的事：三轮评审都落在措辞和格式上，「使用者根本用不上」这个前提问题却是常浩自己发现的。

**要找**：

- 重大遗漏
- 错误前提
- 不成立的因果推导
- 被忽略的重要路径
- 还没比较过的关键取舍
- 对整个方案有决定性影响的风险

**要求**：尽量在这一阶段把会实质影响结论的问题一次暴露出来，不要每一轮才发现一个新的结构性缺口。不以发现大量次要问题为目标。GPT 可以重构问题定义、提出 Claude 没考虑的路径、明确认可已成熟的部分。

**产出**：一张按优先级筛过的关键问题地图，每条标「成立」「需深化」「不值得继续讨论」。全部成立时直接建议成熟退出。

## 第二阶段：关键深化

**回答**：第一阶段最重要的判断和分歧，现在有充分依据了吗？

**范围**：只处理决策记录里标为「需深化」的项。不再默认从头审视全部内容。

**做法**：核实事实、验证前提、比较路径、消除重大分歧。Claude 补充的事实、实验结果、比较和推导是这一阶段的主要材料。

**新问题的准入**：这一阶段（以及第三阶段）提出新的重大问题，必须同时说清四件事：

1. 新问题是什么；
2. 来自什么证据；
3. 为什么会改变之前的核心判断；
4. 为什么不能留到执行阶段处理。

说不清这四件事的，记为执行阶段的普通建议，不扩大评审范围。说得清的，即使在后面的阶段也允许重开，不能为了收敛而压住。

**缺事实时**：暂停去取证，不靠连续对话模拟事实验证。

**产出**：关键问题的明确判断，分为已经解决、需要额外证据、需要常浩取舍三类。

## 第三阶段：决策收敛

**回答**：剩下的问题还值得继续评审，还是已经可以交给 Claude 执行？

**要明确**：

- 关键问题的最终判断
- 选择的路径及依据
- 接受了哪些约束和风险
- 哪些假设留到执行阶段验证（怎么验、谁验、错了后果是否可控）
- 哪些事项需要常浩决定
- 退出类型

**要求**：不再做没有目标的广泛探索。产出不是又一份冗长的修改清单，而是一个明确的处理结果：可以执行、需要定向补充、需要常浩裁决，或者当前应当暂停。

## 阶段推进原则

- 首轮已经充分完成全景、论证和收敛判断的，直接退出。
- 第二阶段仍缺重要事实的，暂停取证。
- 重要前提被新证据推翻的，可以回到相应的分析层级，但必须写明重新展开的理由。
- 已经处理过的意见，不允许换个说法再提一遍。
- 控制的是认知活动的范围和价值，不是对话次数。

## 每次送审时告诉 GPT 当前在哪个阶段

送审包里写明「本次处于第 X 阶段」以及该阶段的任务。进入第二、三阶段时，附上决策记录里「已确认」和「需深化」的清单，让 GPT 知道哪些不用再讨论。
